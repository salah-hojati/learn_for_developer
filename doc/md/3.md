## ۴. پانویس (Footnote)

```markdown
Markdown در سال ۲۰۰۴ معرفی شد.[^1]

[^1]: توسط John Gruber و با همکاری Aaron Swartz.
```

خروجی در انتهای سند به‌صورت خودکار شماره‌گذاری و لینک می‌شود.

**چند پانویس:**

```markdown
این ادعا نیاز به منبع دارد.[^منبع۱] و این یکی هم.[^منبع۲]

[^منبع۱]: مستندات رسمی، بخش ۳.
[^منبع۲]: گزارش سالانه ۲۰۲۴.
```

می‌توانی به‌جای شماره، نام معنادار بدهی (`[^منبع۱]`) که خودش خوانایی فایل خام را بالا می‌برد.

**هشدار:** پانویس در GitHub، Obsidian و Pandoc کار می‌کند اما در همه پارسرها پشتیبانی نمی‌شود. برای اسناد رسمی، اگر مطمئن نیستی، از «پانویس دستی» استفاده کن:

```markdown
این ادعا نیاز به منبع دارد.<sup>[1]</sup>

---
<sub>[1] مستندات رسمی، بخش ۳.</sub>
```

## ۵. لینک داخلی (به بخش دیگری از همان سند)

با لنگر (anchor):

```markdown
به [بخش نصب](#نصب) مراجعه کن.
```

قواعد ساخت لنگر از متن عنوان:

| عنوان | لنگر |
|-------|------|
| `## نصب` | `#نصب` |
| `## نصب و راه‌اندازی` | `#نصب-و-راه‌اندازی` |
| `## مرحله ۱: شروع` | `#مرحله-۱-شروع` |
| `## API Reference` | `#api-reference` |

یعنی: حروف کوچک، فاصله‌ها → `-`، علائم نگارشی حذف.

**راه امن‌تر:** اگر لنگر را دستی حدس می‌زنی و مطمئن نیستی، در GitHub روی عنوان کلیک کن — آیکون زنجیر کنارش ظاهر می‌شود و لینک دقیق را می‌دهد.

---

## ۶. لینک به فایل دیگر در همان مخزن

```markdown
[راهنمای نصب](docs/install.md)
[بخش پیکربندی در همان فایل](docs/install.md#پیکربندی)
[پوشه تصاویر](../assets/)
```

**قانون:** همیشه **مسیر نسبی** بده، نه مطلق. مسیر نسبی هم در GitHub کار می‌کند، هم در Obsidian، هم در VS Code، هم در MkDocs.

اگر فایل مقصد `.md` است، در GitHub می‌توانی پسوند را هم حذف کنی و باز کار می‌کند: `[نصب](docs/install)` — اما صریح نوشتن امن‌تر است.

## ۷. لینک ارجاعی (Reference-style Link)

وقتی یک URL را چند بار استفاده می‌کنی، این روش تمیزتر است:

```markdown
به [مستندات رسمی][docs] و [راهنمای GitHub][gh] مراجعه کن.

[docs]: https://example.com/docs
[gh]: https://docs.github.com
```

مزیت: لینک‌های طولانی وسط متن شلوغی نمی‌کنند و اگر URL عوض شد، فقط یک جا اصلاح می‌کنی.

## ۸. متن پنهان و جزئیات بازشو (Details/Summary)

Markdown استاندارد ندارد، اما HTML داخل Markdown تقریباً همه‌جا کار می‌کند:

```html
<details>
<summary>برای دیدن راه‌حل کلیک کن</summary>

این محتوا فقط وقتی باز شود دیده می‌شود.

```bash
npm run build
```

</details>
```

کاربرد: پنهان کردن راه‌حل تمرین‌ها، لاگ‌های طولانی، بخش‌های پیشرفته. در GitHub و Obsidian عالی کار می‌کند.

## ۹. بلوک هشدار (Alerts / Callouts)

GitHub و بعضی ابزارها سینتکس ویژه‌ای برای هشدار رنگی دارند:

```markdown
> [!NOTE]
> این یک نکته است.

> [!TIP]
> این یک ترفند است.

> [!IMPORTANT]
> این مهم است.

> [!WARNING]
> مراقب باش!

> [!CAUTION]
> خطر!
```

در GitHub به‌صورت باکس رنگی رندر می‌شود. در Obsidian هم با همین سینتکس (یا `> [!info]`) کار می‌کند. اگر ابزارت پشتیبانی نکرد، فقط یک نقل‌قول ساده می‌بینی — چیزی خراب نمی‌شود.

**جایگزین جهانی:** اگر می‌خواهی در همه‌جا یکسان باشد، از ایموجی + پررنگ استفاده کن:

```markdown
> ⚠️ **هشدار:** این دستور داده‌ها را پاک می‌کند.
```

## ۱۰. کدام ویژگی کجا کار می‌کند؟ (جدول سازگاری)

| ویژگی | GitHub | Obsidian | VS Code | Pandoc | Markdown پایه |
|-------|:------:|:--------:|:-------:|:------:|:-------------:|
| بلوک کد با زبان | ✅ | ✅ | ✅ | ✅ | ✅ |
| چک‌لیست | ✅ | ✅ | ✅ | ✅ | ⚠️ |
| پانویس | ✅ | ✅ | ⚠️ | ✅ | ❌ |
| Alerts | ✅ | ✅ | ⚠️ | ❌ | ❌ |
| `<details>` | ✅ | ✅ | ✅ | ✅ | ✅ (HTML) |
| جدول | ✅ | ✅ | ✅ | ✅ | ⚠️ |

⚠️ = بسته به افزونه/تنظیمات.

**درس مهم:** اگر سندت را فقط در GitHub می‌خوانی، آزادانه از همه استفاده کن. اگر باید در چند ابزار مختلف باز شود، به ستون‌های آخر نگاه کن و محافظه‌کارتر باش.

- [ ] دسترسی به سرور
- [ ] کلید SSH

## مراحل

۱. مخزن را کلون کن:

```bash
git clone https://github.com/example/repo.git

```

۲. وابستگی‌ها را نصب کن:

```bash
npm install

۳. فایل `config.yml` را بساز:

```yaml

## عیب‌یابی

<details>

از `pm2` استفاده کن:

```bash
pm2 start app.js
```

</details>

[^port]: پورت‌های زیر ۱۰۲۴ نیاز به دسترسی root دارند.

## تمرین جلسه ۳

یک فایل `setup.md` بساز که شامل این موارد باشد:

1. دو بلوک کد با زبان مشخص (`bash` و `json`)
2. یک بلوک `diff` که یک تغییر را نشان دهد
3. یک چک‌لیست ۴ آیتمی (دو تای تیک‌خورده)
4. یک پانویس با نام معنادار فارسی
5. یک لینک داخلی به بخش «نصب» که خودت بالاتر ساخته‌ای
6. یک لینک ارجاعی که دو بار استفاده شده باشد
7. یک بلوک `> [!NOTE]` و یک `<details>` بازشو

**چالش اضافه:** یک بلوک کد بنویس که *خودش* شامل سه بک‌تیک باشد (یعنی باید با چهار بک‌تیک احاطه‌اش کنی).
