# جلسه ۴: اسناد حرفه‌ای و قابل انتشار

در جلسات قبل یاد گرفتیم چطور بنویسیم. حالا می‌رویم سراغ چیزهایی که یک سند را از «فایل متنی» به «مستند قابل ارائه و انتشار» تبدیل می‌کند: **فراداده (Front Matter)**، **نشان‌ها (Badge)**، **ساختار پوشه‌بندی** و در نهایت **راه‌حل کامل راست‌به‌چپ** برای فارسی.

---

## ۱. Front Matter (فراداده سند)

Front Matter یک بلوک **YAML** است که در **اولین خطوط فایل** قرار می‌گیرد و اطلاعاتی درباره خودِ سند می‌دهد، نه محتوای آن: عنوان، نویسنده، تاریخ، برچسب‌ها و هر چیز دیگری.

### ساختار پایه
</div>


```yaml
---
title: "راهنمای راه‌اندازی پروژه"
author: "تیم فنی"
date: 2026-10-22
tags:
  - مستندات
  - راه‌اندازی
  - فارسی
---
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


- باید در **خط اول** فایل با `---` شروع شود و با `---` (یا `...`) در یک خط جداگانه بسته شود.
- داخل آن YAML معتبر می‌نویسیم: کلید: مقدار.
- **تورفتگی در YAML حیاتی است** — فقط از **فاصله (Space)** استفاده کن، نه Tab.

### چه فیلدهایی رایج است؟

| فیلد | کاربرد |
|------|--------|
| `title` | عنوان سند (برای فهرست و SEO) |
| `description` | توضیح کوتاه |
| `author` | نویسنده یا نویسندگان |
| `date` / `last_updated` | تاریخ ایجاد / آخرین ویرایش |
| `tags` | برچسب‌ها برای دسته‌بندی |
| `draft: true` | نشان‌گذاری به‌عنوان پیش‌نویس |

### کجا کار می‌کند؟

Front Matter در **Zettlr**، **Obsidian**، **Jekyll**، **Hugo**، **VitePress**، **Docusaurus**، **Pandoc** و بسیاری دیگر پشتیبانی می‌شود. حتی اگر ابزارت الان از آن استفاده نمی‌کند، نوشتنش ضرری ندارد — آینده‌نگرانه است.

### نکته مهم

Front Matter در **پیش‌نمایش GitHub** به‌صورت یک جدول بالای صفحه رندر می‌شود (اگر پارسر پشتیبانی کند)، اما در خودِ فایل خام هم خوانا و مفید است.

## ۲. Badge (نشان)

Badge یک **تصویر کوچک با لینک** است که وضعیت پروژه را نشان می‌دهد: نسخه، وضعیت CI، مجوز، پلتفرم و… . استاندارد صنعتی برای ساخت آن **Shields.io** است.

### ساختار پایه
</div>


```markdown
![alt text](https://img.shields.io/badge/LABEL-MESSAGE-COLOR)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


مثال:
</div>


```markdown
![نسخه](https://img.shields.io/badge/version-1.0.0-blue)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### پارامترهای Shields.io

URL به این شکل ساخته می‌شود:
</div>


```text
https://img.shields.io/badge/<LABEL>-<MESSAGE>-<COLOR>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


- `LABEL` و `MESSAGE` با `-` جدا می‌شوند.
- فاصله را با `_` یا `%20` جایگزین کن؛ `__` یعنی خودِ `_`؛ `--` یعنی خودِ `-`.
- `COLOR` می‌تواند نام رنگ باشد (`blue`, `green`, `red`, `orange`, `brightgreen`, …) یا کد HEX بدون `#`.



### پارامترهای اختیاری (Query String)
</div>


```markdown
![نسخه](https://img.shields.io/badge/version-1.0.0-blue?style=for-the-badge&logo=github)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


| پارامتر | کاربرد |
|---------|--------|
| `style` | `flat` (پیش‌فرض)، `flat-square`، `plastic`، `for-the-badge`، `social` |
| `logo` | نام آیکون از Simple Icons (مثل `github`، `python`، `react`) |
| `logoColor` | رنگ آیکون |
| `labelColor` | رنگ بخش چپ نشان |

### Badge با لینک

الگوی استاندارد در README: تصویر را داخل لینک بگذار.
</div>

```markdown
[![نسخه](https://img.shields.io/badge/version-1.0.0-blue)](https://example.com/releases)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### چند Badge کنار هم

معمولاً در یک خط، پشت سر هم، زیر عنوان اصلی:
</div>


```markdown
# پروژه من

![نسخه](https://img.shields.io/badge/version-1.0.0-blue)
![وضعیت](https://img.shields.io/badge/build-passing-brightgreen)
![مجوز](https://img.shields.io/badge/license-MIT-green)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## ۳. ساختار پوشه‌بندی اسناد

یک قانون طلایی وجود دارد که تقریباً همه ابزارهای مستندسازی روی آن توافق دارند:

> **فقط `README.md` در ریشه پروژه باشد. بقیه فایل‌های Markdown در پوشه `docs/` قرار بگیرند**.

### ساختار پیشنهادی
</div>


```text
project/
├── README.md              ← تنها فایل Markdown در ریشه
├── docs/
│   ├── setup/
│   │   ├── QUICKSTART.md
│   │   └── INSTALL.md
│   ├── guides/
│   │   ├── GIT_WORKFLOW.md
│   │   └── DEPLOYMENT.md
│   ├── reference/
│   │   └── API.md
│   └── images/
│       └── architecture.png
└── src/
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


این الگو در Docusaurus، VitePress و بسیاری از پروژه‌های متن‌باز استاندارد است.

### قوانین نام‌گذاری

- **بدون فاصله** در نام فایل: `PROJECT_SETUP_GUIDE.md` ✅ یا `project-setup-guide.md` ✅
- `Feature Name.md` ❌ — فاصله در URL مشکل ایجاد می‌کند.
- برای مهم‌ترین راهنماها، **حروف بزرگ** رایج است (مثل `QUICKSTART.md`).
- نام توصیفی بگذار: `setup.md` خیلی مبهم است؛ `INSTALLATION_GUIDE.md` بهتر است.

### قانون طلایی README

`README.md` ریشه باید:

1. پروژه را معرفی کند
2. شروع سریع بدهد
3. به مستندات تفصیلی در `docs/` **لینک** بدهد
4. مختصر بماند

## ۴. راه‌حل راست‌به‌چپ (RTL) برای فارسی

این مهم‌ترین بخش این جلسه برای توست. Markdown استاندارد **هیچ سینتکسی برای جهت متن ندارد**. مرورگر و پارسر بر اساس heuristic تصمیم می‌گیرد. اما راه‌حل‌های عملی وجود دارد.

### ۴.۱. روش HTML (جهانی‌ترین راه‌حل)

هر جا که جهت مهم است، از تگ HTML با `dir` استفاده کن:
</div>


```html
<div dir="rtl">

این پاراگراف فارسی است و از راست شروع می‌شود.

</div>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**نکته مهم:** در GitHub، تگ `<div dir="rtl">` کار می‌کند، اما ممکن است **در تب Preview تغییری نبینی** — بعد از Commit اعمال می‌شود.

برای پاراگراف‌های کوتاه:
</div>


```html
<p dir="rtl">متن فارسی</p>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


برای کل سند در ابزارهایی که کنترل کامل داری (مثل تولید HTML سفارشی)، می‌توانی `dir="rtl"` را روی تگ `<body>` بگذاری.

### ۴.۲. `dir="auto"` — هوشمندترین گزینه

مرورگرها و برخی پارسرها از `dir="auto"` پشتیبانی می‌کنند. این مقدار باعث می‌شود مرورگر بر اساس **اولین کاراکتر قوی** در متن، جهت را تشخیص دهد.
</div>


```html
<p dir="auto">این متن فارسی است.</p>
<p dir="auto">This is English text.</p>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


GitHub و GitLab از `dir="auto"` روی عناصر خودشان استفاده می‌کنند، اما در Markdown معمولی، اگر خودت آن را اضافه کنی، **تضمینی** برای اعمال روی همه عناصر نیست.

### ۴.۳. ابزارهای تخصصی RTL

| ابزار | کاربرد |
|-------|--------|
| **افزونه Markdown RTL Viewer** (Firefox) | پیش‌نمایش Markdown با یک کلیک RTL/LTR/Auto — عالی برای اسناد دوزبانه |
| **Obsidian** | از نسخه ۱.۶ به بعد، جهت هر خط را خودکار تشخیص می‌دهد و `dir` را روی هر خط اعمال می‌کند |
| **افزونه Any-RTL** (Obsidian) | تشخیص محتوایی برای یادداشت‌های دوزبانه |
| **RTLknitr** (R Markdown) | پشتیبانی کامل RTL در خروجی R Markdown و LaTeX |
| **mystrotamer-tohtml** | تبدیل Markdown به HTML با پشتیبانی خودکار RTL |

### ۴.۴. راه‌حل عملی برای GitHub (که مهم‌ترین مقصد اسناد است)

GitHub از **Markdown استاندارد** پیروی می‌کند و `dir` را به‌صورت خودکار روی همه عناصر اعمال نمی‌کند. بهترین کاری که می‌توانی بکنی:

1. **برای پاراگراف‌های مهم**، از `<div dir="rtl">` استفاده کن.
2. **برای جدول‌ها**، HTML خام با `dir="rtl"` بنویس:
</div>


```html
<table dir="rtl">
  <tr><th>نام</th><th>توضیح</th></tr>
  <tr><td>Markdown</td><td>زبان نشانه‌گذاری سبک</td></tr>
</table>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


3. **برای بلوک‌های کد**، جهت خودکار LTR است و این درست است — کد باید چپ‌به‌راست بماند.
4. اگر سند کاملاً فارسی است و می‌خواهی همه‌چیز راست‌چین باشد، **به‌جای GitHub، از یک تولیدکننده سایت مستندات** استفاده کن (Docusaurus، VitePress، MkDocs) که در آن‌ها می‌توانی قالب RTL سفارشی کنی.

### ۴.۵. هشدار درباره ترکیب فارسی و انگلیسی

بزرگ‌ترین دردسر RTL، **متن دوزبانه** است: یک پاراگراف فارسی که وسطش یک اصطلاح انگلیسی دارد، ممکن است علائم نگارشی‌اش جابه‌جا شود. راه‌حل:

- اصطلاحات انگلیسی را داخل `` `backtick` `` بگذار تا از متن جدا شوند و جهت‌شان حفظ شود.
- برای نقل‌قول انگلیسی داخل متن فارسی، از `<span dir="ltr">` استفاده کن:
</div>


```html
<p dir="rtl">
این یک متن فارسی است که شامل <span dir="ltr">npm install</span> می‌شود.
</p>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## تمرین جلسه ۴

1. یک فایل `README.md` حرفه‌ای بساز با:
    - Front Matter شامل `title`، `author`، `date` و `tags`
    - سه Badge (نسخه، مجوز، وضعیت) که دومی و سومی به لینک وصل باشند
    - یک بخش «مستندات» که به فایل‌های داخل `docs/` لینک بدهد

2. ساختار پوشه `docs/` را طراحی کن: حداقل دو زیرپوشه (`setup/` و `guides/`) با یک فایل Markdown در هرکدام.

3. یک فایل `faq.md` در `docs/` بساز و **همه پاراگراف‌های فارسی را داخل `<div dir="rtl">`** بگذار. یک جدول فارسی هم با HTML و `dir="rtl"` بنویس.

4. **چالش:** یک پاراگراف فارسی بنویس که وسطش یک دستور انگلیسی (`npm start`) داشته باشد، طوری که علائم نگارشی فارسی خراب نشوند.
