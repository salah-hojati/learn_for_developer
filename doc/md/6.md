# نوشتن دستورات ساخت فایل در Markdown

سؤالت دو بخش دارد: **۱)** چه دستوراتی فایل با محتوای خاص می‌سازند، **۲)** چطور این دستورات را در سند Markdown مستند کنیم. هر دو را کامل می‌بینیم.

---

## ۱. دستورات ساخت فایل (بر اساس سیستم‌عامل)

### لینوکس / مک (Bash / Zsh)

#### ساخت فایل خالی

```bash
touch config.yml
```

#### ساخت فایل تک‌خطی

```bash
echo "port: 3000" > config.yml
```

⚠️ `>` فایل را **بازنویسی** می‌کند. برای **افزودن** از `>>` استفاده کن:

```bash
echo "debug: false" >> config.yml
```

#### ساخت فایل چندخطی با Heredoc (بهترین روش)

```bash
cat > config.yml << 'EOF'
port: 3000
debug: false
database:
  host: localhost
  name: app_db
EOF
```

نکته مهم: `<< 'EOF'` (با کوتیشن) یعنی محتوا **عیناً** نوشته شود — متغیرها ($VAR) و بک‌تیک‌ها تفسیر نمی‌شوند. اگر می‌خواهی متغیرها جایگزین شوند، `<< EOF` (بدون کوتیشن) بنویس.

#### ساخت پوشه + فایل با هم

```bash
mkdir -p ~/projects/myapp/config
cat > ~/projects/myapp/config/app.yml << 'EOF'
name: myapp
version: 1.0.0
EOF
```

`-p` یعنی اگر پوشه‌های والد وجود ندارند، ساخته شوند.

#### نوشتن با `printf` (کنترل دقیق‌تر روی `\n`)

```bash
printf "line1\nline2\nline3\n" > notes.txt
```

### ویندوز (PowerShell)

#### ساخت فایل تک‌خطی

```powershell
"port: 3000" | Out-File -FilePath config.yml -Encoding utf8
```

یا ساده‌تر:

```powershell
Set-Content -Path config.yml -Value "port: 3000"
```

#### ساخت فایل چندخطی با Here-String

```powershell
@"
port: 3000
debug: false
database:
  host: localhost
  name: app_db
"@ | Out-File -FilePath config.yml -Encoding utf8
```

#### ساخت پوشه + فایل

```powershell
New-Item -ItemType Directory -Force -Path "C:\projects\myapp\config"
@"
name: myapp
version: 1.0.0
"@ | Out-File -FilePath "C:\projects\myapp\config\app.yml" -Encoding utf8
```

### ویندوز (CMD)

```cmd
echo port: 3000 > config.yml
mkdir config
type nul > config\app.yml
```

CMD برای محتوای چندخطی خیلی محدود است؛ اگر چند خط می‌خواهی، PowerShell را انتخاب کن.

## ۲. چطور این دستورات را در سند Markdown بنویسیم

### قاعده طلایی: زبان بلوک کد را مشخص کن

````markdown
```bash
cat > config.yml << 'EOF'
port: 3000
EOF
```
````

چرا؟ چون:
- رنگ‌آمیزی نحوی فعال می‌شود.
- در GitHub دکمه Copy درست کار می‌کند.
- خواننده می‌فهمد برای کدام شل است.

### قاعده دوم: دستور را **قابل کپی مستقیم** بنویس

```bash
# ❌ بد — با $ که کپی‌کردن را خراب می‌کند
$ touch config.yml

# ✅ خوب — بدون $
touch config.yml
```

### قاعده سوم: قبل از دستور توضیح بده، داخل کد کامنت بگذار

````markdown
فایل پیکربندی را با محتوای زیر بساز:

```bash
# ایجاد فایل پیکربندی اصلی
cat > config.yml << 'EOF'
port: 3000
debug: false
EOF
```

سپس محتوای فایل را بررسی کن:

```bash
cat config.yml
```
````

### قاعده چهارم: برای چند سیستم‌عامل، از `<details>` استفاده کن

````markdown
<details>
<summary>لینوکس / مک</summary>

```bash
cat > config.yml << 'EOF'
port: 3000
EOF
```

</details>

<details>
<summary>ویندوز (PowerShell)</summary>

```powershell
@"
port: 3000
"@ | Out-File -FilePath config.yml -Encoding utf8
```

</details>
````

این روش سند را شلوغ نمی‌کند و خواننده فقط بخش مربوط به خودش را می‌بیند.

### قاعده پنجم: هشدار بازنویسی بگذار

````markdown
> [!WARNING]
> دستور زیر فایل `config.yml` را **بازنویسی** می‌کند. اگر فایل موجود است، ابتدا از آن پشتیبان بگیر:

```bash
cp config.yml config.yml.bak
```
````

### قاعده ششم: بررسی وجود فایل قبل از ساخت (idempotent)

اگر دستور قرار است در اسکریپت یا مستندات تکرار شود، بهتر است بازنویسی نکند:

```bash
# فقط اگر فایل وجود ندارد، بساز
[ -f config.yml ] || cat > config.yml << 'EOF'
port: 3000
EOF
```

یا با پیام:

```bash
if [ -f config.yml ]; then
  echo "config.yml از قبل وجود دارد — رد شد"
else
  cat > config.yml << 'EOF'
port: 3000
EOF
  echo "config.yml ساخته شد"
fi
```

<div dir="rtl">

## پیش‌نیاز

- [ ] دسترسی به ترمینال
- [ ] پوشه پروژه ساخته شده باشد

## ایجاد پوشه

اگر پوشه پروژه وجود ندارد:

```bash
mkdir -p ~/projects/myapp/config
cd ~/projects/myapp/config
```

## ایجاد فایل

### لینوکس / مک

```bash
cat > config.yml << 'EOF'
port: 3000
debug: false
database:
  host: localhost
  name: app_db
  user: admin
EOF
```

> [!NOTE]
> از `<< 'EOF'` (با کوتیشن) استفاده شده تا متغیرها تفسیر نشوند. اگر می‌خواهی مقادیر از متغیرهای محیطی خوانده شوند، کوتیشن را حذف کن.

### ویندوز (PowerShell)

```powershell
@"
port: 3000
debug: false
database:
  host: localhost
  name: app_db
  user: admin
"@ | Out-File -FilePath config.yml -Encoding utf8
```

## بررسی نتیجه

```bash
cat config.yml
```

خروجی مورد انتظار:

```yaml
port: 3000
debug: false
database:
  host: localhost
  name: app_db
  user: admin
```

## ۴. اشتباهات رایج

| اشتباه | مشکل | راه‌حل |
|--------|------|--------|
| `echo "line1\nline2" > f` | `\n` در بعضی شل‌ها literal می‌ماند | از `printf` یا heredoc استفاده کن |
| `cat > f << EOF` بدون کوتیشن | متغیرها ($USER) تفسیر می‌شوند | اگر محتوای ثابت می‌خواهی: `<< 'EOF'` |
| `EOF` با فاصله در ابتدا | heredoc بسته نمی‌شود | `EOF` باید در ستون اول باشد |
| `>` به‌جای `>>` | فایل قبلی پاک می‌شود | اگر می‌خواهی اضافه کنی، `>>` |
| بلوک کد بدون زبان در md | Copy در GitHub درست کار نمی‌کند | همیشه ` ```bash ` یا ` ```powershell ` |
| قرار دادن `$` ابتدای دستور | کپی‌کردن را خراب می‌کند | `$` را حذف کن |
| مسیر مطلق با `~` در PowerShell | PowerShell `~` را نمی‌شناسد | `$HOME` یا مسیر کامل بنویس |

## ۵. نکته امنیتی مهم

هرگز در مستندات Markdown **رمز، توکن یا کلید API واقعی** در دستورات نگذار:

```bash
# ❌ هرگز
echo "API_KEY=sk_live_abc123xyz" > .env

# ✅ همیشه
cat > .env << 'EOF'
API_KEY=your_api_key_here
EOF
```

و در `.env` واقعی، از `.gitignore` استفاده کن.

## ۶. جمع‌بندی سریع

| هدف | دستور |
|-----|-------|
| فایل خالی | `touch file` |
| تک‌خطی | `echo "text" > file` |
| چندخطی (استاندارد) | `cat > file << 'EOF' ... EOF` |
| افزودن | `echo "text" >> file` |
| پوشه + فایل | `mkdir -p dir && cat > dir/file << 'EOF' ... EOF` |
| ویندوز چندخطی | `@"..."@ \| Out-File file -Encoding utf8` |
| فقط اگر وجود ندارد | `[ -f file ] \|\| command` |

اگر بگویی دقیقاً **چه محتوایی** و **در چه مسیری** می‌خواهی، یک نمونه آماده و قابل کپی برایت می‌سازم.
