# Lesson 4: Forms and controlled inputs

## 1. The core idea: controlled inputs

In plain HTML, an input keeps its own value. In React, we usually let **state** hold the value:

```jsx
import { useState } from "react";

function NameInput() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
    />
  );
}
```

What happens:

1. You type `a`.
2. `onChange` fires, `e.target.value` is `"a"`.
3. `setName("a")` updates state.
4. Component re-renders.
5. Input's `value` is now `"a"`.

The input **never** holds the truth — React does. That's what "controlled" means.

If you set `value` but forget `onChange`, the input becomes read-only (React warns in the console). If you use `onChange` without `value`, it's an "uncontrolled" input — you lose the ability to read/validate it from state consistently.

**Rule: always pair `value` with `onChange`.**

## 2. Each input type

| Input | Read it via | Notes |
|---|---|---|
| text / email / password / number | `e.target.value` | Always a **string**, even for `type="number"` |
| checkbox | `e.target.checked` | boolean |
| radio | `e.target.value` + `checked` | compare to state |
| select | `e.target.value` | put `value` on the `<select>` |
| textarea | `e.target.value` | in React use `value`, not children |

Examples:

```jsx
// checkbox
const [agreed, setAgreed] = useState(false);
<input
  type="checkbox"
  checked={agreed}
  onChange={(e) => setAgreed(e.target.checked)}
/>
```

```jsx
// select
const [role, setRole] = useState("developer");
<select value={role} onChange={(e) => setRole(e.target.value)}>
  <option value="developer">Developer</option>
  <option value="designer">Designer</option>
  <option value="manager">Manager</option>
</select>
```

```jsx
// radio
const [plan, setPlan] = useState("free");
<label>
  <input
    type="radio"
    name="plan"
    value="free"
    checked={plan === "free"}
    onChange={(e) => setPlan(e.target.value)}
  />
  Free
</label>
<label>
  <input
    type="radio"
    name="plan"
    value="pro"
    checked={plan === "pro"}
    onChange={(e) => setPlan(e.target.value)}
  />
  Pro
</label>
```

```jsx
// textarea
const [bio, setBio] = useState("");
<textarea value={bio} onChange={(e) => setBio(e.target.value)} />
```

## 3. Many fields: one object of state

Once you have 3+ fields, don't create 5 separate `useState` calls. Use **one object**:

```jsx
import { useState } from "react";

const initialForm = {
  name: "",
  email: "",
  age: "",
  role: "developer",
  agreed: false,
};

function RegistrationForm() {
  const [form, setForm] = useState(initialForm);

  function handleChange(e) {
    const { name, value, type, checked } = e.target;
    setForm((prev) => ({
      ...prev,
      [name]: type === "checkbox" ? checked : value,
    }));
  }

  return (
    <form>
      <input name="name"  value={form.name}  onChange={handleChange} placeholder="Name" />
      <input name="email" value={form.email} onChange={handleChange} placeholder="Email" />
      <input name="age"   value={form.age}   onChange={handleChange} placeholder="Age" />

      <select name="role" value={form.role} onChange={handleChange}>
        <option value="developer">Developer</option>
        <option value="designer">Designer</option>
      </select>

      <label>
        <input
          type="checkbox"
          name="agreed"
          checked={form.agreed}
          onChange={handleChange}
        />
        I agree to the terms
      </label>
    </form>
  );
}
```

Things to notice carefully:

**`[name]` is a computed property.** Each input has `name="name"`, `name="email"`, etc. `[name]: value` updates only that key.

**The spread `...prev` is essential.** Without it you'd replace the whole object with just one key. `setForm({ name: value })` would wipe out `email`, `age`, etc.

**The extra parentheses around the returned object.** This:

```jsx
setForm((prev) => ({ ...prev, [name]: value }));
```

…is not the same as:

```jsx
setForm((prev) => { ...prev, [name]: value });  // ❌ syntax error
```

An arrow function with `{` starts a **body**, not an object. You need `({ ... })` to return an object directly. This trips up almost everyone once — when you see a "Unexpected token" error in a setter, check for this.

**Why `(prev) => ...` instead of `setForm({...form, ...})`?** Both usually work, but the functional form is safer when updates happen quickly (e.g. typing fast, or updating in an event handler that fires multiple times). It always sees the latest state. Use it by habit for objects.

## 4. Submitting

```jsx
function handleSubmit(e) {
  e.preventDefault();          // stops the browser from reloading the page
  console.log(form);
}

return <form onSubmit={handleSubmit}> ... </form>;
```

`e.preventDefault()` is **mandatory**. Without it, the browser navigates/reloads and your React state is lost.

A `<button>` inside a `<form>` defaults to `type="submit"`. If you have other buttons inside the form (e.g. "Reset"), give them `type="button"` or they'll also submit.

Reset the form after submit:

```jsx
setForm(initialForm);
```

(Note: `initialForm` is a constant object defined outside the component, so reusing it is safe. Don't reuse a state object directly as your reset value after mutating it — but since we never mutate state, this is fine.)

## 5. Basic validation

Keep it simple for now — validate on submit:

```jsx
function validate(form) {
  const errors = {};
  if (!form.name.trim()) errors.name = "Name is required";
  if (!form.email.includes("@")) errors.email = "Email looks invalid";
  if (!form.age || Number(form.age) < 18) errors.age = "Must be 18 or older";
  if (!form.agreed) errors.agreed = "You must accept the terms";
  return errors;
}
```

```jsx
const [errors, setErrors] = useState({});

function handleSubmit(e) {
  e.preventDefault();
  const nextErrors = validate(form);
  setErrors(nextErrors);
  if (Object.keys(nextErrors).length > 0) return;

  console.log("Submitted:", form);
  setForm(initialForm);
  setErrors({});
}
```

Display them:

```jsx
{errors.name && <p style={{ color: "red" }}>{errors.name}</p>}
```

Remember: `form.age` is a **string**. Always convert with `Number(...)` before comparing numerically. `"20" < 18` is `false`, but `"9" < 18` is also `false` because strings compare alphabetically — a classic bug.

## 6. Common pitfalls (in order of frequency)

1. **Missing `e.preventDefault()`** → page reloads, state lost.
2. **Missing parens around returned object in `setForm`** → syntax error.
3. **Missing `...prev`** → only one field survives.
4. **Missing `onChange`** → input is frozen.
5. **Treating `age` as a number** → `form.age < 18` compares strings.
6. **Missing `name` attribute on inputs** → the `[name]: value` trick breaks.
7. **Mutating state directly** — `form.name = "x"` does nothing; React won't re-render. Always go through `setForm`.
