# 🔐 Lesson 2: Adding Spring Security & Understanding the Default Login

In this lesson, we go hands-on. You’ll add Spring Security to a Spring Boot app, observe the default behavior, and then replace the generated password with your own configuration.

---

## 🎯 Lesson 2 Goal
By the end of this lesson, you should be able to:

- Add Spring Security to a Spring Boot project
- Explain what happens when you run the app for the first time
- Log in using the default generated credentials
- Customize the default user and password
- Understand the modern `SecurityFilterChain` bean

## 1. Create the Project

Go to [start.spring.io](https://start.spring.io) and create a project with:

- **Project**: Maven
- **Language**: Java
- **Spring Boot**: 3.x (latest stable)
- **Dependencies**:
    - Spring Web
    - Spring Security

Download, unzip, and open it in your IDE.

Your `pom.xml` should include:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

---

## 2. Create a Simple Controller

Create a controller so we have something to protect:

```java
package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello, authenticated user!";
    }

    @GetMapping("/public")
    public String publicEndpoint() {
        return "This is public.";
    }
}
```

---

## 3. Run the App and Observe the Default Behavior

Start the application. In the console, you will see something like:

```text
Using generated security password: 8f3c1a2e-7b4d-4e9a-9c1f-2d5e6a7b8c9d
```

This is Spring Boot’s **default security configuration** kicking in.

### What just happened?

Without any configuration, Spring Security:

1. **Secured every endpoint** — `/hello` and `/public` both require login.
2. **Created a default user** named `user`.
3. **Generated a random password** and printed it in the console.
4. **Enabled form-based login** — a default login page is served.
5. **Enabled CSRF protection** by default (more on this later).
6. **Enabled HTTP Basic authentication** as well.

---

## 4. Try It Out

Open your browser and go to:

```text
http://localhost:8080/hello
```

You will be redirected to a login page at `/login`.

### Login credentials:

| Field | Value |
|---|---|
| Username | `user` |
| Password | The one printed in the console |

After logging in, you will see:

```text
Hello, authenticated user!
```

Now try `http://localhost:8080/public` — you will notice it also requires login. That’s because **everything is secured by default**.

---

## 5. Replacing the Default User with Your Own (application.properties)

The simplest way to override the default user is via `application.properties`:

```properties
spring.security.user.name=admin
spring.security.user.password=admin123
spring.security.user.roles=ADMIN
```

Restart the app. Now the console will **not** print a generated password, and you can log in with:

| Username | Password |
|---|---|
| `admin` | `admin123` |

> ⚠️ **Note**: This approach stores the password in plain text. It’s fine for learning, but never use it in production.

## 6. The Modern Way: SecurityFilterChain Bean

In Spring Security 6 (Spring Boot 3), the recommended approach is to define a `SecurityFilterChain` bean. The old `WebSecurityConfigurerAdapter` is deprecated and removed.

Create a configuration class:

```java
package com.example.demo;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/public").permitAll()   // allow everyone
                .anyRequest().authenticated()             // everything else needs login
            )
            .formLogin(form -> form.permitAll())          // enable default login page
            .httpBasic(basic -> {});                      // optionally enable basic auth

        return http.build();
    }
}
```

### What this configuration does:

| Line | Meaning |
|---|---|
| `requestMatchers("/public").permitAll()` | `/public` is open to everyone |
| `anyRequest().authenticated()` | All other endpoints require login |
| `formLogin(form -> form.permitAll())` | Enables the default login page, accessible without auth |
| `httpBasic(...)` | Enables HTTP Basic authentication (e.g., for Postman) |

Restart the app.

Now:

- `http://localhost:8080/public` → ✅ accessible without login
- `http://localhost:8080/hello` → 🔒 redirects to login page

---

## 7. Understanding the Flow So Far

Here is what happens when you hit `/hello`:

```text
GET /hello
   ↓
Security Filter Chain
   ↓
AuthorizationFilter checks: is /hello permitted?
   ↓
No → redirect to /login
   ↓
User submits credentials
   ↓
AuthenticationManager → UserDetailsService → PasswordEncoder
   ↓
Authenticated → SecurityContext populated
   ↓
Redirect back to /hello → access granted
```

---

## 8. A Quick Note on `SecurityFilterChain`

The `SecurityFilterChain` bean is where you will spend most of your configuration time. It allows you to:

- Define which URLs are public vs protected
- Configure login mechanisms (form, basic, JWT, OAuth2)
- Configure logout behavior
- Configure CORS and CSRF
- Define custom filters (important later for JWT)

In the next lessons, we will keep extending this bean.
