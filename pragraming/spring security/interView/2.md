در **Spring Security**، annotations های `@PreAuthorize` و `@PostAuthorize` برای پیاده‌سازی **مجوزدهی در سطح متد (Method-Level Security)** با استفاده از عبارت‌های **SpEL (Spring Expression Language)** به کار می‌روند.

* **`@PreAuthorize`**: **قبل** از اجرای متد بررسی می‌شود. اگر عبارت SpEL مقدار `false` برگرداند، متد اصلاً اجرا نمی‌شود و استثنای `AccessDeniedException` پرتاب می‌شود.
* **`@PostAuthorize`**: **بعد** از اجرای متد بررسی می‌شود و به مقدار بازگشتی متد با متغیر `returnObject` دسترسی دارد. اگر شرط برقرار نباشد، نتیجه را برنمی‌گرداند و `AccessDeniedException` پرتاب می‌کند.

---

### ۱. فعال‌سازی Method Security

ابتدا باید امنیت در سطح متد را در کلاس پیکربندی فعال کنید (در Spring Security 6 و جدیدتر):

```java
@Configuration
@EnableMethodSecurity // به‌طور پیش‌فرض prePostEnabled = true است
public class SecurityConfig {
}

```

### ۲. نحوه استفاده از `@PreAuthorize`

از این annotation زمانی استفاده می‌کنید که می‌توانید دسترسی را **پیش از اجرای منطق اصلی متد** (بر اساس نقش، مقام، پارامترهای ورودی یا مالکیت منبع) بسنجید.

```java
@Service
public class DocumentService {

    // ۱. بررسی نقش یا authority
    @PreAuthorize("hasRole('ADMIN')")
    public void deleteAllDocuments() {
        // فقط کاربران دارای ROLE_ADMIN می‌توانند این متد را صدا بزنند
    }

    // ۲. بررسی پارامتر ورودی و مقایسه با کاربر فعلی
    @PreAuthorize("#username == authentication.name or hasRole('ADMIN')")
    public UserProfile getProfile(String username) {
        return userProfileRepository.findByUsername(username);
    }

    // ۳. استفاده از یک Bean سفارشی برای منطق پیچیده‌تر
    @PreAuthorize("@documentSecurity.canEdit(authentication, #docId)")
    public void updateDocument(Long docId, String content) {
        // منطق ویرایش سند
    }
}

```

> **نکته مهم درباره `hasRole`:** متد `hasRole('ADMIN')` به‌صورت خودکار پیشوند `ROLE_` را اضافه می‌کند و `ROLE_ADMIN` را می‌سنجد؛ در حالی که `hasAuthority('ROLE_ADMIN')` دقیقاً همان رشته را بررسی می‌کند.

### ۳. نحوه استفاده از `@PostAuthorize`

از این annotation زمانی استفاده می‌کنید که برای تصمیم‌گیری نهایی نیاز به **نتیجهٔ واکشی‌شده از متد** دارید (مثلاً چک کردن مالکیت رکوردی که از دیتابیس خوانده شده است).

```java
@Service
public class OrderService {

    // بررسی مالکیت سفارش پس از بارگذاری آن از دیتابیس
    @PostAuthorize("returnObject.ownerUsername == authentication.name or hasRole('SUPPORT')")
    public Order getOrderById(Long orderId) {
        return orderRepository.findById(orderId)
                .orElseThrow(() -> new EntityNotFoundException("Order not found"));
    }
}

```

> **هشدار:** از `@PostAuthorize` برای متدهایی که عملیات تغییر داده‌ی حساس یا پرهزینه (مثل `DELETE` یا ثبت تراکنش مالی) انجام می‌دهند استفاده نکنید، زیرا متد **پیش از بررسی شرط اجرا شده** است.

---

### ۴. مقایسه سریع `@PreAuthorize` و `@PostAuthorize`

| ویژگی | `@PreAuthorize` | `@PostAuthorize` |
| --- | --- | --- |
| **زمان اجرا** | قبل از اجرای متد | پس از اجرای متد |
| **دسترسی به `returnObject**` | خیر | بله (نتیجه بازگشتی متد) |
| **دسترسی به پارامترهای ورودی** | بله (`#paramName`) | بله (`#paramName`) |
| **مورد استفاده ایده‌آل** | نقش‌ها، ورودی‌ها، جلوگیری از اجرای متد | بررسی داده واکشی‌شده (مثلاً مالکیت موجودیت) |
