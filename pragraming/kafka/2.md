Building on error handling, the next step is to address three pillars of production-grade Kafka: **delivery guarantees**, **data contract evolution**, and **observability**.

### 🎯 Exactly-Once Semantics (EOS) & Manual Acknowledgment

The default `auto-commit` in Kafka can silently lose messages or cause duplicates if a consumer crashes between fetching and processing. For critical operations like writing to a database, you need explicit control.

**1. Manual Acknowledgment (At-Least-Once)**
Disable auto-commit and set `AckMode` to `MANUAL_IMMEDIATE`. The listener then receives an `Acknowledgment` object, and you call `acknowledge()` only **after** successful processing.

```properties
spring.kafka.consumer.enable-auto-commit=false
spring.kafka.listener.ack-mode=MANUAL_IMMEDIATE
```

```java
@KafkaListener(topics = "order-events", groupId = "order-processor")
public void onOrderEvent(OrderEvent event, Acknowledgment ack) {
    try {
        orderService.process(event);
        ack.acknowledge(); // Commit offset only after success
    } catch (RetryableException e) {
        // Do NOT acknowledge; Kafka will redeliver
        throw e;
    } catch (FatalException e) {
        // Send to DLT, then acknowledge to skip the poison pill
        deadLetterPublisher.send(event);
        ack.acknowledge();
    }
}
```

**2. True Exactly-Once (Transactions)**
To guarantee that a message is processed **exactly once** across a consume-transform-produce pipeline, use Kafka transactions. Configure a `DefaultKafkaProducerFactory` with a `transactionIdPrefix` and a `KafkaTransactionManager`.

```java
@Bean
public ProducerFactory<String, String> producerFactory() {
    DefaultKafkaProducerFactory<String, String> factory =
        new DefaultKafkaProducerFactory<>(producerProps());
    factory.setTransactionIdPrefix("tx-");
    return factory;
}

@Bean
public KafkaTransactionManager<String, String> transactionManager(
        ProducerFactory<String, String> pf) {
    return new KafkaTransactionManager<>(pf);
}
```

When a listener container is configured with this transaction manager, the container starts a transaction before invoking the listener, and offsets are committed atomically with the producer's output.

### 🗂️ Avro & Schema Registry

JSON is flexible but lacks a formal contract. **Avro** provides a compact binary format with a schema, and **Confluent Schema Registry** enforces compatibility as schemas evolve.

**1. Define the Schema**
Create an `.avsc` file (or use Avro IDL) and generate Java classes via the `avro-maven-plugin`.

**2. Configure the Application**
Point Spring to the Schema Registry URL and use the Confluent `KafkaAvroSerializer` / `KafkaAvroDeserializer`.

```properties
spring.kafka.producer.value-serializer=io.confluent.kafka.serializers.KafkaAvroSerializer
spring.kafka.consumer.value-deserializer=io.confluent.kafka.serializers.KafkaAvroDeserializer
spring.kafka.properties.schema.registry.url=http://localhost:8081
spring.kafka.properties.specific.avro.reader=true
```

**3. Producer & Consumer**
The `KafkaTemplate` and `@KafkaListener` now work with your generated Avro class. The Schema Registry validates the schema and ensures backward-compatible evolution.

### 📊 Monitoring with Micrometer

Spring Boot Actuator auto-configures Micrometer to expose Kafka metrics out of the box—no extra code needed beyond the dependency.

**1. Add Dependencies**
```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

**2. Expose Metrics**
```properties
management.endpoints.web.exposure.include=*
```

Key metrics appear at `/actuator/metrics`:
- **Producer**: `kafka.producer.record.error.rate`, `kafka.producer.request.latency.avg`
- **Consumer**: `kafka.consumer.fetch.manager.records.lag`, `kafka.consumer.fetch.manager.fetch.latency.avg`

**3. Custom Tags for Filtering**
Add a `MicrometerProducerListener` to your `ProducerFactory` to tag every metric with an application name, making it easier to filter in Grafana or Prometheus.

```java
pf.addListener(new MicrometerProducerListener<>(
    meterRegistry,
    List.of(new ImmutableTag("app-name", "order-service"))
));
```

Similar customization is available for consumers and for `KafkaTemplate` / `@KafkaListener` via `setMicrometerTags()`.

**4. Tracing**
Micrometer Observation automatically propagates `traceId` and `spanId` across Kafka message headers, allowing you to correlate a single request across producers and consumers in your logs.

---
**One critical note:** Exactly-once semantics with transactions adds latency and requires careful configuration of `isolation.level=read_committed` on consumers. Use it only when the business logic truly demands atomicity between Kafka and an external system.
