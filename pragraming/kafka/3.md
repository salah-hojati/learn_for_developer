### 5. `KafkaConfig.java` — factories, error handler, topics, Micrometer tags

```java
@Configuration
public class KafkaConfig {

    @Bean
    public ProducerFactory<String, OrderEvent> producerFactory(
            KafkaProperties props, MeterRegistry registry) {
        var factory = new DefaultKafkaProducerFactory<String, OrderEvent>(
                props.buildProducerProperties());
        factory.setTransactionIdPrefix("order-tx-");
        factory.addListener(new MicrometerProducerListener<>(registry,
                List.of(new ImmutableTag("app", "order-service"))));
        return factory;
    }

    @Bean
    public ConsumerFactory<String, OrderEvent> consumerFactory(
            KafkaProperties props, MeterRegistry registry) {
        var factory = new DefaultKafkaConsumerFactory<String, OrderEvent>(
                props.buildConsumerProperties());
        factory.addListener(new MicrometerConsumerListener<>(registry,
                List.of(new ImmutableTag("app", "order-service"))));
        return factory;
    }

    @Bean
    public KafkaTemplate<String, OrderEvent> kafkaTemplate(
            ProducerFactory<String, OrderEvent> pf) {
        return new KafkaTemplate<>(pf);
    }

    @Bean
    public DefaultErrorHandler kafkaErrorHandler(KafkaTemplate<Object, Object> tpl) {
        var recoverer = new DeadLetterPublishingRecoverer(tpl,
                (record, ex) -> new TopicPartition(record.topic() + ".DLT", -1));
        return new DefaultErrorHandler(recoverer, new FixedBackOff(1000L, 3));
    }

    @Bean public NewTopic orderEvents() { return TopicBuilder.name("order-events").partitions(3).replicas(1).build(); }
    @Bean public NewTopic orderAudit()  { return TopicBuilder.name("order-audit").partitions(1).replicas(1).build(); }
    @Bean public NewTopic orderEventsDlt() { return TopicBuilder.name("order-events.DLT").partitions(1).replicas(1).build(); }
}
```

> ⚠️ **Gotcha:** the `KafkaTemplate` used for DLT re-publishes the deserialized payload using its **own serializers**. Because you're on Avro here, `KafkaAvroSerializer` must be reachable by that template — hence the `KafkaTemplate<Object, Object>` still resolves through the same auto-configured producer properties.

### 6. `OrderEventPublisher.java` — transactional producer

```java
@Service
public class OrderEventPublisher {
    private final KafkaTemplate<String, OrderEvent> kafka;

    public OrderEventPublisher(KafkaTemplate<String, OrderEvent> kafka) {
        this.kafka = kafka;
    }

    /** Both writes commit together, or neither is visible to readers. */
    public void publish(OrderEvent event) {
        kafka.executeInTransaction(ops -> {
            ops.send("order-events", event.getOrderId(), event);
            ops.send("order-audit",  event.getOrderId(), event);
            return true;
        });
    }
}
```

### 7. `OrderEventConsumer.java` — EOS with `@Transactional`

```java
@Component
public class OrderEventConsumer {

    private static final Logger log = LoggerFactory.getLogger(OrderEventConsumer.class);

    private final ProcessedOrdersRepository processed;   // JPA or simple in-memory set
    private final KafkaTemplate<String, OrderEvent> kafka;

    public OrderEventConsumer(ProcessedOrdersRepository processed,
                              KafkaTemplate<String, OrderEvent> kafka) {
        this.processed = processed;
        this.kafka = kafka;
    }

    @KafkaListener(topics = "order-events", groupId = "order-processor")
    @Transactional   // joins the container's KafkaTransactionManager
    public void onOrder(OrderEvent event) {
        // 1. Idempotency guard – skip already-processed IDs
        if (processed.existsByOrderId(event.getOrderId())) {
            log.debug("Skipping duplicate {}", event.getOrderId());
            return;
        }

        // 2. Business side effect (DB write). If it throws → tx rollback + redeliver.
        processed.save(event.getOrderId());

        // 3. Downstream send – atomically part of the same Kafka transaction.
        kafka.send("order-audit", event.getOrderId(), event);
    }
}
```

Key points:
- **If the method throws**, the transaction rolls back and the offset is **not** committed → Kafka redelivers.
- **If it succeeds**, the offset commit + the `order-audit` write are committed **atomically** → exactly-once semantics across consume-transform-produce.
- Because `isolation-level=read_committed`, downstream consumers won't see half-open transactions.
- The **idempotency guard** protects you from redelivery caused by crashes *after* commit but *before* the broker recorded it (rare, but possible).

### 8. Manual-ack variant (choose this *instead of* transactions when you don't need atomic produce)

```java
@Component
public class ManualAckConsumer {
    @KafkaListener(topics = "order-events-manual", groupId = "manual-processor")
    public void onEvent(OrderEvent event, Acknowledgment ack) {
        processOrder(event);
        ack.acknowledge();           // commit offset only after success
        // exceptions bubble to the DefaultErrorHandler → retry → DLT
    }
}
```

Trade-off: at-least-once only (a crash between processing and ack redelivers), but no transactional overhead.

### 9. `OrderEventIntegrationTest.java` — end-to-end without Docker

```java
@SpringBootTest
@EmbeddedKafka(
    partitions = 1,
    topics = { "order-events", "order-audit", "order-events.DLT" },
    brokerProperties = {
        "transaction.state.log.replication.factor=1",
        "transaction.state.log.min.isr=1",
        "offsets.topic.replication.factor=1"
    })
class OrderEventIntegrationTest {

    @Autowired OrderEventPublisher publisher;
    @Autowired ProcessedOrdersRepository processed;

    @Test
    void publish_shouldTriggerConsumerAndAudit() {
        var event = OrderEvent.newBuilder()
                .setOrderId("o-1").setCustomerId("c-1")
                .setAmount(49.99).setStatus(OrderStatus.CREATED)
                .setCreatedAt(System.currentTimeMillis()).build();

        publisher.publish(event);

        // Poll (Avro + transactions are async) up to 10s
        Awaitility.await().atMost(Duration.ofSeconds(10)).untilAsserted(() ->
                assertThat(processed.existsByOrderId("o-1")).isTrue());
    }
}
```

> ⚠️ **Note:** `@EmbeddedKafka` starts a plain broker without Schema Registry. To run Avro-backed tests, either (a) point `schema.registry.url` at a Testcontainers-managed registry, or (b) switch to `JsonSerializer` for the test profile. The **transaction broker properties above are mandatory** — without them the embedded broker rejects the `KafkaTransactionManager`.

### 🧠 Summary of the design

| Concern | How it's handled |
|---|---|
| Delivery guarantees | Transactions + `read_committed` → EOS; manual ack → at-least-once |
| Schema evolution | Avro + Schema Registry with compatibility checks on `OrderEvent` |
| Poison pills | `DefaultErrorHandler` → 3 retries → `.DLT` topic |
| Idempotency | `ProcessedOrdersRepository.existsByOrderId` guard |
| Observability | `MicrometerProducerListener` / `MicrometerConsumerListener` tagged `app=order-service`; visible at `/actuator/metrics` |
| Testing | `@EmbeddedKafka` + `Awaitility` (or Testcontainers + Schema Registry) |

**Try this next:** swap `ProcessedOrdersRepository` for a real JPA entity so the DB write and Kafka offset truly share a transaction — the current sample uses a simple repo for brevity, but the pattern is identical with Spring's `JpaTransactionManager` once you've wired `ChainedTransactionManager` (deprecated) or the idiomatic **outbox pattern** for cross-resource atomicity.
