در **Spring Security**، تفاوت اصلی بین خانواده `Authorize` و خانواده `Filter` در این است که **Authorize تصمیم می‌گیرد آیا کلِ فراخوانی متد مجاز است یا خیر**، اما **Filter عناصرِ داخل یک مجموعه (Collection یا Array) را غربال می‌کند** تا فقط موارد مجاز باقی بمانند.

* **`@PreAuthorize` / `@PostAuthorize` (تصمیم‌گیری کلّی / Authorization):** اگر شرط برقرار نباشد، کل متد را متوقف می‌کنند یا کل نتیجه را رد می‌کنند و `AccessDeniedException` می‌دهند.
* **`@PreFilter` / `@PostFilter` (پالایش مجموعه‌ها / Filtering):** روی عناصرِ یک `Collection` یا آرایه اعمال می‌شوند و عناصر نامجاز را حذف می‌کنند (معمولاً بدون پرتاب `AccessDeniedException` برای کل متد، مگر اینکه کل مجموعه غیرقابل فیلتر باشد).

---

### ۱. تفاوت دقیق هر چهار Annotation

| Annotation | زمان اجرا | هدف اصلی | خروجی در صورت عدم تطابق شرط |
| --- | --- | --- | --- |
| **`@PreAuthorize`** | قبل از اجرای متد | مجوزدهی کلی بر اساس نقش، کاربر یا ورودی‌ها | عدم اجرای متد + `AccessDeniedException` |
| **`@PostAuthorize`** | پس از اجرای متد | مجوزدهی کلی بر اساس `returnObject` | رد کردن نتیجه + `AccessDeniedException` |
| **`@PreFilter`** | قبل از اجرای متد | حذف آیتم‌های نامجاز از یک مجموعه **ورودی** | حذف آیتم‌ها از مجموعه قبل از ورود به متد |
| **`@PostFilter`** | پس از اجرای متد | حذف آیتم‌های نامجاز از مجموعه **خروجی** (`filterObject`) | حذف آیتم‌ها از مجموعه بازگشتی قبل از تحویل |

---

### ۲. کی از `@PreFilter` و `@PostFilter` استفاده کنیم؟

#### استفاده از `@PreFilter`

وقتی متد یک لیست یا مجموعه ورودی می‌گیرد و می‌خواهید قبل از پردازش، آیتم‌هایی که کاربر مجاز به کار با آن‌ها نیست از لیست حذف شوند. به‌طور پیش‌فرض اگر فقط یک مجموعه در پارامترها باشد نیازی به `filterTarget` نیست؛ اگر چند مجموعه دارید، `filterTarget` را مشخص کنید:

```java
@Service
public class NotificationService {

    // حذف پیام‌هایی که فرستنده آن‌ها کاربر فعلی نیست قبل از ارسال دسته‌جمعی
    @PreFilter("filterObject.senderUsername == authentication.name")
    public void sendBatch(List<Message> messages) {
        // در اینجا فقط پیام‌های مجاز باقی مانده‌اند
        messageDispatcher.dispatchAll(messages);
    }

    // وقتی بیش از یک مجموعه در ورودی وجود دارد، filterTarget ضروری است
    @PreFilter(filterTarget = "documentIds", value = "@docAccess.canArchive(authentication, filterObject)")
    public void archiveDocuments(List<Long> documentIds, String reason) {
        documentRepository.archiveAll(documentIds, reason);
    }
}

```

#### استفاده از `@PostFilter`

وقتی متد یک مجموعه (مانند `List` یا `Set`) برمی‌گرداند و می‌خواهید آیتم‌هایی که کاربر اجازه دیدنشان را ندارد از خروجی حذف شوند. در عبارت SpEL از متغیر `filterObject` برای اشاره به هر عنصر استفاده می‌شود:

```java
@Service
public class TaskService {

    // فیلتر کردن تسک‌ها پس از واکشی تا فقط تسک‌های قابل مشاهده برای کاربر بمانند
    @PostFilter("filterObject.assignee == authentication.name or filterObject.isPublic or hasRole('MANAGER')")
    public List<Task> getAllTasks() {
        return taskRepository.findAll();
    }
}

```

### ۳. چه زمانی از `Filter` استفاده نکنیم؟

* **مجموعه‌های بزرگ در دیتابیس:** `@PostFilter` ابتدا همه رکوردها را از دیتابیس می‌کشد و سپس در حافظه فیلتر می‌کند. اگر تعداد رکوردها زیاد باشد، هم کارایی افت می‌کند و هم صفحه‌بندی (`Pagination`) به هم می‌ریزد. در این موارد بهتر است شرط را مستقیماً در کوئری دیتابیس (مثلاً با Spring Data JPA و `Authentication`) اعمال کنید.
* **مجموعه‌های غیرقابل تغییر (Immutable):** اگر متدی یک `List.of(...)` یا مجموعه غیرقابل تغییر برگرداند، `@PostFilter` که تلاش کند آیتمی را حذف کند ممکن است با `UnsupportedOperationException` مواجه شود؛ پس خروجی باید یک مجموعه قابل ویرایش (مانند `ArrayList`) باشد.
* **وقتی کل عملیات باید رد شود:** اگر کاربر اصلاً نباید اجازه دسترسی به آن متد یا منبع را داشته باشد، از `@PreAuthorize` یا `@PostAuthorize` استفاده کنید تا `AccessDeniedException` برگردد و وضعیت خطا برای کلاینت شفاف باشد.
