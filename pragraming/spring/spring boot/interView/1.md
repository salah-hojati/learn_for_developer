در Spring Boot، مفهوم **Auto-Configuration** یعنی Spring Boot با بررسی وابستگی‌های پروژه، کلاس‌های موجود در Classpath، تنظیمات و Beanهای تعریف‌شده توسط برنامه‌نویس، بسیاری از تنظیمات موردنیاز برنامه را به‌صورت خودکار انجام می‌دهد.

به زبان ساده، به‌جای اینکه خودمان تمام Beanها و تنظیمات را دستی تعریف کنیم، Spring Boot تشخیص می‌دهد چه چیزهایی لازم داریم و آن‌ها را پیکربندی می‌کند.

# **۱. Auto-Configuration چگونه فعال می‌شود؟**

وقتی یک پروژه Spring Boot می‌سازیم، معمولاً کلاس اصلی به این شکل است:

```
@SpringBootApplication
public class MyApplication {

    public static void main(String[] args) {
        SpringApplication.run(
            MyApplication.class, args
        );
    }
}
```

نکته مهم این است که Annotation زیر:

```
@SpringBootApplication
```

در واقع ترکیبی از سه Annotation است:

```
@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
```

هرکدام وظیفه مشخصی دارند:

| Annotation                 | وظیفه                             |
| -------------------------- | --------------------------------- |
| `@SpringBootConfiguration` | مشخص‌کردن کلاس اصلی Configuration |
| `@EnableAutoConfiguration` | فعال‌کردن Auto-Configuration      |
| `@ComponentScan`           | اسکن و شناسایی Componentها        |

بنابراین موتور اصلی Auto-Configuration، Annotation زیر است:

```
@EnableAutoConfiguration
```

# **۲. مکانیزم Auto-Configuration چگونه کار می‌کند؟**

فرض کن در پروژه این Dependency را اضافه کرده‌ای:

```
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
```

با اضافه‌شدن این Dependency، کتابخانه‌های مرتبط با JPA و Hibernate وارد Classpath می‌شوند.

Spring Boot متوجه می‌شود که قابلیت JPA در دسترس است.

سپس بررسی می‌کند:

1. آیا کلاس‌های موردنیاز JPA در Classpath وجود دارند؟
2. آیا Beanهای موردنیاز قبلاً توسط برنامه‌نویس تعریف شده‌اند؟
3. آیا تنظیمات مربوط به JPA در Configuration موجود است؟
4. آیا شرایط لازم برای فعال‌شدن Configuration برقرار است؟

اگر شرایط برقرار باشند، Beanهای موردنیاز را ایجاد می‌کند.

برای مثال:

- `DataSource`
- `EntityManagerFactory`
- `JpaTransactionManager`

البته ایجاد هرکدام به شرایط و تنظیمات پروژه وابسته است.

**اضافه‌شدن Dependency به پروژه**

**بررسی Classpath**

**بررسی Conditional Annotations**

**بررسی Beanهای موجود**

**ایجاد Beanهای موردنیاز**

# **۳. نقش Conditional Annotations چیست؟**

این بخش مهم‌ترین قسمت Auto-Configuration است.

Spring Boot از Annotationهای شرطی استفاده می‌کند تا تصمیم بگیرد یک Configuration باید فعال شود یا خیر.

مهم‌ترین آن‌ها:

| Annotation                     | کاربرد                                |
| ------------------------------ | ------------------------------------- |
| `@ConditionalOnClass`          | اگر کلاس مشخصی در Classpath وجود داشت |
| `@ConditionalOnMissingBean`    | اگر Bean مشخصی وجود نداشت             |
| `@ConditionalOnBean`           | اگر Bean مشخصی وجود داشت              |
| `@ConditionalOnProperty`       | اگر یک Property مقدار مشخصی داشت      |
| `@ConditionalOnWebApplication` | اگر برنامه یک Web Application بود     |
| `@ConditionalOnResource`       | اگر Resource مشخصی وجود داشت          |

مثلاً:

```
@Configuration
@ConditionalOnClass(DataSource.class)
public class MyDatabaseConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public MyDatabaseService myDatabaseService() {
        return new MyDatabaseService();
    }
}
```

این Configuration دو شرط دارد:

- کلاس `DataSource` باید در Classpath موجود باشد.
- نباید قبلاً Beanای از نوع `MyDatabaseService` تعریف شده باشد.

اگر هر دو شرط برقرار باشند، Spring Bean را ایجاد می‌کند.

# **۴. آیا می‌توانیم Auto-Configuration را Override کنیم؟**

بله؛ این یکی از مهم‌ترین ویژگی‌های Spring Boot است.

فرض کن Spring Boot قرار است یک Bean از نوع `DataSource` ایجاد کند.

اما ما می‌خواهیم DataSource خودمان را تعریف کنیم.

```
@Configuration
public class DatabaseConfig {

    @Bean
    public DataSource dataSource() {

        return DataSourceBuilder.create()
            .url("jdbc:postgresql://localhost:5432/mydb")
            .username("admin")
            .password("123456")
            .driverClassName(
                "org.postgresql.Driver"
            )
            .build();
    }
}
```

چون Bean از نوع `DataSource` را خودمان تعریف کرده‌ایم، Auto-Configuration مربوط به DataSource معمولاً به دلیل شرط `@ConditionalOnMissingBean` از ایجاد Bean جایگزین خودداری می‌کند.

**اصل مهم:**

Spring Boot به‌صورت پیش‌فرض تنظیمات لازم را فراهم می‌کند، اما اجازه می‌دهد آن‌ها را با تنظیمات خودمان جایگزین کنیم.

# **۵. مثال عملی: Auto-Configuration در Spring MVC**

فرض کن این Dependency را اضافه می‌کنیم:

```
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

Spring Boot با توجه به Dependencyهای موجود می‌تواند تنظیمات متداول Web Application را فراهم کند؛ از جمله:

- پیکربندی Spring MVC
- ثبت Handler Mappingها
- ثبت Handler Adapterها
- پیکربندی Message Converterها
- راه‌اندازی Embedded Tomcat در حالت پیش‌فرض

در نتیجه لازم نیست برای راه‌اندازی یک REST API ساده، همه این موارد را دستی تعریف کنیم.

مثلاً:

```
@RestController
@RequestMapping("/users")
public class UserController {

    @GetMapping
    public String getUsers() {
        return "List of users";
    }
}
```

با همین کد می‌توانیم یک Endpoint داشته باشیم.

# **۶. فایل‌های Auto-Configuration کجا هستند؟**

این سؤال برای مصاحبه بسیار مهم است.

در نسخه‌های جدید Spring Boot، کلاس‌های Auto-Configuration معمولاً از طریق فایل زیر معرفی می‌شوند:

```
META-INF/spring/
    org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

این فایل نام کلاس‌های Auto-Configuration را در اختیار Spring Boot قرار می‌دهد.

برای مثال ممکن است نام کلاس‌هایی مانند این را در آن ببینی:

```
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
```

در نسخه‌های قدیمی‌تر Spring Boot، از فایل زیر استفاده می‌شد:

```
META-INF/spring.factories
```

بنابراین نباید سازوکار نسخه‌های قدیمی و جدید را با هم اشتباه بگیریم.

# **۷. چگونه بفهمیم Spring Boot چه Auto-Configurationهایی را فعال کرده است؟**

برای بررسی تصمیمات Spring Boot می‌توانیم از گزینه زیر استفاده کنیم:

```
debug=true
```

با اجرای برنامه، گزارشی به نام **Condition Evaluation Report** در خروجی نمایش داده می‌شود.

این گزارش نشان می‌دهد:

- کدام Auto-Configuration فعال شده است.
- کدام Configuration فعال نشده است.
- کدام شرط باعث فعال یا غیرفعال‌شدن آن شده است.

این ابزار هنگام Debug کردن مشکلات Auto-Configuration بسیار مفید است.

# **۸. جمع‌بندی مهم برای مصاحبه**

| سؤال                                            | پاسخ کوتاه                                                |
| ----------------------------------------------- | --------------------------------------------------------- |
| Auto-Configuration چیست؟                        | تنظیم خودکار Beanها براساس شرایط برنامه                   |
| چگونه فعال می‌شود؟                              | با `@EnableAutoConfiguration`                             |
| `@SpringBootApplication` چه می‌کند؟             | ترکیب سه Annotation اصلی                                  |
| شرط فعال‌شدن Configuration چیست؟                | Conditional Annotations                                   |
| آیا می‌توانیم تنظیمات را Override کنیم؟         | بله، با تعریف Bean یا Configuration خودمان                |
| کلاس‌های Auto-Configuration چگونه پیدا می‌شوند؟ | از طریق فایل `AutoConfiguration.imports` در نسخه‌های جدید |

نکته طلایی مصاحبه

Auto-Configuration به معنی ساختن تصادفی Beanها نیست؛ بلکه مجموعه‌ای از Configurationهای از پیش نوشته‌شده است که با استفاده از Conditional Annotations و بررسی محیط برنامه، تصمیم می‌گیرند چه Beanهایی باید ساخته شوند.

# **۹. سؤال تمرینی مصاحبه**

فرض کن این دو Bean را داریم:

```
@Configuration
public class AppConfig {

    @Bean
    public MyService myService() {
        return new MyService();
    }
}
```

و در یک Auto-Configuration دیگر:

```
@AutoConfiguration
public class MyAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean(MyService.class)
    public MyService defaultMyService() {
        return new MyService();
    }
}
```

**سؤال:** وقتی برنامه اجرا می‌شود، چند Bean از نوع `MyService` ساخته خواهد شد؟ چرا؟

پاسخ این سؤال به تو کمک می‌کند مفهوم `@ConditionalOnMissingBean` و نحوه Override کردن Auto-Configuration را واقعاً درک کنی.
