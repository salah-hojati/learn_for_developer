<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


تفاوت اصلی **Spring Data JPA** با **JPA خام (Raw JPA)** در این است که Spring Data JPA روی JPA ساخته شده و بسیاری از کارهای تکراری مربوط به Repository، Query و دسترسی به دیتابیس را ساده و خودکار می‌کند.

نکته مهم: Spring Data JPA جایگزین JPA نیست؛ بلکه Abstraction و امکانات بیشتری روی آن ارائه می‌دهد.

# **۱. JPA خام چیست؟**

JPA یک Specification در Java برای مدیریت ارتباط بین Objectهای Java و جداول دیتابیس (ORM) است.

در JPA خام، معمولاً با `EntityManager` کار می‌کنیم.

مثلاً برای ذخیره یک User:


<div dir="ltr" style="text-align: left;">


```
@Repository
public class UserRepository {

    @PersistenceContext
    private EntityManager entityManager;

    public void save(User user) {
        entityManager.persist(user);
    }

    public User findById(Long id) {
        return entityManager.find(User.class, id);
    }

    public void delete(User user) {
        entityManager.remove(user);
    }
}
```
</div>

برای هر Repository باید متدهای موردنیاز را خودمان پیاده‌سازی کنیم.

# **۲. Spring Data JPA چیست؟**

Spring Data JPA یک ماژول از خانواده Spring Data است که کار با JPA را ساده‌تر می‌کند.

به‌جای پیاده‌سازی دستی Repository، کافی است Interface تعریف کنیم:

<div dir="ltr" style="text-align: left;">

```
public interface UserRepository
        extends JpaRepository<User, Long> {
}
```
</div>


Spring Data JPA در زمان اجرا پیاده‌سازی این Interface را ایجاد می‌کند.

بدون اینکه خودمان متدهای CRUD را بنویسیم، امکانات زیر را داریم:
<div dir="ltr" style="text-align: left;">


```
userRepository.save(user);

userRepository.findById(1L);

userRepository.findAll();

userRepository.deleteById(1L);

userRepository.count();
```
</div>


# **۳. مقایسه JPA خام و Spring Data JPA**

| ویژگی          | Raw JPA                         | Spring Data JPA                      |
| -------------- | ------------------------------- | ------------------------------------ |
| CRUD           | پیاده‌سازی با EntityManager     | آماده                                |
| Query          | JPQL، Criteria API و Native SQL | Query Methods، JPQL و Native SQL     |
| Pagination     | پیاده‌سازی دستی                 | Pageable و Page                      |
| Sorting        | پیاده‌سازی دستی                 | Sort                                 |
| Repository     | پیاده‌سازی دستی                 | Interface-based                      |
| Transaction    | JTA یا Transaction Manager      | یکپارچگی با Spring Transaction       |
| کنترل جزئیات   | بیشتر                           | در حالت عادی کمتر                    |
| کدنویسی تکراری | بیشتر                           | کمتر                                 |
| انعطاف‌پذیری   | بسیار زیاد                      | زیاد، با امکان استفاده از JPA مستقیم |

# **۴. مزایای Spring Data JPA**

## **مزیت اول: کاهش کدنویسی تکراری**

در JPA خام باید متدهای CRUD را پیاده‌سازی کنیم.

اما در Spring Data JPA:
<div dir="ltr" style="text-align: left;">


```
public interface UserRepository
        extends JpaRepository<User, Long> {
}
```
</div>


بسیاری از عملیات آماده هستند.

این موضوع باعث کاهش Boilerplate Code می‌شود.

## **مزیت دوم: Query Methods**

یکی از قابلیت‌های جذاب Spring Data JPA ساخت Query براساس نام متد است.

مثلاً:
<div dir="ltr" style="text-align: left;">


```
public interface UserRepository
        extends JpaRepository<User, Long> {

    List<User> findByFirstName(String firstName);

    List<User> findByAgeGreaterThan(int age);

    List<User> findByEmailAndActiveTrue(String email);

    Optional<User> findByEmail(String email);

    List<User> findByFirstNameContaining(String name);
}
```
</div>


Spring Data JPA از روی نام متد، Query مناسب را تولید می‌کند.

مثلاً:
<div dir="ltr" style="text-align: left;">


```
findByAgeGreaterThan(18);
```
</div>


تقریباً معادل Query زیر است:
<div dir="ltr" style="text-align: left;">

```
SELECT *
FROM users
WHERE age > 18;
```
</div>


## **مزیت سوم: Pagination و Sorting**

در JPA خام باید Pagination را با `setFirstResult()` و `setMaxResults()` مدیریت کنیم.

اما در Spring Data JPA:
<div dir="ltr" style="text-align: left;">


```
Page<User> findAll(Pageable pageable);
```
</div>


استفاده:
<div dir="ltr" style="text-align: left;">


```
Pageable pageable =
    PageRequest.of(0, 10, Sort.by("name"));

Page<User> users =
    userRepository.findAll(pageable);
```
</div>


در این مثال:

- صفحه اول دریافت می‌شود.
- هر صفحه ۱۰ رکورد دارد.
- اطلاعات براساس نام مرتب می‌شوند.

## **مزیت چهارم: Query Annotation**

اگر Query پیچیده باشد، می‌توانیم از `@Query` استفاده کنیم.
<div dir="ltr" style="text-align: left;">


```
@Query("""
    SELECT u
    FROM User u
    WHERE u.age > :age
    AND u.active = true
""")
List<User> findActiveUsersOlderThan(
    @Param("age") int age
);
```
</div>


حتی می‌توانیم Native SQL بنویسیم:
<div dir="ltr" style="text-align: left;">


```
@Query(
    value = "SELECT * FROM users WHERE age > :age",
    nativeQuery = true
)
List<User> findUsersByAge(
    @Param("age") int age
);
```
</div>


بنابراین Spring Data JPA ما را به Query Methodها محدود نمی‌کند.

## **مزیت پنجم: Custom Repository**

اگر عملیات خاصی داشته باشیم که با امکانات استاندارد Spring Data JPA به‌خوبی قابل پیاده‌سازی نباشد، می‌توانیم از EntityManager استفاده کنیم.

مثلاً:
<div dir="ltr" style="text-align: left;">


```
public interface UserRepositoryCustom {

    List<User> searchUsers(String name);
}
```
</div>


پیاده‌سازی:
<div dir="ltr" style="text-align: left;">


```
@Repository
public class UserRepositoryCustomImpl
        implements UserRepositoryCustom {

    @PersistenceContext
    private EntityManager entityManager;

    @Override
    public List<User> searchUsers(String name) {

        return entityManager.createQuery(
            """
            SELECT u FROM User u
            WHERE u.name LIKE :name
            """,
            User.class
        )
        .setParameter("name", "%" + name + "%")
        .getResultList();
    }
}
```
</div>


سپس این Interface را به Repository اصلی اضافه می‌کنیم:
<div dir="ltr" style="text-align: left;">


```
public interface UserRepository
        extends JpaRepository<User, Long>,
                UserRepositoryCustom {
}
```
</div>


پس حتی با Spring Data JPA هم می‌توانیم کنترل مستقیم روی EntityManager داشته باشیم.

# **۵. معایب Spring Data JPA**

با وجود مزایای زیاد، استفاده از آن همیشه بهترین انتخاب نیست.

## **عیب اول: پیچیدگی Query Methods**

گاهی نام متدها بیش از حد طولانی می‌شوند.

مثلاً:
<div dir="ltr" style="text-align: left;">


```
findByFirstNameAndLastNameAndAgeGreaterThanAndActiveTrue(...)
```
</div>


وقتی شرط‌های زیادی داریم، خوانایی کاهش پیدا می‌کند.

در این شرایط بهتر است از `@Query` یا Specification استفاده کنیم.

## **عیب دوم: کاهش کنترل مستقیم**

در Spring Data JPA بسیاری از عملیات توسط Framework انجام می‌شوند.

در نتیجه ممکن است برنامه‌نویس دقیقاً متوجه نشود:

- چه Queryای اجرا شده است؟
- چه زمانی Flush انجام می‌شود؟
- چه زمانی Entity از Persistence Context خارج می‌شود؟
- چه تعداد Query به دیتابیس ارسال شده است؟

البته این مشکل با Logging و شناخت JPA قابل مدیریت است.

## **عیب سوم: مشکلات Performance**

Spring Data JPA به‌خودی‌خود تضمین‌کننده Performance نیست.

مثلاً مشکل معروف N+1 Query می‌تواند در هر دو روش Raw JPA و Spring Data JPA اتفاق بیفتد.

مثال:
<div dir="ltr" style="text-align: left;">


```
List<Order> orders = orderRepository.findAll();

for (Order order : orders) {
    System.out.println(
        order.getCustomer().getName()
    );
}
```
</div>


اگر Customer به‌صورت Lazy بارگذاری شود، ممکن است برای هر Order یک Query جداگانه اجرا شود.

راهکارهایی مانند موارد زیر می‌توانند کمک کنند:

- `JOIN FETCH`
- `@EntityGraph`
- Batch Fetching
- Projection
- بررسی SQLهای اجراشده

مثلاً:
<div dir="ltr" style="text-align: left;">


```
@Query("""
    SELECT o
    FROM Order o
    JOIN FETCH o.customer
""")
List<Order> findAllWithCustomer();
```
</div>


## **عیب چهارم: وابستگی بیشتر به اکوسیستم Spring**

Spring Data JPA به Spring وابسته است.

اگر پروژه‌ای داشته باشیم که بخواهیم آن را مستقل از Spring یا در یک محیط Java/Jakarta EE دیگر اجرا کنیم، JPA خام انتخاب مستقل‌تری است.

# **۶. چه زمانی از کدام استفاده می‌کنم؟**

| شرایط پروژه                     | انتخاب مناسب                        |
| ------------------------------- | ----------------------------------- |
| پروژه معمولی CRUD               | Spring Data JPA                     |
| سیستم مدیریت کاربران و سفارش‌ها | Spring Data JPA                     |
| نیاز به Pagination و Sorting    | Spring Data JPA                     |
| Queryهای پیچیده                 | Spring Data JPA + Custom Repository |
| کنترل دقیق EntityManager        | Raw JPA یا Custom Repository        |
| پروژه مستقل از Spring           | JPA خام                             |
| عملیات Bulk و بهینه‌سازی خاص    | EntityManager یا Native SQL         |

نکته حرفه‌ای: این دو روش رقیب مطلق نیستند. در یک پروژه Spring Boot می‌توانیم برای ۹۰ درصد عملیات از Spring Data JPA و برای بخش‌های خاص از EntityManager استفاده کنیم.

# **۸. پاسخ مناسب برای مصاحبه**

اگر مصاحبه‌کننده بپرسد:

**What are the advantages and disadvantages of Spring Data JPA compared to raw JPA?**

می‌توانی این‌طور پاسخ بدهی:
<div dir="ltr" style="text-align: left;">


> Spring Data JPA is built on top of the JPA specification and simplifies database access by providing ready-to-use repository implementations.
>
> Its main advantages are reduced boilerplate code, derived query methods, built-in pagination, sorting, and easier integration with Spring's transaction management.
>
> However, it can introduce abstraction overhead, make complex query methods harder to maintain, and sometimes hide important persistence details.
>
> It also does not automatically solve performance problems such as N+1 queries.
>
> In real-world projects, I usually use Spring Data JPA for standard CRUD operations and custom queries, while using EntityManager directly when I need more control over complex queries or persistence operations.
<div dir="ltr" style="text-align: left;">
