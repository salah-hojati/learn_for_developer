این سه مفهوم در تست‌نویسی Spring Boot کاربرد زیادی دارند، اما وظیفه یکسانی ندارند:

- `@MockBean`: یک Bean را در Spring Context با Mock جایگزین می‌کند.
- `@WebMvcTest`: فقط لایه Web و Controllerها را برای تست بارگذاری می‌کند.
- `@SpringBootTest`: تقریباً کل Application Context را برای تست بارگذاری می‌کند.

بیایید با مثال بررسی کنیم.

## **۱.&#x20;**`@MockBean`**&#x20;چیست؟**

فرض کن یک `UserController` داریم که به `UserService` وابسته است:

```
@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public User getUser(@PathVariable Long id) {
        return userService.getUser(id);
    }
}
```

هنگام تست Controller، ممکن است نخواهیم واقعاً دیتابیس را صدا بزنیم.

پس `UserService` را Mock می‌کنیم:

```
@WebMvcTest(UserController.class)
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean
    private UserService userService;

    @Test
    void shouldReturnUser() throws Exception {

        User user = new User(1L, "Ali");

        Mockito.when(userService.getUser(1L))
                .thenReturn(user);

        mockMvc.perform(get("/api/users/1"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.name").value("Ali"));
    }
}
```

در این تست:

1. Spring فقط زیرساخت Web و Controller موردنظر را بارگذاری می‌کند.
2. `UserService` واقعی ساخته نمی‌شود؛ Mock آن در Context قرار می‌گیرد.
3. با Mockito رفتار Mock را تعریف می‌کنیم.
4. درخواست HTTP را با `MockMvc` شبیه‌سازی می‌کنیم.

**نکته نسخه‌ای مهم:** از Spring Boot 3.4 به بعد، `@MockBean` deprecated شده و پیشنهاد می‌شود از `@MockitoBean` استفاده کنیم.

```
@MockitoBean
private UserService userService;
```

`@MockitoBean` از Spring Framework 6.2 معرفی شده است.

## **۲.&#x20;**`@WebMvcTest`**&#x20;چیست؟**

این Annotation برای تست لایه Web در Spring MVC طراحی شده است.

یعنی به‌جای بالا آوردن کل برنامه، فقط اجزای مرتبط با Web را بارگذاری می‌کند.

معمولاً موارد زیر در این تست در دسترس هستند:

- `@Controller`
- `@RestController`
- `@ControllerAdvice`
- `WebMvcConfigurer`
- JSON Serialization و Deserialization
- MVC Filters و Interceptors مرتبط با تنظیمات Web

اما Service و Repository واقعی معمولاً بارگذاری نمی‌شوند.

مثال:

```
@WebMvcTest(UserController.class)
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockitoBean
    private UserService userService;

    @Test
    void getUserShouldReturn200() throws Exception {

        Mockito.when(userService.getUser(1L))
                .thenReturn(new User(1L, "Ali"));

        mockMvc.perform(get("/api/users/1"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.name").value("Ali"));
    }
}
```

چرا `@WebMvcTest` سریع‌تر است؟

چون Spring نیازی ندارد تمام Serviceها، Repositoryها، دیتابیس و سایر Beanهای برنامه را ایجاد کند.

**چه زمانی استفاده کنیم؟**

وقتی می‌خواهیم موارد زیر را تست کنیم:

- HTTP Status Code
- Request Mapping
- ورودی و خروجی JSON
- Validation
- Exception Handling با `@ControllerAdvice`
- رفتار Controller در برابر درخواست‌های HTTP

## **۳.&#x20;**`@SpringBootTest`**&#x20;چیست؟**

این Annotation برای Integration Test استفاده می‌شود.

برخلاف `@WebMvcTest`، برنامه را با Application Context کامل‌تری اجرا می‌کند و Configurationهای اصلی برنامه را بارگذاری می‌کند.

مثال:

```
@SpringBootTest
class UserServiceIntegrationTest {

    @Autowired
    private UserService userService;

    @Test
    void shouldCreateUser() {

        User user = userService.createUser(
                new UserRequest("Ali", "ali@test.com")
        );

        assertNotNull(user.getId());
    }
}
```

در این تست:

- `UserService` واقعی است.
- Repository واقعی است.
- Beanهای Spring واقعی هستند.
- اگر دیتابیس تست تنظیم شده باشد، عملیات دیتابیس نیز واقعاً اجرا می‌شود.

البته `@SpringBootTest` به‌تنهایی تضمین نمی‌کند دیتابیس واقعی یا سرور HTTP اجرا شود؛ این موضوع به تنظیمات تست بستگی دارد.

### **حالت‌های مختلف&#x20;**`@SpringBootTest`

| WebEnvironment | توضیح                                     |
| -------------- | ----------------------------------------- |
| `MOCK`         | محیط Web شبیه‌سازی می‌شود؛ حالت پیش‌فرض   |
| `RANDOM_PORT`  | سرور واقعی روی پورت تصادفی اجرا می‌شود    |
| `DEFINED_PORT` | سرور واقعی روی پورت تعریف‌شده اجرا می‌شود |
| `NONE`         | محیط Web راه‌اندازی نمی‌شود               |

مثلاً:

```
@SpringBootTest(
    webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT
)
class UserApiIntegrationTest {

    @Autowired
    private TestRestTemplate restTemplate;

    @Test
    void shouldReturnUser() {

        ResponseEntity<String> response =
                restTemplate.getForEntity(
                    "/api/users/1",
                    String.class
                );

        assertEquals(
                HttpStatus.OK,
                response.getStatusCode()
        );
    }
}
```

در این مثال یک سرور واقعی Spring Boot اجرا می‌شود و درخواست HTTP واقعی به آن ارسال می‌کنیم.

## **۴. مقایسه سه مفهوم**

`@MockBean`**&#x20;/&#x20;**`@MockitoBean`

Mocking

جایگزین کردن یک Bean واقعی با Mock در Spring Context

هدف: کنترل وابستگی‌ها

`@WebMvcTest`

Web Slice Test

بارگذاری محدود لایه Web و تست Controller

هدف: تست API و رفتار HTTP

`@SpringBootTest`

Integration Test

بارگذاری Application Context و تست تعامل اجزای واقعی

هدف: تست یکپارچگی برنامه

| ویژگی               | `@WebMvcTest`                   | `@SpringBootTest`        |
| ------------------- | ------------------------------- | ------------------------ |
| سرعت اجرا           | معمولاً بالا                    | معمولاً پایین‌تر         |
| Controller          | واقعی                           | واقعی                    |
| Service             | معمولاً Mock                    | معمولاً واقعی            |
| Repository          | معمولاً Mock یا خارج از Context | واقعی، در صورت پیکربندی  |
| Application Context | محدود                           | کامل‌تر                  |
| تست HTTP            | با MockMvc                      | با MockMvc یا HTTP واقعی |
| کاربرد اصلی         | تست Web Layer                   | تست Integration          |

توجه کن که `@MockBean` و `@WebMvcTest` رقیب یکدیگر نیستند؛ اتفاقاً اغلب با هم استفاده می‌شوند.

## **۵. چه زمانی از کدام استفاده کنیم؟**

یک استراتژی مناسب برای پروژه Spring Boot:

| نوع تست                              | ابزار پیشنهادی                 |
| ------------------------------------ | ------------------------------ |
| تست منطق یک کلاس Service بدون Spring | JUnit + Mockito                |
| تست Controller                       | `@WebMvcTest` + `@MockitoBean` |
| تست Repository و Queryهای JPA        | `@DataJpaTest`                 |
| تست یکپارچگی چند Bean                | `@SpringBootTest`              |
| تست کامل API با سرور واقعی           | `@SpringBootTest(RANDOM_PORT)` |

یک نکته مهم دیگر: برای تست Repository معمولاً `@DataJpaTest` انتخاب بهتری از `@SpringBootTest` است، چون فقط اجزای مرتبط با JPA را بارگذاری می‌کند.

## **۶. نکات مهم مصاحبه**

1. `@WebMvcTest` یک Slice Test است، نه Full Integration Test.
2. `@SpringBootTest` معمولاً کندتر است، چون Context بزرگ‌تری می‌سازد.
3. Mock کردن Service در تست Controller باعث می‌شود فقط رفتار لایه Web را بررسی کنیم.
4. در `@SpringBootTest` می‌توان Beanهای واقعی را با `@MockitoBean` جایگزین کرد، اگر بخواهیم بخشی از سیستم را Mock کنیم.
5. برای تست منطق Service نیازی نیست همیشه Spring Context را بالا بیاوریم؛ تست Unit با Mockito سریع‌تر و ساده‌تر است.
6. `@Transactional` در تست‌های Spring می‌تواند باعث Rollback شدن تغییرات دیتابیس در پایان تست شود؛ اما این رفتار به نوع تست و Transaction Manager وابسته است.

## **پاسخ مناسب برای مصاحبه (English)**

"`@MockBean` is used to replace a Spring bean with a Mockito mock inside the application context. In newer versions of Spring Boot, `@MockitoBean` is the recommended replacement.

`@WebMvcTest` is a slice testing annotation that loads only the web layer, allowing us to test controllers, request mappings, validation, and exception handling without loading the entire application.

`@SpringBootTest` loads the full Spring application context and is mainly used for integration testing, where we want to verify that multiple application components work together.

In general, I use unit tests for business logic, `@WebMvcTest` for controllers, and `@SpringBootTest` for integration tests."

## **سؤال تمرینی**

فرض کن یک پروژه Spring Boot داری با این معماری:

```
UserController
      |
      v
UserService
      |
      v
UserRepository
      |
      v
MySQL
```

می‌خواهی سه تست بنویسی:

1. بررسی کنی اگر کاربر وجود نداشت، Controller پاسخ 404 برگرداند.
2. بررسی کنی متد `UserService.createUser()` اطلاعات را درست ذخیره می‌کند.
3. بررسی کنی درخواست HTTP واقعاً از Controller به Service و Repository برسد و اطلاعات در دیتابیس ذخیره شود.

**سؤال: برای هر سه تست از چه Annotationهایی استفاده می‌کنی و کدام قسمت‌ها را Mock می‌کنی؟**
