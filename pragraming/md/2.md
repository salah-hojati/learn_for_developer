# جلسه ۲: ساختاردهی سند حرفه‌ای

در جلسه ۱ پایه‌ها را یاد گرفتی. حالا می‌رویم سراغ چیزهایی که یک سند را از «متن ساده» به «سند قابل ارائه» تبدیل می‌کند: سلسله‌مراتب عنوان‌ها، فهرست مطالب، جدول، تصویر و کنترل دقیق خطوط.

---

## ۱. سلسله‌مراتب عنوان‌ها (مهم‌ترین اصل)

قانون طلایی: **پله‌ها را جا نینداز.**

✅ درست:

```markdown
# عنوان سند
## بخش اول
### زیربخش ۱.۱
### زیربخش ۱.۲
## بخش دوم
### زیربخش ۲.۱
```

❌ غلط:

```markdown
# عنوان سند
### زیربخش بدون بخش والد
```

چرا مهم است؟ چون خیلی از ابزارها (GitHub، Obsidian، MkDocs، Sphinx، و حتی Word) **فهرست مطالب را خودکار از روی عنوان‌ها** می‌سازند. اگر ساختار به‌هم‌ریخته باشد، فهرست هم به‌هم می‌ریزد.

نکته: در هر سند فقط **یک** `#` داشته باش. عنوان سطح ۱ = نام سند.

---

## ۲. فهرست مطالب (Table of Contents)

### روش دستی

با لینک‌های لنگر (anchor) می‌سازی:

```markdown
- [مقدمه](#مقدمه)
- [نصب](#نصب)
- [پیکربندی](#پیکربندی)
```

نکته مهم: لنگر از **متن عنوان** ساخته می‌شود، نه از شماره. یعنی عنوان `## نصب و راه‌اندازی` لنگرش `#نصب-و-راه‌اندازی` است (فاصله‌ها به `-` تبدیل می‌شوند، حروف کوچک می‌شوند).

### روش خودکار

- در **GitHub**: در ویرایش فایل، روی آیکون فهرست بالای کادر متن بزن → «Insert a table of contents».
- در **VS Code**: افزونه `Markdown All in One` → دستور `Create Table of Contents`.
- در **Obsidian**: افزونه `Table of Contents`.

برای اسناد بلند، همیشه فهرست مطالب بگذار. خواننده‌ات از تو ممنون می‌شود.

## ۳. جدول

ساختار پایه:

```markdown
| ستون ۱ | ستون ۲ | ستون ۳ |
|--------|--------|--------|
| مقدار ۱ | مقدار ۲ | مقدار ۳ |
| مقدار ۴ | مقدار ۵ | مقدار ۶ |
```

خروجی:

| ستون ۱ | ستون ۲ | ستون ۳ |
|--------|--------|--------|
| مقدار ۱ | مقدار ۲ | مقدار ۳ |
| مقدار ۴ | مقدار ۵ | مقدار ۶ |

### ترازبندی ستون‌ها

با `:` در ردیف جداکننده:

```markdown
| راست‌چین | وسط‌چین | چپ‌چین |
|--------:|:-------:|:-------|
| ۱ | ۲ | ۳ |
```

یعنی:
- `:---` → چپ‌چین
- `:---:` → وسط‌چین
- `---:` → راست‌چین

### نکات جدول

- لازم نیست ستون‌ها در کد هم‌تراز باشند؛ Markdown خودش مرتب می‌کند. اما برای **خوانایی خودِ فایل خام**، هم‌تراز نوشتن را عادت کن.
- داخل جدول می‌توانی از `**پررنگ**`، `` `کد` `` و `[لینک](url)` استفاده کنی.
- برای شکستن خط داخل یک سلول، از `<br>` استفاده کن:

```markdown
| مورد | توضیح |
|------|-------|
| نصب | ابتدا Node را نصب کن<br>سپس npm install |
```

- **هشدار RTL:** جدول‌ها در بعضی پیش‌نمایش‌ها (مثل GitHub) چپ‌به‌راست رندر می‌شوند. اگر سند فارسی رسمی می‌نویسی و چیدمان ستون‌ها مهم است، جدول را با HTML بنویس و `dir="rtl"` بگذار:

```html
<table dir="rtl">
  <tr><th>نام</th><th>توضیح</th></tr>
  <tr><td>Markdown</td><td>زبان نشانه‌گذاری سبک</td></tr>
</table>
```

## ۴. تصویر

```markdown
![متن جایگزین](مسیر/به/تصویر.png)
![متن جایگزین](مسیر/به/تصویر.png "عنوان اختیاری")
```

- **متن جایگزین (alt)** را هرگز خالی نگذار. اگر تصویر لود نشد، همین متن نمایش داده می‌شود و برای دسترس‌پذیری (screen reader) هم لازم است.
- مسیر نسبی بده، نه مطلق: `images/logo.png` ✅ به‌جای `C:\Users\...\logo.png` ❌

### تغییر اندازه تصویر

Markdown استاندارد برای اندازه تصویر سینتکس ندارد. راه‌حل: HTML.

```html
<img src="images/logo.png" alt="لوگو" width="200">
```

### تصویر با لینک

```markdown
[![متن جایگزین](badge.svg)](https://example.com)
```

این الگو (تصویر داخل لینک) پایه ساخت **Badge** است که در جلسه ۴ مفصل می‌بینیم.

### نکته‌ای که خیلی‌ها را اذیت می‌کند

اگر تصویر در **همان پوشه** سند است، فقط نام فایل را بنویس: `![نمودار](chart.png)`. اگر در پوشه بالاتر است: `../assets/chart.png`.

## ۵. شکستن خط و کنترل فاصله

Markdown با Enter ساده خط جدید نمی‌سازد؛ **یک خط خالی** = پاراگراف جدید. اگر می‌خواهی داخل یک پاراگراف به خط بعد بروی، دو راه داری:

```markdown
روش اول: دو فاصله در انتهای خط··
خط بعدی

روش دوم: بک‌اسش انتهای خط\
خط بعدی

روش سوم: تگ <br>
خط بعدی
```

(در روش اول، `··` یعنی دو فاصله واقعی که نامرئی‌اند — این روش در بعضی ویرایشگرها با پاک‌سازی فاصله‌ها از بین می‌رود، پس `<br>` امن‌تر است.)

**فرق مهم:**

```markdown
خط اول
خط دوم
```
→ در خروجی به هم می‌چسبند: «خط اول خط دوم»

```markdown
خط اول

خط دوم
```
→ دو پاراگراف جدا.

## ۶. کاراکترهای ویژه را چطور چاپ کنم؟

اگر بخواهی خودِ `*` یا `#` یا `_` را در متن نشان دهی، با بک‌اسش `\` فرار کن:

```markdown
\*این ستاره است، نه کج\*
\# این عنوان نیست
```

خروجی: \*این ستاره است، نه کج\* و \# این عنوان نیست

## ۷. لیست تو در تو (تودرتو)

```markdown
- سطح اول
  - سطح دوم (دو فاصله تو رفتگی)
    - سطح سوم (چهار فاصله)
- سطح اول دیگر
  1. لیست شماره‌دار داخل لیست نشانه‌دار
  2. آیتم دوم
```

نکته: **دو فاصله** تو رفتگی استاندارد است (بعضی پارسرها ۴ فاصله می‌خواهند — برای سازگاری بیشتر، ۴ فاصله بزن).

اگر بین آیتم‌ها خط خالی بگذاری، لیست «شل» می‌شود و پاراگراف داخل آیتم می‌تواند داشته باشی:

```markdown
- آیتم اول

  این پاراگراف داخل آیتم اول است.

- آیتم دوم
```

## ۸. نمونه کامل یک سند ساختاریافته

```markdown
# راهنمای راه‌اندازی پروژه

## فهرست مطالب
- [مقدمه](#مقدمه)
- [پیش‌نیازها](#پیشنیازها)
- [نصب](#نصب)
- [پیکربندی](#پیکربندی)

## مقدمه

این سند مراحل راه‌اندازی پروژه را شرح می‌دهد.

## پیش‌نیازها

| ابزار | نسخه حداقل |
|-------|-----------:|
| Node.js | 18 |
| npm | 9 |

## نصب

1. مخزن را کلون کن
2. وابستگی‌ها را نصب کن

![نمودار نصب](images/install.png "فرایند نصب")

## پیکربندی

فایل `config.yml` را باز کن و مقادیر را تنظیم کن.
```

## تمرین جلسه ۲

یک فایل `product.md` بساز و در آن:

1. یک عنوان اصلی + سه بخش (`##`) + برای هر بخش یک زیربخش (`###`)
2. یک فهرست مطالب دستی با لینک لنگر به هر سه بخش
3. یک جدول مشخصات محصول با ۴ ستون و ترازبندی متفاوت برای هر ستون
4. یک تصویر (می‌توانی از یک URL آنلاین استفاده کنی) با متن جایگزین معنادار و عرض ۳۰۰ پیکسل
5. یک لیست تودرتو سه‌سطحی
6. یک خط که در آن کاراکتر `*` را به‌صورت متنی چاپ کنی (نه کج)

---

**اگر پیش‌نمایش جدولت در ویرایشگر چپ‌به‌راست آمد**، نگران نباش — این محدودیت خودِ پارسر است نه اشتباه تو. در جلسه ۴ راه‌حل کامل RTL را می‌بینیم.

بگو **«جلسه ۳»** تا برویم سراغ بلوک‌های کد، چک‌لیست، پانویس و لینک‌های داخلی — همان چیزهایی که اسناد فنی را حرفه‌ای می‌کند.
