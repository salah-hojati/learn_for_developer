Let's set up the project and walk through building a reactive "Product" API step by step. We'll go from an empty skeleton to a working, tested application.

- **Language**: Java
- **Spring Boot**: Choose a recent stable version

Click **Generate**, download the ZIP file, and open it in your IDE.

### 📦 Step 2: Understanding the Foundation (Mono & Flux)

Before writing endpoints, it's vital to remember the core rule of Project Reactor: **Nothing happens until you subscribe**. `Mono` (for 0 or 1 item) and `Flux` (for 0 to N items) are lazy declarations. The execution only starts when a subscriber, like the WebFlux framework, subscribes to them.

You can practice this in a simple `main` method:

```java
// This will NOT print anything because there is no subscriber
Mono<String> greeting = Mono.just("Hello, Reactive World");
greeting.map(String::toUpperCase);

// This WILL print "HELLO, REACTIVE WORLD" because we subscribed
greeting.map(String::toUpperCase)
        .subscribe(System.out::println);
```

This lazy behavior is the key to non-blocking execution.

### 💾 Step 3: Configure the Database and Entity

We'll use an in-memory H2 database, which requires minimal configuration.

1.  **Application Properties**: In `src/main/resources/application.properties`, Spring Boot will auto-configure an embedded H2 database by default. You can optionally add these lines for clarity:
    ```properties
    spring.r2dbc.url=r2dbc:h2:mem:///testdb
    spring.r2dbc.username=sa
    spring.r2dbc.password=
    ```

2.  **Schema**: Create a `schema.sql` file in `src/main/resources/` to define your table. Spring Boot will automatically execute it on startup.
    ```sql
    CREATE TABLE IF NOT EXISTS product (
        id SERIAL PRIMARY KEY,
        name VARCHAR(255) NOT NULL,
        price DECIMAL(10, 2) NOT NULL
    );
    ```

3.  **Entity Class**: Create a `Product` class. R2DBC entities use `@Table` and `@Id` annotations, similar to JPA but with a simpler feature set.
    ```java
    import org.springframework.data.annotation.Id;
    import org.springframework.data.relational.core.mapping.Table;
    import java.math.BigDecimal;

    @Table("product")
    public class Product {
        @Id
        private Long id;
        private String name;
        private BigDecimal price;

        // Constructors, getters, and setters...
    }
    ```

### 🗄️ Step 4: Create a Reactive Repository

Create a repository interface that extends `ReactiveCrudRepository`. Spring Data will automatically generate the implementation at runtime.

```java
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import reactor.core.publisher.Flux;

public interface ProductRepository extends ReactiveCrudRepository<Product, Long> {
    // You can add derived query methods, just like with JPA
    Flux<Product> findByPriceGreaterThan(BigDecimal price);
}
```

### 🎯 Step 5: Build the Reactive Service and Controller

Now, tie everything together with a service layer and a REST controller.

1.  **Service Layer**: The `ProductService` handles business logic and uses the repository. Notice the use of `flatMap` for asynchronous operations like `save` and `map` for synchronous transformations.
    ```java
    import org.springframework.stereotype.Service;
    import reactor.core.publisher.Flux;
    import reactor.core.publisher.Mono;

    @Service
    public class ProductService {
        private final ProductRepository repository;

        public ProductService(ProductRepository repository) {
            this.repository = repository;
        }

        public Flux<Product> findAll() {
            return repository.findAll();
        }

        public Mono<Product> findById(Long id) {
            return repository.findById(id);
        }

        public Mono<Product> save(Product product) {
            return repository.save(product);
        }

        public Mono<Void> deleteById(Long id) {
            return repository.deleteById(id);
        }
    }
    ```

2.  **Controller**: The `ProductController` is similar to a standard Spring MVC controller, but methods return `Mono` or `Flux`.
    ```java
    import org.springframework.http.HttpStatus;
    import org.springframework.http.ResponseEntity;
    import org.springframework.web.bind.annotation.*;
    import reactor.core.publisher.Flux;
    import reactor.core.publisher.Mono;

    @RestController
    @RequestMapping("/api/products")
    public class ProductController {
        private final ProductService productService;

        public ProductController(ProductService productService) {
            this.productService = productService;
        }

        @GetMapping
        public Flux<Product> getAllProducts() {
            return productService.findAll();
        }

        @GetMapping("/{id}")
        public Mono<ResponseEntity<Product>> getProduct(@PathVariable Long id) {
            return productService.findById(id)
                    .map(ResponseEntity::ok)
                    .defaultIfEmpty(ResponseEntity.notFound().build());
        }

        @PostMapping
        @ResponseStatus(HttpStatus.CREATED)
        public Mono<Product> createProduct(@RequestBody Mono<Product> productMono) {
            return productMono.flatMap(productService::save);
        }

        @DeleteMapping("/{id}")
        @ResponseStatus(HttpStatus.NO_CONTENT)
        public Mono<Void> deleteProduct(@PathVariable Long id) {
            return productService.deleteById(id);
        }
    }
    ```

You can now run the application. The WebFlux framework will automatically subscribe to the returned `Mono`/`Flux`, and the entire request handling pipeline will be non-blocking.

### 🌐 Step 6: Make Non-Blocking Calls with WebClient

When your reactive application needs to call another service, use **`WebClient`**. It is the non-blocking, reactive alternative to `RestTemplate`.

You can inject a pre-configured `WebClient.Builder` and use it to make calls:

```java
import org.springframework.stereotype.Service;
import org.springframework.web.reactive.function.client.WebClient;
import reactor.core.publisher.Mono;

@Service
public class ExternalApiService {
    private final WebClient webClient;

    public ExternalApiService(WebClient.Builder webClientBuilder) {
        this.webClient = webClientBuilder.baseUrl("https://api.example.com").build();
    }

    public Mono<String> fetchData(String id) {
        return webClient.get()
                .uri("/data/{id}", id)
                .retrieve()
                .bodyToMono(String.class);
    }
}
```

### ✅ Step 7: Test Your Reactive Streams

Testing reactive code requires tools that understand asynchronous streams.

1.  **`StepVerifier` (Unit Testing)**: This is the primary tool for testing your `Mono` and `Flux` directly. It allows you to declaratively assert the sequence of signals (onNext, onComplete, onError).
    ```java
    import org.junit.jupiter.api.Test;
    import reactor.core.publisher.Flux;
    import reactor.test.StepVerifier;

    class ProductServiceTest {
        @Test
        void testFindAll() {
            Flux<Product> products = Flux.just(new Product("Laptop", BigDecimal.valueOf(1200)),
                                                new Product("Mouse", BigDecimal.valueOf(25)));

            StepVerifier.create(products)
                    .expectNextMatches(p -> p.getName().equals("Laptop"))
                    .expectNextMatches(p -> p.getName().equals("Mouse"))
                    .verifyComplete();
        }
    }
    ```

2.  **`WebTestClient` (Integration Testing)**: For testing your HTTP endpoints, use `WebTestClient`. It can bind to your application context and perform requests without needing a real running server, validating the entire WebFlux processing chain (routing, binding, encoding, error handling).
    ```java
    import org.junit.jupiter.api.Test;
    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.boot.test.autoconfigure.web.reactive.AutoConfigureWebTestClient;
    import org.springframework.boot.test.context.SpringBootTest;
    import org.springframework.test.web.reactive.server.WebTestClient;

    @SpringBootTest
    @AutoConfigureWebTestClient
    class ProductControllerTest {
        @Autowired
        private WebTestClient webTestClient;

        @Test
        void testGetAllProducts() {
            webTestClient.get().uri("/api/products")
                    .exchange()
                    .expectStatus().isOk()
                    .expectBodyList(Product.class);
        }
    }
    ```

### 🔒 Next Steps and Advanced Topics

Once you are comfortable with this flow, you can explore:

- **Reactive Security**: Secure your endpoints by using `@EnableWebFluxSecurity` and a reactive `SecurityWebFilterChain`. The `SecurityContext` is propagated through Reactor's `Context`, not a `ThreadLocal`.
- **Server-Sent Events (SSE)**: Use a `Flux` to stream real-time updates to clients.
- **Custom Error Handling**: Learn to use `onErrorResume`, `onErrorReturn`, and a global `@ControllerAdvice` to manage errors reactively.

This step-by-step guide gives you a solid, working foundation. You can build on this "Product" example by adding more features as you learn.
