Here's the complete `pom.xml` for the reactive Product API project. Save it at the root of your project folder (replacing any existing `pom.xml`).

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- Spring Boot parent manages versions for all dependencies below -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.3.5</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>reactive-product</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <name>reactive-product</name>
    <description>Reactive Product API with Spring WebFlux and R2DBC</description>

    <properties>
        <!-- Spring Boot 3.x requires Java 17+. Change to 17 if you're on JDK 17. -->
        <java.version>21</java.version>
    </properties>

    <dependencies>
        <!-- 1. Reactive web stack (Netty, WebFlux). Do NOT also add spring-boot-starter-web. -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webflux</artifactId>
        </dependency>

        <!-- 2. Reactive database access (Spring Data R2DBC + connection pool) -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-r2dbc</artifactId>
        </dependency>

        <!-- 3. R2DBC driver for H2 (version managed by Spring Boot BOM) -->
        <dependency>
            <groupId>io.r2dbc</groupId>
            <artifactId>r2dbc-h2</artifactId>
            <scope>runtime</scope>
        </dependency>

        <!-- 4. H2 JDBC driver — only needed so the /h2-console web UI can connect.
                Your application itself uses the R2DBC driver above. -->
        <dependency>
            <groupId>com.h2database</groupId>
            <artifactId>h2</artifactId>
            <scope>runtime</scope>
        </dependency>

        <!-- 5. Testing: JUnit 5, AssertJ, Mockito, WebTestClient, etc. -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>

        <!-- 6. StepVerifier and other Reactor testing utilities -->
        <dependency>
            <groupId>io.projectreactor</groupId>
            <artifactId>reactor-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <!-- Enables `mvn spring-boot:run`, executable JAR packaging,
                 and efficient Docker image builds -->
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

### 📝 Key points about this `pom.xml`

- **`spring-boot-starter-webflux`** — This is the reactive web starter. Do **not** also add `spring-boot-starter-web`; having both makes Spring Boot silently fall back to the blocking Servlet stack.
- **Versions are managed by the parent** — That's why `r2dbc-h2`, `h2`, `reactor-test`, etc., have no `<version>` tags. Spring Boot's BOM picks compatible versions for you.
- **Two H2 artifacts** — `r2dbc-h2` is what your app uses at runtime for non-blocking queries. The plain `com.h2database:h2` (JDBC) is only there so the browser-based `/h2-console` can connect. It's harmless to include both.
- **Java 21** — If you're on JDK 17, change `<java.version>21</java.version>` to `17`. Anything below 17 will not work with Spring Boot 3.x.
- **Upgrading Spring Boot** — You can bump the parent `<version>` to any newer 3.x release (e.g. `3.4.x`) without touching the dependency list.
