# Lesson 8: Your first project — written by you

No new concepts today. Everything you need you already have: components, props, `useState`, lists and keys, forms, `useEffect`, and routing. Today you **combine** them into something that's yours.

This lesson is different in shape. There's no code to copy. There's a spec, a build order, and a review rubric. Your job is to build. Mine is to review what you send.

I've said this a few times already, so I'll say it once and then drop it: **you can't learn to build React apps by reading about building React apps.** If you take nothing else from this course, take this: the gap between "I understand the lesson" and "I can build the thing" is where all the learning is. You close it by writing code that breaks, reading the error, and fixing it.

## 1. Pick one project

### Option A — Book Library *(recommended)*

A personal reading tracker.

- Add a book: title, author, status (`want` / `reading` / `finished`), rating (1–5, only when finished)
- List all books as cards
- Filter by status tabs with counts
- Search by title or author
- Click a book → detail page at `/books/:id`
- Delete from the list or the detail page
- Persist to `localStorage`

**Why this one:** it has every skill except fetch, and every update you'll make is a nested-object update — the thing that breaks most beginners. Rating only applies to finished books, so you'll deal with conditional UI.

### Option B — Quiz App

10 hardcoded questions, one at a time, multiple choice. Score at the end, restart button. **Different shape:** no lists, no CRUD — it's a state machine (`questionIndex`, `answers`, `finished`). Good if you're tired of list apps. Harder to make impressive, easier to make correct.

### Option C — Weather Dashboard

Search a city, fetch current weather + 5-day forecast from a free API (Open-Meteo needs no key). Save favourite cities to `localStorage`. Recent searches as chips. **Mostly about async:** loading/error/empty states, debouncing the search, refetching when the city changes.

Pick **A** unless you have a reason not to. The rest of this lesson is written for A.

## 2. The spec (Option A)

### Data model

```js
{
  id: "uuid-string",
  title: "The Pragmatic Programmer",
  author: "Hunt & Thomas",
  status: "want" | "reading" | "finished",
  rating: 0 | 1 | 2 | 3 | 4 | 5,   // 0 = not rated
  createdAt: 1699999999999         // ms timestamp, for sorting
}
```

Decide this **first** and write it down in a comment at the top of `App.jsx`. Half of all bugs come from a data model that wasn't decided up front.

### Routes

| Path | Page | Notes |
|---|---|---|
| `/` | Home / redirect to `/books` | A one-line welcome is fine |
| `/books` | Library list | Filter + search live here |
| `/books/:id` | Book detail | Show all fields; delete; change status |
| `*` | 404 | |

Filter and search go in the URL (`?status=reading&q=pragmatic`), not `useState` — Lesson 7, §8.

### Rules

- Status and rating: `rating` only settable when `status === "finished"`. Changing status away from `finished` resets rating to `0`. *(This is a real product decision, not just an exercise — it forces you to think about derived vs. stored state.)*
- Filter tabs always show counts: `All (8) · Want (3) · Reading (2) · Finished (3)`.
- Search matches title **or** author, case-insensitive.
- Empty states: no books at all, and no results for the current filter/search. Two different messages.
- Persist to `localStorage` on every change; hydrate from it on mount. Use the **lazy initializer** form: `useState(() => loadFromStorage())` — not a `useEffect` that sets state on mount. *(If you don't remember why, re-read Lesson 6 §7.)*

### Files

```
src/
  main.jsx
  App.jsx
  pages/
    Home.jsx
    BookList.jsx
    BookDetail.jsx
    NotFound.jsx
  components/
    Layout.jsx
    BookCard.jsx
    BookForm.jsx
    FilterBar.jsx
  lib/
    storage.js      // load/save helpers
    books.js        // pure helpers: filterBooks, counts, etc. (optional but good)
```

## 3. Build order (this is the important part)

Beginners try to build everything at once and drown. Do it in this order. **Get each step working before starting the next.** Commit to git after each step if you're using git.

1. **Shell.** Vite app, router, `Layout`, four empty pages, nav links. Click around, confirm no console errors, 404 works.
2. **Data model + fake data.** In `App.jsx`, `useState` with 3 hardcoded books. No form, no storage yet.
3. **List.** `BookList` renders `BookCard` for each book. Hardcode nothing in `BookCard` — all via props. Check the `key` warning is gone.
4. **Filter tabs.** Status in the URL. Counts computed from `books` during render. No search yet.
5. **Search.** Query in the URL. Both filters combine. Empty state message.
6. **Add form.** On `/books`, a form above the list. Adds to state. Doesn't persist yet — refresh loses it, and that's fine for now.
7. **Delete.** Button on each card.
8. **Status change.** On the card or the detail page — your choice. Remember the rating rule.
9. **Detail page.** `/books/:id`, `useParams`, cast the id, find the book, render fields. Handle "id not found" (someone typed a bad URL).
10. **Persistence.** `localStorage` save on change, lazy-init load on mount.
11. **Polish.** Empty states, disabled submit when title is blank, loading nothing (no fetch here), keyboard-friendly. Optional: sort by `createdAt` desc.

Notice the order: **UI → data → interaction → persistence.** Beginners usually start with persistence and the form. Don't.

## 4. Self-review before you send it

Answer each of these honestly. If any answer is "no" or "I'm not sure", fix it before sending.

**State**
- [ ] Is `books` state in exactly one place (`App`)?
- [ ] Are `visibleBooks` and `counts` **computed during render**, not stored in state and not in a `useEffect`?
- [ ] Is there any `useEffect` at all? *(Correct answer for this project: probably zero or one, for `localStorage`. If you have three, you're deriving state — Lesson 5 §6.)*
- [ ] Do all updates use `prev => ...` and spread (`[...prev, x]`, `{ ...book, status }`)?
- [ ] Zero occurrences of `.push(`, `.splice(`, or `book.status = ` anywhere?

**Lists**
- [ ] Is `key` on the element returned by `.map()`, using `book.id`?
- [ ] Zero uses of the array index as `key`?

**Forms**
- [ ] `e.preventDefault()` in `onSubmit`?
- [ ] Inputs are controlled — `value` + `onChange` on every one?
- [ ] Rating is only editable when status is `finished`?

**Routing**
- [ ] `<BrowserRouter>` in `main.jsx` above everything?
- [ ] All internal navigation via `<Link>` / `<NavLink>` / `navigate()`, no `<a href>`?
- [ ] `id` from `useParams` cast with `Number()` (or compared as string consistently)?
- [ ] Filter and search in the URL — refresh keeps them?
- [ ] `*` route exists?

**Hygiene**
- [ ] Console is clean — no key warnings, no "setState on unmounted", no controlled/uncontrolled input warnings?
- [ ] No commented-out dead code left behind?
- [ ] Component names capitalized, files named consistently?

## 5. What to send me

Send all of:

1. **The code** — paste the files, or a GitHub repo link, or a CodeSandbox/StackBlitz link. Any of those is fine.
2. **The URL state** — what the address bar shows after: (a) clicking "Reading", (b) typing `tol` in search, (c) both.
3. **Console output** — paste it exactly, including warnings in yellow. Don't clean it up.
4. **A three-line honest report:**
    - What works.
    - What doesn't work (be specific: "clicking delete on the detail page deletes, but the page doesn't go anywhere" is useful; "it's broken" isn't).
    - What you're least sure about.

I'll review it the way I'd review a colleague's PR: things that are wrong, things that are risky, things that are good, and the one thing to fix first. Then we go to **Lesson 9 — testing and refactoring your own project** (yes, we refactor *your* code, not mine).
