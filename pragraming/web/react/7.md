## 1. Why not `<a href>`?

In a normal website, `<a href="/tasks">` makes the browser request a new HTML page from the server. In a React app, you have **one HTML page**. There is no `/tasks` file on the server. If you click that `<a>`, you get a 404, or the dev server serves the same page but **all your React state is wiped**.

React Router solves this:

- It intercepts clicks on special links (`<Link>`).
- It changes the URL using the browser's History API — **no page reload**.
- It reads the URL and decides which component to render.

The URL becomes **part of your app's state.** That's the mental model: routing is state management for the address bar.

## 3. The simplest possible router

`src/main.jsx`:

```jsx
import React from "react";
import ReactDOM from "react-dom/client";
import { BrowserRouter } from "react-router-dom";
import App from "./App";
import "./index.css";

ReactDOM.createRoot(document.getElementById("root")).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);
```

`BrowserRouter` must wrap everything that uses routing. **Common bug #1:** forgetting this, then getting `useRoutes() may be used only in the context of a <Router> component`.

`src/App.jsx`:

```jsx
import { Routes, Route, Link } from "react-router-dom";
import Home from "./pages/Home";
import Tasks from "./pages/Tasks";
import About from "./pages/About";

function App() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/tasks">Tasks</Link>
        <Link to="/about">About</Link>
      </nav>

      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/tasks" element={<Tasks />} />
        <Route path="/about" element={<About />} />
        <Route path="*" element={<p>Page not found (404)</p>} />
      </Routes>
    </div>
  );
}

export default App;
```

That's the whole core. `<Routes>` is a switch — it picks **one** matching `<Route>`. `<Route path="*" element={...}>` is the 404 fallback; always include it.

`<Link to="/tasks">` is the router's `<a>`. Always use it inside a React app. If you must use `<a>` (e.g. external URL), that's fine — but for internal navigation, `<Link>`.

## 4. `NavLink` — links that know they're active

`<NavLink>` adds an `active` class automatically.

```jsx
import { NavLink } from "react-router-dom";

<NavLink to="/tasks" className={({ isActive }) => isActive ? "active" : ""}>
  Tasks
</NavLink>
```

You'll use this for every nav menu you ever build. Style `.active` in CSS and you're done.

## 5. URL parameters — `useParams`

Routes can have **dynamic segments**:

```jsx
<Route path="/tasks/:id" element={<TaskDetails />} />
```

Now in `TaskDetails`:

```jsx
import { useParams } from "react-router-dom";

function TaskDetails() {
  const { id } = useParams();   // string! "5", not 5
  // fetch the task by id, or find it in a shared store
  return <h1>Task {id}</h1>;
}
```

Two things to internalize:

1. **`id` is a string.** Comparing `task.id === id` will be `false` if `task.id` is a number. Convert: `Number(id)`.
2. **If the URL changes (e.g. `/tasks/1` → `/tasks/2`), React reuses the same component.** If you fetch by id, put `id` in the effect's deps — otherwise you'll show the first task forever. This is the *one* time the effect deps rule genuinely matters:

```jsx
useEffect(() => {
  // fetch task by id
}, [id]);   // ← required
```

## 6. `useNavigate` — navigate from code

Sometimes you want to navigate after an action (e.g. after submitting a form):

```jsx
import { useNavigate } from "react-router-dom";

function NewTask() {
  const navigate = useNavigate();

  function handleSubmit(e) {
    e.preventDefault();
    // ... save it
    navigate("/tasks");   // or navigate(`/tasks/${newId}`)
  }
}
```

`navigate(-1)` goes back. `navigate("/tasks", { replace: true })` replaces the history entry instead of adding one — good for redirects after login.

## 7. Nested routes and layouts — `Outlet`

This is the feature that makes router code *clean*. Instead of repeating `<nav>` on every page:

```jsx
// App.jsx
import { Routes, Route, Outlet, Link } from "react-router-dom";

function Layout() {
  return (
    <div>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/tasks">Tasks</Link>
        <Link to="/tasks/new">New</Link>
      </nav>
      <Outlet />   {/* ← child routes render here */}
    </div>
  );
}

export default function App() {
  return (
    <Routes>
      <Route element={<Layout />}>
        <Route path="/" element={<Home />} />
        <Route path="/tasks" element={<Tasks />} />
        <Route path="/tasks/new" element={<NewTask />} />
        <Route path="/tasks/:id" element={<TaskDetails />} />
        <Route path="*" element={<NotFound />} />
      </Route>
    </Routes>
  );
}
```

The `<Route element={<Layout />}>` wrapper has **no `path`** — it's a *layout route*. Every child renders inside its `<Outlet />`. Change the nav once, it's everywhere.

## 8. Where does the URL go? Query strings — `useSearchParams`

For **filters**, query strings are better than params — they're shareable and optional:

```jsx
import { useSearchParams } from "react-router-dom";

function Tasks() {
  const [searchParams, setSearchParams] = useSearchParams();
  const filter = searchParams.get("filter") ?? "all";   // "all" | "active" | "done"

  function setFilter(next) {
    setSearchParams({ filter: next });
  }

  // ...use `filter` instead of useState
}
```

Notice the pattern: **the URL replaces `useState`** for the filter. Refresh the page → the filter is still there. Send the link to a friend → same view. That's why routing is state management.

**This is a direct upgrade to Lesson 6's tasks app.** Same UI, `filter` moves from `useState` to the URL. That's the exercise below.

## 9. Common pitfalls (all of them are real)

1. **Missing `<BrowserRouter>`** — everything breaks with a hook-context error.
2. **`<a href>` instead of `<Link>`** — page reload, state gone.
3. **`useParams` returns strings** — always cast.
4. **Forgetting `[id]` in the deps of a fetch-by-id effect** — shows stale task.
5. **No `path="*"` route** — navigating to a bad URL shows a blank page.
6. **Wrapping `<Routes>` in a component outside the `<BrowserRouter>`** in the tree — hooks lose context.
7. **Order of routes with overlapping paths** — React Router 6+ picks the most specific match, so you usually *don't* need to worry, but `/tasks/new` and `/tasks/:id` both matching `/tasks/new` is a classic — React Router prefers the static one, but if you're ever confused, check specificity.
8. **Using `window.location.href`** for navigation — reloads the app. Use `navigate()`.
9. **`<Route>` children must be `element={<X />}`** — not `component={X}` (that's the v5 API, still copied around a lot; if a tutorial says `component=`, it's out of date).
