# Lesson 3: Lists, keys, and rendering multiple items

## 1. The problem

So far you’ve written components by hand:

```jsx
<UserCard name="Ali" role="manager" age={35} />
<UserCard name="Sara" role="designer" age={17} />
```

That works for 2 items. It does **not** work for 50, or for data that comes from an API.  
In React, you almost never write repeated JSX — you **map over an array**.

## 2. `.map()` in JSX

You already know `.map()` from JavaScript. In JSX it returns an array of elements, and React renders each one.

```jsx
const users = [
  { id: 1, name: "Ali", role: "manager", age: 35 },
  { id: 2, name: "Sara", role: "designer", age: 17 },
  { id: 3, name: "Reza", role: "developer", age: 28 },
];

function App() {
  return (
    <div>
      {users.map((user) => (
        <UserCard
          key={user.id}
          name={user.name}
          role={user.role}
          age={user.age}
        />
      ))}
    </div>
  );
}
```

Notice:

- `{ }` lets us run JavaScript inside JSX.
- `.map()` returns an array of `<UserCard />` elements.
- We use **parentheses** after the arrow: `(user) => (` — not `{`. Curly braces would be a function body, not a return.

## 3. Keys — the most common beginner mistake

React needs a **`key`** for each item in a list. It uses keys to know which item is which when the list changes.

Rules:

1. `key` must be **unique among siblings**.
2. `key` must be a **stable** value — usually an `id` from your data.
3. **Do not use the array index** as a key if the list can reorder, filter, or change. Index keys cause subtle bugs (wrong item updating, input values jumping).
4. `key` is not a prop. You can’t read `props.key` inside the component.

Wrong:

```jsx
{users.map((user, index) => <UserCard key={index} ... />)}  // ❌ avoid
```

Right:

```jsx
{users.map((user) => <UserCard key={user.id} ... />)}      // ✅
```

## 4. Filtering and searching

Combining `.filter()` and `.map()` is the bread and butter of React lists.

```jsx
import { useState } from "react";

const users = [
  { id: 1, name: "Ali", role: "manager" },
  { id: 2, name: "Sara", role: "designer" },
  { id: 3, name: "Reza", role: "developer" },
];

function UserList() {
  const [search, setSearch] = useState("");

  const filtered = users.filter((user) =>
    user.name.toLowerCase().includes(search.toLowerCase())
  );

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search by name"
      />

      {filtered.length === 0 ? (
        <p>No users found.</p>
      ) : (
        <ul>
          {filtered.map((user) => (
            <li key={user.id}>
              {user.name} — {user.role}
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}

export default UserList;
```

Key idea: **don’t modify `users`**. Compute a new array with `.filter()`. React state and props should be treated as read-only.

## 5. Rendering rules to remember

| Situation | How |
|---|---|
| Render array | `{arr.map(item => <X key={item.id} />)}` |
| Show one of two things | `{cond ? <A /> : <B />}` |
| Show or hide | `{cond && <A />}` |
| Empty state | `{arr.length === 0 ? <Empty /> : arr.map(...)}` |
| Nothing to render | return `null` |

Also:

- `false`, `null`, `undefined` render **nothing** in JSX — safe.
- `0` renders as `0` — a classic bug. Use `arr.length > 0 && ...` or a ternary.

## 6. Common pitfalls

1. Forgetting `key` → React warns in the console.
2. Using index as key → bugs when items move.
3. Forgetting `return` inside `.map()` with curly braces:
   ```jsx
   users.map((u) => { <UserCard /> })   // ❌ returns undefined
   users.map((u) => <UserCard />)       // ✅ implicit return
   ```
4. Mutating the array: `users.push(...)`, `users.sort(...)` — don’t. Use `.filter`, `.map`, `.slice`, or a copy.
