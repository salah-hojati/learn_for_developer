در React، هر دو Hook یعنی `useMemo` و `useCallback` برای **بهینه‌سازی Performance و جلوگیری از محاسبات یا ایجاد Referenceهای غیرضروری در هر Render** استفاده می‌شوند؛ اما تفاوت اصلی آن‌ها در چیزی است که ذخیره می‌کنند.

- `useMemo`: نتیجه اجرای یک تابع را ذخیره می‌کند (Memoize a Value).
- `useCallback`: خود تابع را ذخیره می‌کند (Memoize a Function).

## **1. useMemo چیست؟**

فرض کن یک کامپوننت داری که محاسبه‌ای نسبتاً سنگین انجام می‌دهد. نمی‌خواهی با هر Render دوباره این محاسبه انجام شود.

مثال:

```
import { useMemo, useState } from "react";

function ProductList({ products }) {
    const [count, setCount] = useState(0);

    const expensiveResult = useMemo(() => {
        console.log("Calculating...");

        return products.filter(
            product => product.price > 100
        );
    }, [products]);

    return (
        <div>
            <p>Count: {count}</p>

            <button onClick={() => setCount(count + 1)}>
                Increase
            </button>

            {expensiveResult.map(product => (
                <p key={product.id}>{product.name}</p>
            ))}
        </div>
    );
}
```

**چه اتفاقی می‌افتد؟**

- در اولین Render، تابع اجرا و نتیجه ذخیره می‌شود.
- اگر `count` تغییر کند، کامپوننت دوباره Render می‌شود؛ اما محاسبه مجدداً انجام نمی‌شود.
- اگر `products` تغییر کند، محاسبه دوباره اجرا می‌شود.

بنابراین `useMemo` برای جلوگیری از محاسبات تکراری و گران‌قیمت کاربرد دارد.

## **2. useCallback چیست؟**

فرض کن یک تابع را به یک Child Component ارسال می‌کنی.

در JavaScript، با هر Render یک Function جدید ساخته می‌شود. حتی اگر کد تابع تغییری نکرده باشد، Reference آن متفاوت است.

مثال:

```
import { useState, useCallback, memo } from "react";

const Child = memo(({ onClick }) => {
    console.log("Child Rendered");

    return (
        <button onClick={onClick}>
            Click Me
        </button>
    );
});

function Parent() {
    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {
        console.log("Button Clicked");
    }, []);

    return (
        <div>
            <p>{count}</p>

            <button onClick={() => setCount(count + 1)}>
                Increase
            </button>

            <Child onClick={handleClick} />
        </div>
    );
}
```

**چه اتفاقی می‌افتد؟**

بدون `useCallback`:

- با هر Render تابع جدیدی ساخته می‌شود.
- Reference تابع تغییر می‌کند.
- React.memo تصور می‌کند Prop تغییر کرده است.
- Child مجدداً Render می‌شود.

با `useCallback`:

- Reference تابع ثابت می‌ماند.
- تا زمانی که Dependencyها تغییر نکنند، همان تابع قبلی استفاده می‌شود.
- در نتیجه Child غیرضروری Render نمی‌شود.

## **3. تفاوت اصلی useMemo و useCallback**

| ویژگی                    | useMemo                   | useCallback                   |
| ------------------------ | ------------------------- | ----------------------------- |
| چه چیزی را ذخیره می‌کند؟ | مقدار (Value)             | تابع (Function)               |
| هدف                      | جلوگیری از محاسبات تکراری | ثابت نگه‌داشتن Reference تابع |
| خروجی                    | نتیجه اجرای تابع          | خود تابع                      |
| کاربرد رایج              | محاسبات سنگین             | ارسال Callback به Child       |
| Dependency Array         | دارد                      | دارد                          |

از نظر مفهومی:

```
// useMemo
const value = useMemo(() => {
    return calculateSomething();
}, [dependency]);

// useCallback
const callback = useCallback(() => {
    doSomething();
}, [dependency]);
```

نکته جالب اینکه:

```
useCallback(fn, dependencies);
```

تقریباً معادل این است:

```
useMemo(() => fn, dependencies);
```

## **4. چه زمانی از هر کدام استفاده می‌کنم؟**

### **استفاده از useMemo**

زمانی که:

1. محاسبات سنگین و پرهزینه داریم.
2. عملیات Filter، Sort یا Transform روی آرایه‌های بزرگ انجام می‌دهیم.
3. می‌خواهیم Reference یک Object یا Array در Renderهای مختلف ثابت بماند.
4. یک مقدار Memoized را به کامپوننتی که با React.memo بهینه شده ارسال می‌کنیم.

مثال:

```
const sortedUsers = useMemo(() => {
    return [...users].sort(
        (a, b) => a.name.localeCompare(b.name)
    );
}, [users]);
```

### **استفاده از useCallback**

زمانی که:

1. تابعی را به Child Component ارسال می‌کنیم.
2. Child با React.memo بهینه شده است.
3. تابع به‌عنوان Dependency در Hookهای دیگر استفاده می‌شود.
4. می‌خواهیم Reference یک تابع بین Renderها ثابت بماند.

مثال:

```
const handleDelete = useCallback((id) => {
    deleteUser(id);
}, [deleteUser]);
```

## **5. نکته مهم در مصاحبه: Dependency Array**

یکی از اشتباهات رایج، مدیریت نادرست Dependencyها است.

مثلاً:

```
const [count, setCount] = useState(0);

const increment = useCallback(() => {
    setCount(count + 1);
}, []);
```

این کد مشکل دارد؛ چون تابع مقدار قدیمی `count` را نگه می‌دارد. به این مشکل Stale Closure می‌گویند.

راه‌حل اول:

```
const increment = useCallback(() => {
    setCount(count + 1);
}, [count]);
```

راه‌حل دوم، استفاده از Functional Update:

```
const increment = useCallback(() => {
    setCount(prev => prev + 1);
}, []);
```

در روش دوم نیازی به قرار دادن `count` در Dependency Array نیست.

## **6. آیا همیشه باید از useMemo و useCallback استفاده کنیم؟**

خیر!

این نکته برای یک Developer حرفه‌ای بسیار مهم است.

استفاده بیش‌ازحد از این Hookها خودش هزینه دارد:

- مصرف حافظه برای نگهداری مقادیر Memoized
- بررسی Dependencyها
- افزایش پیچیدگی کد
- سخت‌تر شدن نگهداری و Debug کردن

بنابراین ابتدا Performance را اندازه‌گیری می‌کنم و فقط در صورت نیاز از Memoization استفاده می‌کنم.

همچنین در نسخه‌های جدید React، React Compiler می‌تواند بسیاری از Memoizationهای دستی را به‌صورت خودکار انجام دهد؛ بنابراین بسته به تنظیمات پروژه، نیاز به استفاده دستی از این Hookها کمتر می‌شود.

## **7. پاسخ پیشنهادی برای مصاحبه Senior React Developer**

اگر در مصاحبه از من بپرسند تفاوت `useMemo` و `useCallback` چیست، این‌طور پاسخ می‌دهم:

> Both useMemo and useCallback are React performance optimization hooks.
>
> useMemo memoizes the result of an expensive computation, while useCallback memoizes a function reference.
>
> I use useMemo when I have expensive calculations, such as filtering or sorting large datasets.
>
> I use useCallback when passing functions to memoized child components using React.memo, to prevent unnecessary re-renders caused by changing function references.
>
> However, I don't use them everywhere because memoization also has its own overhead. I use them when performance profiling indicates that they are beneficial.

**نکته طلایی مصاحبه:**

این سه مفهوم را در کنار هم به‌خوبی یاد بگیر:

- `React.memo` → جلوگیری از Render غیرضروری یک Component.
- `useMemo` → جلوگیری از محاسبه مجدد یک Value.
- `useCallback` → جلوگیری از تغییر غیرضروری Reference یک Function.

این سه ابزار در کنار هم یکی از مباحث مهم Performance Optimization در React هستند.
