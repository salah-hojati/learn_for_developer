تفاوت اصلی در **زمان اجرای مجدد افکت** است. آرایه وابستگی (dependency array) به React می‌گوید که افکت شما به کدام مقادیر وابسته است و چه زمانی باید دوباره اجرا شود. وقتی این آرایه را حذف می‌کنید، این کنترل را از React می‌گیرید.

### 🆚 مقایسه مستقیم

| ویژگی | بدون آرایه وابستگی | با آرایه خالی `[]` |
| :--- | :--- | :--- |
| **زمان اجرا** | بعد از **هر** رندر (mount و هر update) | **فقط یک بار** بعد از اولین mount |
| **رفتار مشابه** | ترکیب `componentDidMount` و `componentDidUpdate` | فقط `componentDidMount` |
| **اجرای Cleanup** | قبل از هر اجرای مجدد افکت و در زمان unmount | فقط در زمان unmount |
| **خطر اصلی** | ری‌رندرهای بی‌نهایت در صورت تغییر state | — |

---

### 📌 بدون آرایه وابستگی (`useEffect(() => { ... })`)
وقتی آرایه را حذف می‌کنید، React هیچ راهی ندارد که بفهمد افکت شما به چه چیزی وابسته است. بنابراین، برای اطمینان از همگام‌سازی مداوم، **افکت را بعد از هر بار رندر شدن کامپوننت اجرا می‌کند**.

این رفتار زمانی مفید است که واقعاً می‌خواهید بعد از هر تغییر در DOM کاری انجام شود. اما خطر بزرگی هم دارد: اگر داخل افکت، state ای را تغییر دهید که باعث رندر مجدد شود، یک **حلقه بی‌نهایت** ایجاد می‌شود， زیرا هر رندر افکت را دوباره اجرا می‌کند و افکت هم دوباره state را تغییر می‌دهد.

### 📌 با آرایه خالی (`useEffect(() => { ... }, [])`)
آرایه خالی `[]` به React می‌گوید: «این افکت به **هیچ** مقدار واکنش‌گرایی (props یا state) وابسته نیست.» در نتیجه، React آن را **فقط یک بار**، بلافاصله بعد از اینکه کامپوننت برای اولین بار در صفحه ظاهر شد (mount)، اجرا می‌کند و دیگر در آپدیت‌های بعدی سراغش نمی‌رود.

این الگو معمولاً برای کارهای یک‌بارمصرف مثل **واکشی اولیه داده (initial data fetch)**، تنظیم یک شنونده رویداد (event listener) یا اتصال به یک سرویس خارجی استفاده می‌شود.

### 🧹 تفاوت در تابع Cleanup
این تفاوت در نحوه اجرای تابع cleanup (اگر از افکت return کنید) هم نمود پیدا می‌کند:
- **بدون آرایه**: تابع cleanup **قبل از هر اجرای مجدد افکت** (یعنی قبل از هر رندر بعدی) و همچنین در زمان unmount اجرا می‌شود. این یعنی افکت قبلی قبل از اجرای افکت جدید، پاک‌سازی می‌شود.
- **با آرایه خالی**: تابع cleanup **فقط یک بار**، آن هم دقیقاً زمانی که کامپوننت از صفحه حذف می‌شود (unmount)، اجرا می‌شود.

### 💡 نکته‌ای درباره StrictMode در توسعه
اگر در حالت توسعه (development) از `React.StrictMode` استفاده می‌کنید، ممکن است ببینید که افکتِ دارای آرایه خالی `[]` **دو بار** اجرا می‌شود. این یک باگ نیست؛ React این کار را عمداً برای کمک به پیدا کردن مشکلات مربوط به cleanup انجام می‌دهد. در نسخه production این اتفاق نمی‌افتد.

### 💎 جمع‌بندی
- اگر می‌خواهید کدی **فقط یک بار** در طول عمر کامپوننت اجرا شود (مثل واکشی اولیه)، از **`[]`** استفاده کنید.
- اگر می‌خواهید کدی **بعد از هر تغییر در رابط کاربری** همگام شود و مطمئن هستید که باعث حلقه بی‌نهایت نمی‌شود، آرایه را **حذف** کنید.
