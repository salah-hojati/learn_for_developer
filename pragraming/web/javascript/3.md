# Level 3 — Intermediate JavaScript

Async is where JavaScript stops being a toy language and becomes genuinely powerful. Everything in the browser (network requests, timers, user input, file reads) is **asynchronous** — the code runs *later*, not immediately. This level teaches you to control that flow cleanly.

---

## 1. Why async exists — the single-threaded model

JavaScript runs on **one thread**. It can only execute one instruction at a time. So how does it do network requests without freezing the page?

It doesn't wait. It **schedules** the work and moves on.

```js
console.log("A");
setTimeout(() => console.log("B"), 1000);
console.log("C");

// Output: A → C → B
```

`setTimeout` returns immediately; the callback runs after 1 second. The browser's event loop handles that. (Level 4 covers the event loop in depth — for now, accept it.)

**Problem:** if the timing of an async result matters, you need a way to *wait* for it. Enter Promises.

---

## 2. Promises

A **Promise** is an object representing a value that will exist *later*. It is in one of three states:

- **pending** — the work is in progress
- **fulfilled** — succeeded, with a value
- **rejected** — failed, with a reason (error)

```js
const promise = new Promise((resolve, reject) => {
  const success = true;
  setTimeout(() => {
    if (success) resolve("done!");   // → fulfilled
    else reject(new Error("failed")); // → rejected
  }, 1000);
});
```

You **consume** a promise with `.then()` / `.catch()` / `.finally()`:

```js
promise
  .then(value => console.log("Success:", value))   // "Success: done!"
  .catch(err => console.error("Error:", err))
  .finally(() => console.log("Runs either way"));
```

**Promise chaining** — each `.then` returns a new promise, so you can chain:

```js
fetch("/api/user/1")
  .then(res => res.json())
  .then(user => fetch(`/api/posts/${user.id}`))
  .then(res => res.json())
  .then(posts => console.log(posts))
  .catch(err => console.error("Something broke:", err));
```

That works — but it gets ugly fast. That's what `async/await` solves.

---

## 3. `async` / `await` ⭐

**`async/await` is syntax sugar over promises.** It lets you write asynchronous code that *looks* synchronous — far more readable.

Two keywords:

- **`async`** before a function → the function always returns a Promise.
- **`await`** inside an async function → pauses the function until the promise settles, then returns the value.

```js
async function loadUser() {
  try {
    const res  = await fetch("/api/user/1");   // wait for response
    const user = await res.json();             // wait for parse
    console.log(user);
    return user;
  } catch (err) {
    console.error("Failed:", err);
  }
}

loadUser(); // returns a Promise
```

**The same thing in `.then` form** — notice the difference in readability:

```js
function loadUserThen() {
  return fetch("/api/user/1")
    .then(res => res.json())
    .then(user => console.log(user))
    .catch(err => console.error("Failed:", err));
}
```

**Key facts to internalize:**

1. `await` only works **inside an `async` function**.
2. An `async` function **always returns a Promise**, even if you `return 42`.
3. An error thrown inside an async function becomes a **rejected promise** — catch it with `try/catch` (cleaner than `.catch`).
4. `await` **pauses only the current function**, not the whole program.

## 4. `fetch` — talking to APIs

`fetch` is the built-in way to make HTTP requests. It returns a **Promise**.

```js
async function getData() {
  const response = await fetch("https://api.example.com/data");

  // fetch does NOT reject on 404/500 — you must check yourself!
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }

  return await response.json(); // also .text(), .blob()
}
```

**Two traps to know:**

1. **`fetch` only rejects on network failure** (no internet, DNS error). A 404 or 500 response is still "successful" at the fetch level — check `response.ok`.
2. **`response.json()` is itself async** — you must `await` it.

### POST request

```js
async function createUser(data) {
  const response = await fetch("/api/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  });

  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return await response.json();
}
```

### Running requests in parallel

Don't `await` one at a time if they're independent — run them together:

```js
// ❌ slow — sequential
const a = await fetch("/a").then(r => r.json());
const b = await fetch("/b").then(r => r.json());

// ✅ fast — parallel
const [a, b] = await Promise.all([
  fetch("/a").then(r => r.json()),
  fetch("/b").then(r => r.json()),
]);
```

**Other combinators:**

```js
Promise.all([p1, p2]);        // fails fast on first rejection
Promise.allSettled([p1, p2]); // waits for all, reports each outcome
Promise.race([p1, p2]);       // first to settle wins (fulfil OR reject)
Promise.any([p1, p2]);        // first to fulfil wins, ignores rejections
```

## 5. Error handling

Three mechanisms, used together:

```js
try {
  // code that might throw
  const data = await riskyOperation();
  console.log(data);
} catch (err) {
  // runs if anything above throws or rejects
  console.error("Caught:", err.message);
} finally {
  // always runs — cleanup goes here
  console.log("done");
}
```

**Throwing your own errors:**

```js
function divide(a, b) {
  if (b === 0) throw new Error("Division by zero");
  return a / b;
}
```

**Error object basics:**

```js
const err = new Error("Something went wrong");
err.message; // "Something went wrong"
err.name;    // "Error"
```

**Custom error classes** (Level 4, but a taste):

```js
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}
```

**Rule of thumb:** catch errors where you can *do something* about them (log, retry, show a message). Don't swallow them silently.

## 6. JSON

**JSON** is a text format for exchanging data. Almost every API speaks it.

```js
// Object → JSON string
const user = { name: "Sam", age: 25 };
const json = JSON.stringify(user);  // '{"name":"Sam","age":25}'

// JSON string → object
const parsed = JSON.parse(json);    // { name: "Sam", age: 25 }
```

**What JSON supports:** strings, numbers, booleans, `null`, arrays, objects.
**What it does not:** functions, `undefined`, `Date` (becomes a string), `Map`, `Set`.

Pretty-print with a third argument:

```js
JSON.stringify(user, null, 2); // indented 2 spaces
```

## 7. Modules

Modern JS splits code into files that import and export from each other.

```js
// math.js — named exports
export const add = (a, b) => a + b;
export const PI = 3.14159;

// or export a whole function
export function multiply(a, b) { return a * b; }

// default export — one per file
export default function logger(msg) { console.log(msg); }
```

```js
// app.js — importing
import logger, { add, PI, multiply } from "./math.js"; // default + named
import * as math from "./math.js";                     // namespace → math.add(...)
```

**Rules:**

- Use `type="module"` in the HTML: `<script type="module" src="app.js"></script>`
- Paths need `./` or `../` for local files (or full URLs / package names).
- Modules are **singletons** and **strict mode by default**.
- Top-level `await` is allowed in modules (modern browsers/Node).

## 8. `localStorage` & `sessionStorage`

Browser key-value storage. Values are **always strings**, so JSON is your friend.

```js
// Save
localStorage.setItem("user", JSON.stringify({ name: "Sam" }));

// Read
const user = JSON.parse(localStorage.getItem("user"));

// Remove / clear
localStorage.removeItem("user");
localStorage.clear();
```

**Differences:**

| | `localStorage` | `sessionStorage` |
|---|---|---|
| Lifetime | Until deleted | Until tab closes |
| Scope | All tabs, same origin | Single tab |
| Size | ~5–10 MB | ~5 MB |

Both are **synchronous** and **block the main thread** — fine for small data, never for large blobs.

## 🧩 Putting it together — a tiny working example

```js
// Fetch a random user, show it, cache it
async function showRandomUser() {
  const cacheKey = "randomUser";

  // 1. Try cache first
  const cached = localStorage.getItem(cacheKey);
  if (cached) {
    render(JSON.parse(cached));
    return;
  }

  // 2. Otherwise fetch
  try {
    const res = await fetch("https://randomuser.me/api/");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);

    const { results } = await res.json();
    const user = results[0];

    localStorage.setItem(cacheKey, JSON.stringify(user));
    render(user);
  } catch (err) {
    console.error("Failed to load user:", err);
    document.querySelector("#output").textContent = "Could not load user.";
  }
}

function render(user) {
  document.querySelector("#output").textContent =
    `${user.name.first} ${user.name.last}`;
}

showRandomUser();
```
