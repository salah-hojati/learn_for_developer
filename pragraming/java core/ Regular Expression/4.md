# 🎓 جلسه ۴ — گروه‌ها، Backreference ها و Performance

> ⚠️ **توجه:** تمرین‌های جلسهٔ ۳ رو نفرستادی. اگه دوست داری، بعد از این جلسه بفرست — ولی برای اینکه عقب نیفتی، بریم جلسهٔ ۴. اگه جایی از جلسهٔ ۳ گیج شدی، بگو تا برگردیم.

این جلسه دو تا موضوع داره که **کاملاً متفاوت** به نظر می‌رسن ولی در واقع به هم وصلن:
1. **گروه‌ها** — برای استخراج و جایگزینی هوشمند
2. **Performance و backtracking** — چرا بعضی regex ها سرور رو می‌کشن 💀

---

## ۴.۱ گروه‌های شماره‌دار — یادآوری سریع

هر `(...)` یه گروه می‌سازه که از ۱ شماره‌گذاری می‌شه:

```java
Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("2024-03-15");
if (m.matches()) {
    System.out.println(m.group(1));  // 2024
    System.out.println(m.group(2));  // 03
    System.out.println(m.group(3));  // 15
    System.out.println(m.group(0));  // 2024-03-15 ← کل match
}
```

## ۴.۲ گروه‌های نام‌دار — `(?<name>...)`

وقتی گروه‌ها زیاد می‌شن، شماره‌ها گیج‌کننده می‌شن. **گروه نام‌دار** بخونایی کد رو نجات می‌ده:

```java
String regex = "(?<year>\\d{4})-(?<month>\\d{2})-(?<day>\\d{2})";
Matcher m = Pattern.compile(regex).matcher("2024-03-15");
if (m.matches()) {
    System.out.println(m.group("year"));   // 2024
    System.out.println(m.group("month"));  // 03
    System.out.println(m.group("day"));    // 15
}
```

### ⚠️ نکتهٔ حیاتی: فقط حروف و رقم، بدون خط تیره

نام گروه باید با **حرف** شروع بشه و فقط `[A-Za-z0-9]` داشته باشه. `(?<my-name>...)` **کار نمی‌کنه**، `(?<myName>...)` درسته.

### پسوند جاوا (اختصاصی): `(?<name>...)` = `(?<name>...)`

جاوا یه نحو جایگزین هم داره که استاندارد نیست:
```java
"(?<year>\\d{4})"   // استاندارد
"(?'year'\\d{4})"   // فقط در بعضی زبان‌ها، در جاوا هم کار می‌کنه ولی توصیه نمی‌شه
```

فقط از `(?<name>...)` استفاده کن.

### گروه بدون شمارش — `(?:...)`

اگه فقط برای گروه‌بندی می‌خوای گروه بسازی و نمی‌خوای به شمارش اضافه بشه:

```java
// می‌خوای "cat" یا "dog" رو گروه‌بندی کنی ولی شماره‌گذاری رو به‌هم نزنی
"^(?:cat|dog)s?$"   
// match: cat, cats, dog, dogs — بدون گروه اضافی
```

تفاوت:
```java
"(cat|dog)"    // گروه ۱ = cat یا dog
"(?:cat|dog)"  // گروه‌بندی ولی بدون شماره
```

### گروه اتمیک — `(?>...)` (جلسهٔ بعد بیشتر ولی اینجا فقط معرفی)

```java
"(?>abc)"   // گروه اتمیک — بدون backtracking داخل گروه
```

## ۴.۳ Backreference ها — `\1`, `\2`, `\k<name>`

**Backreference یعنی «دقیقاً همون چیزی که قبلاً match شده»** — نه یک الگوی مشابه، بلکه خودِ همون متن.

```java
// تشخیص حرف تکراری پشت‌سرهم: aa, bb, ... ولی نه ab
"(.)\\1"       // هر کاراکتری، بعد همون کاراکتر دوباره

// سه‌بار تکرار: aaa, bbb
"(.)\\1{2}"

// چهار رقم تکراری (مثل 0000 یا 1111)
"(\\d)\\1{3}"
```

### کاربرد در اعتبارسنجی واقعی: کد پستی بدون ۴ رقم تکراری پشت‌سرهم

```java
"^(?!.*(\\d)\\1{3})\\d{10}$"
```
این می‌گه: «۱۰ رقم، به شرطی که هیچ‌جا ۴ رقم تکراری پشت‌سرهم نباشه»:
- `1234567890` ✅
- `1000012345` ❌ (چهار صفر پشت‌سرهم)

### Backreference به گروه نام‌دار: `\k<name>`

```java
// match: "abcabc" ولی نه "abcdef"
"(?<word>[a-z]+)\\k<word>"
```

### ⚠️ تلهٔ کلاسیک: Backreference در Java باید escape بشه

```java
"(.)\\1"        // درست (backslash دو تا)
"(.)\1"         // غلط! کامپایل می‌شه ولی معنی octal escape می‌ده
```

### Backreference در Replacement: `$1`, `$2`, `${name}`

اینجا جای دیگه‌ای از regex-land هستیم — **در `replaceAll` و `appendReplacement`**:

```java
// جابجایی اسم و فامیل
"ali rezaei".replaceAll("(\\w+)\\s+(\\w+)", "$2, $1");
// نتیجه: "rezaei, ali"

// با گروه نام‌دار
"2024-03-15".replaceAll(
    "(?<y>\\d{4})-(?<m>\\d{2})-(?<d>\\d{2})",
    "${d}/${m}/${y}"
);
// نتیجه: "15/03/2024"
```

⚠️ بین `$1` و `${name}` فرق هست: `$1` **در جاوا** همیشه باید با `${...}` یا `$N` و بعدش کاراکتر غیر رقم نوشته بشه، وگرنه `$12` رو «گروه ۱۲» می‌خونه نه «گروه ۱ + ۲». پس:
```java
"abc".replaceAll("(\\w)", "$10");    // خطا یا رفتار عجیب
"abc".replaceAll("(\\w)", "${1}0");  // درست: "a0b0c0"
```

## ۴.۴ `appendReplacement` و `appendTail` — جایگزینی هوشمند

`replaceAll` ساده‌ست، ولی وقتی می‌خوای **روی هر match محاسبه انجام بدی**، این دو متد لازم می‌شن:

```java
// مثال: هر عدد رو دو برابر کن
String input = "قیمت ۱۰۰ و ۲۰۰ و ۳۰۰";
Pattern p = Pattern.compile("\\d+");
Matcher m = p.matcher(input);
StringBuilder sb = new StringBuilder();

while (m.find()) {
    int doubled = Integer.parseInt(m.group()) * 2;
    m.appendReplacement(sb, String.valueOf(doubled));
}
m.appendTail(sb);

System.out.println(sb);  // قیمت ۲۰۰ و ۴۰۰ و ۶۰۰
```

### چرا این بهتر از `replaceAll` هست؟
- `replaceAll` فقط یه string replacement قبول می‌کنه
- `appendReplacement` اجازه می‌ده **مقدار رو از `Matcher` استخراج و محاسبه کنی**

### ⚠️ تله: `$` و `\` در replacement

داخل replacement، `$` و `\` کاراکتر خاصن. اگه می‌خوای عیناً چاپ بشن، باید escape بشن:

```java
m.appendReplacement(sb, "\\$" + m.group());  // دش $ قبلش
```

یا بهتر:
```java
m.appendReplacement(sb, Matcher.quoteReplacement("$" + m.group()));
```

**قانون:** همیشه وقتی مقدارت ممکنه `$` یا `\` داشته باشه، از `Matcher.quoteReplacement(...)` استفاده کن.

## ۴.۵ سه نوع کوانتیفایر — Greedy / Lazy / Possessive

دوباره یادآوری، ولی این بار می‌خوام **تفاوت عملی** شون رو نشون بدم:

```java
String s = "<a><b>";

// Greedy (پیش‌فرض) → بیشترین
"<.+>".matcher       → match: "<a><b>"

// Lazy → کمترین
"<.+?>".matcher      → match: "<a>"، بعد "<b>"

// Possessive → مثل greedy ولی بدون عقب‌گرد
"<.++>".matcher      → match: "<a><b>" (بدون backtracking، سریع‌تر)
```

**تفاوت Greedy و Possessive کجا معلوم می‌شه؟**

```java
// هدف: <a>abc</a>
"<.+>".matches("<a>abc</a>")    // ✅ true (greedy، backtrack می‌کنه)
"<.++>".matches("<a>abc</a>")   // ❌ false (possessive، اول همه رو می‌خوره، بعد عقب نمی‌ره)
```

پس **possessive می‌تونه منجر به شکست بشه** که greedy موفق می‌شد. ولی به قیمت **سرعت خیلی بیشتر و امنیت در برابر backtracking**.

**قانون انتخاب:**
- برای اعتبارسنجی ساده (کل رشته = الگو): هر سه کار می‌کنن
- برای extraction: معمولاً lazy
- برای performance-critical با رشتهٔ طولانی: possessive اگه امکانش هست
- برای جلوگیری از catastrophic backtracking: possessive یا atomic

---

## ۴.۶ 💀 Catastrophic Backtracking — چرا بعضی regex ها سرور رو می‌کشن

این بخش رو **جدی بگیر**. این یه حملهٔ واقعی (ReDoS) هست که سایت‌های بزرگ رو down کرده.

### الگوی خطرناک:

```java
"^(a+)+$".matches("aaaaaaaaaaaaaaaaaaaaaaaaaaaaX")
```

این چه کار می‌کنه؟
- `a+` اولین بار همه رو می‌خوره → به X می‌رسه → شکست
- backtrack: یه `a` رو پس می‌ده، `a+` دوم رو امتحان می‌کنه → شکست
- **یعنی برای n تا `a`، حدود 2^n حالت امتحان می‌شه**

برای ۳۰ تا `a`، ۱ میلیارد حالت. برای ۴۰ تا، سرور می‌مره. **این یه حملهٔ DoS کاملاً واقعیه.**

### چرا؟

**کوانتیفایر تودرتو** با همون کاراکتر: `(a+)+` یا `(a*)*` یا `(\d+)+` روی رشته‌ای که match نمی‌شه.

### سه راه‌حل:

**۱. Possessive:**
```java
"^(a++)+$"   // سریع، بدون backtracking
```

**۲. Atomic group:**
```java
"^(?>a+)+$"  // همون کار
```

**۳. بازنویسی الگو** (بهترین راه):
```java
"^a+$"       // این اصلاً کوانتیفایر تودرتو نداره!
```

### مثال واقعی از اعتبارسنجی ایمیل:

```java
// 💀 خطرناک
"^([a-zA-Z0-9]+)*@..."       // (X+)* = فاجعه

// ✅ امن
"^[a-zA-Z0-9]+@..."
```

**قانون طلایی:** هیچ‌وقت `(X+)+` یا `(X*)*` ننویس. اگه یه `+` یا `*` داخل گروهه و بیرون گروه هم `+` یا `*` هست، ۹۹٪ باگه.

### پسورد قوی — چرا امن هست؟

```java
"^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d).{8,20}$"
```

چرا این catastrophe نمی‌شه؟
- `.{8,20}` محدوده (نه `*` بی‌نهایت)
- `(?=.*...)` ها هم‌پوشانی ندارن (هر کدوم مستقل از هم نگاه می‌کنن)
- طول رشته محدوده

⚠️ ولی این **خطرناک** هست:
```java
"^(.*[a-z].*[A-Z].*\\d.*)$"   // می‌تونه روی رشتهٔ طولانی کند شه
```

### ابزار تست: **regex101.com** یا **regexr.com**

هر دو یه بخش «debugger» دارن که می‌گن چند تا step انجام شده. اگه روی یه ورودی بد عدد انفجاری دیدی، الگو مشکل داره.

## ۴.۷ Performance در جاوا — ۵ قاعدهٔ طلایی

### قاعده ۱: `Pattern` رو **یک بار** کامپایل کن و کش کن

```java
// ❌ بد — داخل حلقه Pattern هر بار کامپایل می‌شه
for (String s : list) {
    if (s.matches("^\\d+$")) { ... }   // کُنده!
}

// ✅ خوب — یک بار کامپایل
private static final Pattern PHONE = Pattern.compile("^09\\d{9}$");
for (String s : list) {
    if (PHONE.matcher(s).matches()) { ... }
}
```

`String.matches()` همون `Pattern.compile().matcher().matches()` هست، **هر بار** کامپایل می‌کنه. برای اعتبارسنجی در حلقه یا endpoint، **همیشه** `Pattern` استاتیک.

### قاعده ۲: `Pattern` immutable و thread-safe است — بذار `static final`

```java
public class Validators {
    private static final Pattern EMAIL = Pattern.compile("^[A-Za-z0-9._-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$");
    private static final Pattern PHONE = Pattern.compile("^09\\d{9}$");
    
    public static boolean isEmail(String s) { return EMAIL.matcher(s).matches(); }
    public static boolean isPhone(String s) { return PHONE.matcher(s).matches(); }
}
```

`Matcher` **thread-safe نیست** — پس `Matcher` رو local بساز، `Pattern` رو static بذار.

### قاعده ۳: از `find()` استفاده کن نه `matches()` وقتی دنبال زیررشته‌ای

```java
// ❌ بد
"^.*\\d+.*$".matcher("abc123").matches()

// ✅ خوب
"\\d+".matcher("abc123").find()
```
دومی هم سریع‌تره هم خواناتر.

### قاعده ۴: از `^` و `$` وقتی `matches()` استفاده می‌کنی می‌تونی صرف‌نظر کنی

```java
"\\d{8}".matcher("12345678").matches()   // true
"^\\d{8}$".matcher("12345678").matches() // true — ولی ~۵٪ کندتر (کم، ولی در حلقه مهم)
```

البته من **همیشه** پیشنهاد می‌کنم `^$` بذار — خوانایی مهم‌تره از ۵٪ micro-optimization، مگه اینکه bottleneck واقعی باشه.

### قاعده ۵: `Pattern.LITERAL` برای رشته‌های literal

```java
// وقتی کاربر ورودی می‌ده که "regex نیست" — مثلاً جستجوی ساده
Pattern.compile(Pattern.quote(userInput))   // امن
Pattern.compile(userInput, Pattern.LITERAL) // حتی بهتر
```
وگرنه اگه کاربر `.*` تایپ کنه، همه‌چیز رو match می‌کنه — **یه باگ امنیتی**.

## ۴.۸ 📌 چیت‌شیت نهایی جلسه

| چی می‌خوای | نحو |
|-----------|-----|
| گروه شماره‌دار | `(...)` → `$1` یا `group(1)` |
| گروه نام‌دار | `(?<name>...)` → `${name}` یا `group("name")` |
| گروه بدون شمارش | `(?:...)` |
| گروه اتمیک (بدون backtracking) | `(?>...)` |
| Backreference در الگو | `\1`، `\k<name>` |
| Backreference در replacement | `$1`، `${name}` |
| Possessive quantifier | `*+`، `++`، `?+`، `{n,m}+` |
| escape رشتهٔ replacement | `Matcher.quoteReplacement(s)` |
| escape رشته در regex | `Pattern.quote(s)` |

## 📝 تمرین‌های جلسه ۴ (۷ تا)

### تمرین ۱ — گروه‌های نام‌دار
یه الگو برای `YYYY-MM-DD` با گروه‌های نام‌دار بنویس. از ورودی تاریخ بگیر و چاپ کن: `روز: 15، ماه: 03، سال: 2024`.

### تمرین ۲ — Backreference
الگویی بنویس که کلمات **تکراری پشت‌سرهم** رو تشخیص بده:
```
"hello hello world"       → match: "hello hello"
"the the cat and and dog" → match: "the the" و "and and"
```
**راهنما:** `\b(\w+)\s+\1\b`

### تمرین ۳ — جایگزینی با `$N`
ورودی: `"ali rezaei"` → خروجی: `"rezaei, ali"`. با `replaceAll` و گروه‌ها.

### تمرین ۴ — `appendReplacement` واقعی
یه رشته با اعداد: `"قیمت 5000 و 3000"`. هر عدد رو با `قیمت اصلی + ۱۰٪ مالیات` جایگزین کن.
خروجی: `"قیمت 5500 و 3300"`

### تمرین ۵ — 💀 آیا این الگو خطرناکه؟
```java
"^(\\d+)*$"
```
اگه بله، چرا؟ با چه ورودی‌ای مشکل می‌شه؟ چطور **دقیقاً** درستش می‌کنی؟

### تمرین ۶ — Refactor برای performance
این کد رو بازنویسی کن:
```java
public boolean isValidPhone(String s) {
    if (s == null) return false;
    for (int i = 0; i < 1000; i++) {
        if (s.matches("^09\\d{9}$")) return true;
    }
    return false;
}
```
حداقل ۲ مشکل رو حل کن.

### تمرین ۷ — چالش: کد ملی کامل
یه کلاس `NationalCodeValidator` بنویس با:
- `public static boolean isValidFormat(String code)` → regex-based: ۱۰ رقم، ۳ رقم اول غیر از ۰۰۰
- `public static boolean isValid(String code)` → علاوه بر format، **چک‌سام** رو هم حساب کن (الگوریتم: هر رقم × وزن نزولی ۱۰ تا ۲، جمع، mod 11، مقایسه با رقم آخر — اگه mod == 10 یا mod+رقم آخر == 11، معتبره)
- Test کن با `"1234567890"` و `"0001234567"` و چندتا معتبر/نامعتبر.

این تمرین بهت یاد می‌ده **مرز regex کجاست** — بعضی چیزها اصلاً نباید با regex حل بشن.
