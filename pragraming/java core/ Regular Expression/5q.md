# 🎓 جلسه ۵ — کارگاه نهایی: از تئوری به کد واقعی

> ⚠️ **توجه:** تمرین‌های جلسهٔ ۲، ۳ و ۴ رو نفرستادی. این جلسه **آخرین جلسهٔ دوره** است و یه **پروژهٔ کامل** می‌سازیم. اگه بعدش تمرین‌ها رو بفرستی، بررسی می‌کنم. ولی این جلسه رو از دست نده — این جلسه همه‌چیز رو به هم وصل می‌کنه.

---

## ۵.۱ چرا این جلسه مهم‌ترین جلسه‌ست؟

تا الان تکه‌تکه یاد گرفتی: کوانتیفایر، lookaround، گروه، backreference، performance. ولی **اعتبارسنجی واقعی** این‌ها رو با هم ترکیب می‌کنه و چندتا چیز دیگه هم اضافه می‌کنه:

- ✅ **Null safety** — `matches()` روی `null` NPE می‌ده
- ✅ **Trim** — کاربر `" ali "` می‌فرسته یا `"ali"`؟
- ✅ **Unicode** — فارسی، عربی، ایموجی
- ✅ **Normalization** — ارقام فارسی `۰۱۲` vs لاتین `012`
- ✅ **Timeout** — جلوگیری از ReDoS
- ✅ **Testing** — بدون unit test، regex = باگ خفته

## ۵.۲ کلاس `Validators` نهایی (production-ready)

این کلاس رو **کپی کن**، تست کن، استفاده کن. همه چیزهایی که یاد گرفتی اینجاست:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
import java.util.regex.Pattern;

public final class Validators {

    private Validators() {}  // utility class

    // ═══════════════════════════════════════════════
    // الگوها — همه static final
    // ═══════════════════════════════════════════════

    // ایمیل کاربردی (نه RFC کامل، ولی ۹۹٪ موارد واقعی)
    private static final Pattern EMAIL = Pattern.compile(
        "^[A-Za-z0-9](?:[A-Za-z0-9._-]{0,62}[A-Za-z0-9])?@" +
        "[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?" +
        "(?:\\.[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?)+$"
    );

    // موبایل ایران
    private static final Pattern MOBILE_IR = Pattern.compile("^09\\d{9}$");

    // تلفن ثابت ایران (با کد شهر، ساده‌شده)
    private static final Pattern PHONE_IR = Pattern.compile("^0\\d{2,3}-?\\d{7,8}$");

    // کد ملی — فقط format، چک‌سام جدا
    private static final Pattern NATIONAL_CODE_FORMAT =
        Pattern.compile("^(?!000)\\d{10}$");

    // کد پستی ایران: ۱۰ رقم، بدون صفر اول، بدون ۵ رقم تکراری پشت‌سرهم
    private static final Pattern POSTAL_CODE_IR = Pattern.compile(
        "^(?!0)(?!.*(\\d)\\1{4})\\d{10}$"
    );

    // شبا: IR + ۲۴ رقم
    private static final Pattern SHEBA = Pattern.compile("^IR\\d{24}$");

    // تاریخ شمسی YYYY/MM/DD یا YYYY-MM-DD
    // سال ۱۳۰۰-۱۴۹۹، ماه ۰۱-۱۲، روز ۰۱-۳۱ (بدون دقت کامل تقویم)
    private static final Pattern JALALI_DATE = Pattern.compile(
        "^1[34]\\d{2}[-/]" +
        "(?:0[1-9]|1[0-2])[-/]" +
        "(?:0[1-9]|[12]\\d|3[01])$"
    );

    // نام فارسی: حداقل ۲ کاراکتر، فقط حروف فارسی + فاصله + ZWNJ (نیم‌فاصله)
    private static final Pattern PERSIAN_NAME = Pattern.compile(
        "^[\\u0600-\\u06FF\\u200c\\s]{2,50}$"
    );

    // رمز قوی: ۱۰-۲۵، حداقل یک حرف کوچک، یک حرف بزرگ، یک رقم، یک کاراکتر خاص
    private static final Pattern STRONG_PASSWORD = Pattern.compile(
        "^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)(?=.*[@#$%!&*])[A-Za-z\\d@#$%!&*]{10,25}$"
    );

    // URL ساده http/https
    private static final Pattern URL = Pattern.compile(
        "^https?://[A-Za-z0-9.-]+(?::\\d{1,5})?(?:/\\S*)?$"
    );

    // ═══════════════════════════════════════════════
    // متدهای public
    // ═══════════════════════════════════════════════

    public static boolean isEmail(String s) {
        return matches(EMAIL, s);
    }

    public static boolean isMobileIR(String s) {
        return matches(MOBILE_IR, s);
    }

    public static boolean isPhoneIR(String s) {
        return matches(PHONE_IR, s);
    }

    public static boolean isPostalCodeIR(String s) {
        return matches(POSTAL_CODE_IR, s);
    }

    public static boolean isSheba(String s) {
        return matches(SHEBA, s);
    }

    public static boolean isJalaliDate(String s) {
        return matches(JALALI_DATE, s);
    }

    public static boolean isPersianName(String s) {
        return matches(PERSIAN_NAME, s);
    }

    public static boolean isStrongPassword(String s) {
        return matches(STRONG_PASSWORD, s);
    }

    public static boolean isUrl(String s) {
        return matches(URL, s);
    }

    /**
     * کد ملی: format + چک‌سام
     */
    public static boolean isNationalCode(String s) {
        if (!matches(NATIONAL_CODE_FORMAT, s)) return false;
        return hasValidNationalCodeChecksum(s);
    }

    // ═══════════════════════════════════════════════
    // helpers
    // ═══════════════════════════════════════════════

    private static boolean matches(Pattern p, String s) {
        return s != null && p.matcher(s).matches();
    }

    /**
     * الگوریتم چک‌سام کد ملی ایران.
     * جمع (رقم[i] × (10-i)) برای i=0..8، mod 11.
     * اگه mod >= 2 و mod != رقم آخر → invalid.
     * اگه mod == 0 یا mod == 1 و رقم آخر == mod → valid.
     */
    private static boolean hasValidNationalCodeChecksum(String code) {
        int sum = 0;
        for (int i = 0; i < 9; i++) {
            sum += (code.charAt(i) - '0') * (10 - i);
        }
        int r = sum % 11;
        int last = code.charAt(9) - '0';
        return (r < 2 && last == r) || (r >= 2 && last == 11 - r);
    }
}
```

</div>


### نکات کلیدی این کلاس

**۱. `s != null` قبل از `matcher`:** بدون این، `null` → NPE. هر validator حرفه‌ای اینو چک می‌کنه.

**۲. `private constructor`:** utility class نباید نمونه‌سازی بشه.

**۳. همه Pattern ها `static final`:** یک بار کامپایل، thread-safe.

**۴. regex جدا از logic:** چک‌سام کد ملی در متد جدا. **regex نباید همه‌کاره باشه**.

**۵. ایمیل واقعی:** `[A-Za-z0-9](?:[...]{0,62}[A-Za-z0-9])?` اجازه نمی‌ده نقطه اول/آخر باشه و از `..` پشت‌سرهم جلوگیری می‌کنه (تمرین ۶ جلسهٔ ۳ — بالاخره جواب!).

## ۵.۳ نکات پنهان که هیچ دوره‌ای بهت نمی‌گه

### ۱. ارقام فارسی — دشمن خاموش اعتبارسنجی

کاربر ایرانی ممکنه `۰۹۱۲۳۴۵۶۷۸۹` بفرسته، نه `09123456789`. اگه مستقیم `\d` بذاری، **fail می‌شه**. راه‌حل: **نرمال‌سازی قبل از اعتبارسنجی**.

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
public static String normalizeDigits(String s) {
    if (s == null) return null;
    StringBuilder sb = new StringBuilder(s.length());
    for (char c : s.toCharArray()) {
        if (c >= '\u06F0' && c <= '\u06F9') {        // ارقام فارسی ۰-۹
            sb.append((char) ('0' + (c - '\u06F0')));
        } else if (c >= '\u0660' && c <= '\u0669') { // ارقام عربی ٠-٩
            sb.append((char) ('0' + (c - '\u0660')));
        } else {
            sb.append(c);
        }
    }
    return sb.toString();
}
```

</div>


حالا:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
public static boolean isMobileIR(String s) {
    return matches(MOBILE_IR, normalizeDigits(s));
}
```

</div>


### ۲. Trim — کاربر همیشه فاصله می‌فرسته

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
private static boolean matches(Pattern p, String s) {
    return s != null && p.matcher(s.strip()).matches();  // strip() ← نه trim()
}
```

</div>


⚠️ `trim()` فقط ASCII فاصله رو حذف می‌کنه؛ `strip()` Unicode-aware هست (NBSP، ZWNJ و ... رو هم می‌گیره). **همیشه `strip()`** — مگه در Java < 11 باشی.

### ۳. Unicode Normalization — قاتل خاموش فارسی

`"سلام"` و `"سَلام"` و `"سـلام"` ممکنه در برخی سیستم‌ها **بایت‌های متفاوت** داشته باشن. برای مقایسه:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
import java.text.Normalizer;

String normalized = Normalizer.normalize(input, Normalizer.Form.NFC);
```

</div>


⚠️ ولی برای اعتبارسنجی **سختگیرانه** (که فقط حروف مجازن)، معمولاً NFC کافیه. برای ذخیره/مقایسه، **همیشه NFC**.

### ۴. ZWNJ (نیم‌فاصله) — `\u200c`

`"می‌روم"` vs `"میروم"` — دومی غلطه ولی کاربر ممکنه بفرسته. ZWNJ کاراکتر `U+200C` هست. توی `PERSIAN_NAME` با `\u200c` پشتیبانی می‌شه.

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"می\u200cروم"   // با نیم‌فاصله
"میروم"         // بدون
```

</div>


### ۵. Timeout برای جلوگیری از ReDoS

حتی اگه الگوت امن باشه، **دشمن می‌تونه ورودی طراحی کنه**. اگه اعتبارسنجی روی endpoint public هست، timeout بذار:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
import java.util.concurrent.*;

public static boolean matchesSafe(Pattern p, String s, long timeoutMs) {
    if (s == null) return false;
    ExecutorService ex = Executors.newSingleThreadExecutor();
    try {
        Future<Boolean> f = ex.submit(() -> p.matcher(s.strip()).matches());
        return f.get(timeoutMs, TimeUnit.MILLISECONDS);
    } catch (TimeoutException e) {
        return false;  // ورودی مشکوک، رد کن
    } catch (Exception e) {
        return false;
    } finally {
        ex.shutdownNow();
    }
}
```

</div>


⚠️ این **thread pool جدید** می‌سازه — برای هر request گران هست. راه بهتر: **یک Executor مشترک** با thread محدود + صف، یا کتابخانه‌ای مثل **`com.google.re2j`** (regex خطی، بدون backtracking).

### ۶. زمان استفاده از **کتابخانه** نه Regex دستی

یه قانون طلایی: **اگه regex از ۸۰ کاراکتر گذشت، احتمالاً باید کتابخانه استفاده کنی.**

| کار | کتابخانه |
|-----|----------|
| ایمیل (RFC کامل) | `commons-validator` (Apache) — `EmailValidator` |
| URL | `java.net.URI` + `java.net.URL` — خود JDK |
| تاریخ شمسی | `java.time.chrono.HijrahDate` یا کتابخانه‌های `jalali` |
| اعتبارسنجی Bean | `jakarta.validation` + `@Pattern`, `@Email` |
| کد ملی / شبا | خودت بنویس (معمولاً منطق چک‌سام هست) |

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
// به جای regex دستی:
try { new URI(input); return true; }
catch (URISyntaxException e) { return false; }
```

</div>


**اعتبارسنجی با URI و URL واقعاً درست‌تره چون استاندارد رو کامل پیاده کرده.**

## ۵.۴ Unit Testing — چرا و چطور

بدون تست، regex خفته می‌مونه. یه تست کوچیک برای هر validator:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class ValidatorsTest {

    @Test
    void mobileIR_valid() {
        assertTrue(Validators.isMobileIR("09123456789"));
    }

    @Test
    void mobileIR_invalid() {
        assertFalse(Validators.isMobileIR(null));
        assertFalse(Validators.isMobileIR(""));
        assertFalse(Validators.isMobileIR("0912345678"));    // ۱۰ رقم
        assertFalse(Validators.isMobileIR("091234567890"));  // ۱۲ رقم
        assertFalse(Validators.isMobileIR("08123456789"));   // با 08
        assertFalse(Validators.isMobileIR("0912345678a"));   // حرف
    }

    @Test
    void nationalCode_valid() {
        assertTrue(Validators.isNationalCode("0499370899")); // کد معتبر واقعی
        assertTrue(Validators.isNationalCode("0790419904"));
    }

    @Test
    void nationalCode_invalidChecksum() {
        assertFalse(Validators.isNationalCode("1234567890")); // چک‌سام نامعتبر
        assertFalse(Validators.isNationalCode("0001234567")); // ۰۰۰ اول
    }

    @Test
    void passwordReDoS_safe() {
        // ورودی بد برای ReDoS — نباید بلاک بشه
        String evil = "a".repeat(50) + "X";
        long start = System.currentTimeMillis();
        Validators.isStrongPassword(evil);
        long elapsed = System.currentTimeMillis() - start;
        assertTrue(elapsed < 100, "احتمال catastrophic backtracking");
    }
}
```

</div>


### ✅ چه چیزهایی تست کنیم؟

- **positive:** ورودی‌های معتبر (حداقل ۳ تا، مختلف‌الجنس)
- **negative:** ورودی‌های نامعتبر (حداقل ۵ تا، هر حالت شکست)
- **edge:** خالی، null، فقط فاصله، طولانه، Unicode، ارقام فارسی
- **ReDoS:** ورودی طراحی‌شده، اجرا باید < 100ms بشه

### ⚠️ تست کد ملی

کدهای معتبر واقعی پیدا کن (گوشه و کنار اینترنت) و تست کن. **هیچ‌وقت به تست خودت اعتماد نکن بدون کد معتبر واقعی** — الگوریتم رو ممکنه اشتباه پیاده کنی و تست خودت هم تاییدش کنه.

## ۵.۷ 🎯 پروژهٔ نهایی — `FormValidator` کامل

یه کلاس `FormValidator` بنویس که یک **فرم ثبت‌نام** رو اعتبارسنجی کنه. سختگیرانه و با پیام خطای دقیق.

### ورودی: یه `Map<String, String>`

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
Map<String, String> form = new HashMap<>();
form.put("firstName", "علی");
form.put("lastName", "رضایی");
form.put("nationalCode", "0499370899");
form.put("mobile", "09123456789");
form.put("email", "ali.rezaei@gmail.com");
form.put("password", "Abc12345@x");
form.put("postalCode", "1234567890");
form.put("birthDate", "1370/05/22");
```

</div>


### خروجی: `List<String>` از پیام‌های خطا (خالی = معتبر)

### قواعد:

| فیلد | قاعده |
|------|-------|
| `firstName` / `lastName` | نام فارسی، ۲-۵۰ کاراکتر، حداقل ۲ کاراکتر غیرفاصله |
| `nationalCode` | کد ملی کامل (format + چک‌سام) |
| `mobile` | موبایل ایران |
| `email` | ایمیل |
| `password` | رمز قوی |
| `postalCode` | کد پستی ایران |
| `birthDate` | تاریخ شمسی، **سن بین ۱۸ تا ۱۰۰ سال** نسبت به امروز |

### چالش اضافه:

- ✅ همه ورودی‌ها رو `strip` و `normalizeDigits` کن
- ✅ اگه فیلد null یا خالی، پیام «فیلد X الزامی است»
- ✅ پیام خطا **دقیق** باشه، نه «مقدار نامعتبر»

### نمونهٔ خروجی:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```
[ERROR] firstName: باید فقط شامل حروف فارسی باشد
[ERROR] birthDate: سن باید بین ۱۸ تا ۱۰۰ سال باشد
```

</div>


### راهنمای محاسبهٔ سن از تاریخ شمسی:

از `java.time.chrono.HijrahDate` استفاده نکن (تقویم هجری قمری متفاوته). ساده‌ترین راه:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
// تبدیل ساده: سال شمسی حدوداً = سال میلادی - 621
int birthYear = Integer.parseInt(birthDate.substring(0, 4));
int currentJalaliYear = 1403;  // یا محاسبه کن
int age = currentJalaliYear - birthYear;
```

## ۵.۸ 📌 جواب تمرین‌های قبلی (همه یک‌جا)

بذار یه‌جا جواب همهٔ تمرین‌های ۲، ۳، ۴ رو بذارم تا اگه دوست داشتی مقایسه کنی:

<details>
<summary>🎯 جواب‌ها (کلیک)</summary>

**جلسهٔ ۲ — تمرین ۲ (کد ملی format):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?!000)\\d{10}$"
```

</div>


**جلسهٔ ۲ — تمرین ۴ (ایمیل):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^[A-Za-z0-9._-]+@[A-Za-z0-9-]+\\.[A-Za-z]{2,}$"
```

</div>


**جلسهٔ ۲ — تمرین ۶ (URL):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^https?://[A-Za-z0-9.-]+(/\\S*)?$"
```

</div>


**جلسهٔ ۳ — تمرین ۱ (رمز متوسط):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?=.*[A-Za-z])(?=.*\\d).{8,20}$"
```

</div>


**جلسهٔ ۳ — تمرین ۳ (رمز قوی):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)(?=.*[@#$%!]).{10,25}$"
```

</div>


**جلسهٔ ۳ — تمرین ۴ (اعداد بعد از $):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"(?<=\\$)\\d+"
// یا:
"\\$\\K\\d+"   // در جاوا \K کار نمی‌کنه، فقط PCRE
```

</div>


**جلسهٔ ۳ — تمرین ۵ (چرا کار نمی‌کنه):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)[A-Z]+$"
```

</div>

`[A-Z]+` فقط حرف بزرگ مجازه، ولی `(?=.*[a-z])` می‌خواد حرف کوچک هم باشه — تناقض. **هیچ‌وقت match نمی‌شه.** جواب درست:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d)[A-Za-z\\d]+$"
```

</div>


**جلسهٔ ۳ — تمرین ۶ (ایمیل بدون نقطهٔ اول/آخر و `..`):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?!.*\\.\\.)(?![.])[A-Za-z0-9._-]*[A-Za-z0-9](?:@)[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$"
```

</div>

یا ساده‌تر (نسخهٔ نهایی جلسهٔ ۵):

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^[A-Za-z0-9](?:[A-Za-z0-9._-]{0,62}[A-Za-z0-9])?@...$"
```

</div>


**جلسهٔ ۳ — تمرین ۷ (تاریخ میلادی):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(?:19|20)\\d{2}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\\d|3[01])$"
```

</div>


**جلسهٔ ۴ — تمرین ۲ (کلمات تکراری):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"\\b(\\w+)\\s+\\1\\b"
```

</div>


**جلسهٔ ۴ — تمرین ۳ (جابجایی اسم و فامیل):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"ali rezaei".replaceAll("(\\w+)\\s+(\\w+)", "$2, $1")
// → "rezaei, ali"
```

</div>


**جلسهٔ ۴ — تمرین ۵ (ReDoS):**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```java
"^(\\d+)*$"   // 💀 روی "123...X" انفجاری
// راه‌حل:
"^\\d+$"      // کوانتیفایر تودرتو حذف
// یا:
"^(?:\\d+)*$"  // (بهتر، ولی بازم امن نیست اگه ) بعد از * باشه)
// بهترین:
"^\\d*$"
```

</div>


**جلسهٔ ۴ — تمرین ۶ (performance):**

```java
private static final Pattern PHONE = Pattern.compile("^09\\d{9}$");
public boolean isValidPhone(String s) {
    if (s == null) return false;
    String normalized = normalizeDigits(s.strip());
    return PHONE.matcher(normalized).matches();  // خارج از حلقه
}
```

## ۵.۹ 🎓 نقشهٔ راه بعد از دوره

تازه شروع کارته. چیزهایی که هنوز یاد نگرفتی:

### سطح بعدی Regex:
- **Conditional patterns:** `(?(1)yes|no)` — ولی جاوا پشتیبانی محدود داره
- **Recursive patterns** — برای پارس ساختارهای تودرتو (JSON و ...)
- **`\G`** — match پیوسته
- **`Pattern.asPredicate()`** — برای Stream API
- **`Pattern.splitAsStream()`** — برای split تنبل

### دنیای بزرگ‌تر:
- **`java.text.MessageFormat`** و `String.format` — جایگزین‌های بهتر برای خیلی کارها
- **Bean Validation (jakarta.validation):** `@Pattern`, `@Email`, `@Size` — استاندارد اعتبارسنجی در Spring
- **کتابخانه‌های اعتبارسنجی:** Apache Commons Validator، Hibernate Validator
- **`re2j`** — Regex خطی، بدون ReDoS، برای endpoint های public
- **`parboiled`** یا **`ANTLR`** — وقتی regex کافی نیست

### منابع برای ادامه:
- 📖 **Mastering Regular Expressions** (Jeffrey Friedl) — Bible regex
- 🌐 **regular-expressions.info** — مرجع کامل
- 🌐 **regex101.com** — هر روز یه regex واقعی تست کن
- 💻 **JavaDoc:** `java.util.regex.Pattern` — همه‌چیز رو بخون

## ۵.۱۰ 🏁 جمع‌بندی: ۷ قانون طلایی اعتبارسنجی

1. **`Pattern` استاتیک، `Matcher` local.** همیشه.
2. **`^$` بذار، حتی با `matches()`.** خوندن کد رو نجات می‌ده.
3. **Whitelist، نه blacklist.** «چی مجازه»، نه «چی مجاز نیست».
4. **`s != null` چک کن** و `strip()` بزن.
5. **`normalizeDigits()` قبل از اعتبارسنجی** — کاربر ایرانی ارقام فارسی می‌فرسته.
6. **Regex = اعتبارسنجی فرمت، نه منطق.** چک‌سام، سن، منطق کسب‌وکار → کد جاوا.
7. **تست کن، مخصوصاً ReDoS.** ورودی ۵۰ کاراکتری بد طراحی‌شده می‌تونه سرور رو بخوابونه.
