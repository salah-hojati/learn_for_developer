|  |                                                          |    |

# Loki: Promtail -> Loki -> Grafana
+------------------------------------------------------------------+
|                      LOKI LOG AGGREGATION                        |
|                                                                  |
|  LOG FLOW:                                                       |
|                                                                  |
|  +--------------------------+                                    |
|  |      APPLICATION PODS    |                                    |
|  |                          |                                    |
|  |  stdout/stderr ->        |                                    |
|  |  /var/log/pods/...       |                                    |
|  |  /var/log/containers/... |                                    |
|  +-----------+--------------+                                    |
|              |                                                   |
|              |  Tail log files                                  |
|              v                                                   |
|  +--------------------------+                                    |
|  |      PROMTAIL (DaemonSet)|                                    |
|  |                          |                                    |
|  |  - Discovers Pod logs    |                                    |
|  |    via kubernetes_sd     |                                    |
|  |  - Labels:               |                                    |
|  |    {namespace, pod,      |                                    |
|    container, app}         |                                    |
|  |  - Pipeline stages:      |                                    |
|  |    - regex/JSON parse    |                                    |
|  |    - label extraction    |                                    |
|  |    - timestamp parse     |                                    |
|  |    - multiline handling  |                                    |
|  |  - Batches & compresses  |                                    |
|  |  - Pushes to Loki        |                                    |
|  |    (HTTP/gRPC, port 3100)|                                    |
|  +-----------+--------------+                                    |
|              |                                                   |
|              |  HTTP POST /loki/api/v1/push                      |
|              v                                                   |
|  +--------------------------+                                    |
|  |         LOKI             |                                    |
|  |  (Distributed:           |                                    |
|  |   ingester, querier,     |                                    |
|  |   query-frontend,        |                                    |
|  |   compactor,             |                                    |
|  |   distributor,           |                                    |
|  |   ruler)                 |                                    |
|  |                          |                                    |
|  |  - Index: Labels only    |                                    |
|  |    (TSDB, chunked)       |                                    |
|  |  - Chunks: Compressed    |                                    |
|  |    log lines (gzip)      |                                    |
|  |  - Storage: S3/GCS/      |                                    |
|  |    filesystem            |                                    |
|  |  - Retention: time/size  |                                    |
|  +-----------+--------------+                                    |
|              |                                                   |
|              |  LogQL queries                                   |
|              v                                                   |
|  +--------------------------+                                    |
|  |        GRAFANA           |                                    |
|  |                          |                                    |
|  |  - Data source: Loki     |                                    |
|  |  - Explore: LogQL        |                                    |
|  |    {app="myapp"} |= "error"                               |
|  |  - Dashboards: Logs +    |                                    |
|  |    Metrics correlation |                                    |
|  |  - Alerting on logs      |                                    |
|  +--------------------------+                                    |
|                                                                  |
|  KEY DIFFERENCE FROM ELK:                                        |
|  - Loki indexes ONLY labels (not full text)                     |
|  - Much smaller index, cheaper storage                          |
|  - Queries scan chunks (parallel, fast)                         |
|  - Native Grafana integration                                   |

# Probes: Startup / Readiness / Liveness
+------------------------------------------------------------------+
|                    PROBES: STARTUP / READINESS / LIVENESS        |
|                                                                  |
|  PROBE TYPES:                                                    |
|  +--------------------------+  +--------------------------+      |
|  |  HTTP GET                |  |  TCP Socket              |      |
|  |  GET /healthz HTTP/1.1   |  |  Dial tcp:8080           |      |
|  |  Host: pod-ip            |  |  Success = open        |      |
|  |  Success: 2xx/3xx        |  |                        |      |
|  +--------------------------+  +--------------------------+      |
|  +--------------------------+  +--------------------------+      |
|  |  gRPC                    |  |  Exec (command)          |      |
|  |  grpc.health.v1.Health/  |  |  cat /tmp/healthy        |      |
|  |  Check                   |  |  Exit 0 = success       |      |
|  |  Status: SERVING         |  |                        |      |
|  +--------------------------+  +--------------------------+      |
|                                                                  |
|  PROBE FIELDS:                                                   |
|  +--------------------------+  +--------------------------+      |
|  |  initialDelaySeconds: 5  |  |  periodSeconds: 10       |      |
|  |  (first probe after      |  |  (interval)              |      |
|  |   container start)       |  |                          |      |
|  |  timeoutSeconds: 1       |  |  successThreshold: 1     |      |
|  |  (per probe timeout)     |  |  (consecutive successes) |      |
|  |  failureThreshold: 3     |  |  failureThreshold: 3     |      |
|  |  (consecutive failures)  |  |  (consecutive failures)  |      |
|  |  terminationGracePeriod  |  |                          |      |
|  |  (SIGTERM wait)          |  |                          |      |
|  +--------------------------+  +--------------------------+      |
|                                                                  |
|  STARTUP PROBE:                                                  |
|  - Runs BEFORE readiness/liveness                                |
|  - For slow-starting apps (Java, DB migration)                  |
|  - failureThreshold * periodSeconds = max startup time          |
|  - If fails: container killed (restartPolicy applies)           |
|  - Disables liveness/readiness until success                    |
|                                                                  |
|  READINESS PROBE:                                                |
|  - Determines if Pod receives traffic                           |
|  - Failure -> Pod removed from Service Endpoints                |
|  - Success -> Pod added to Endpoints                            |
|  - Use for: DB connections, cache warmup, dependencies          |
|                                                                  |
|  LIVENESS PROBE:                                                 |
|  - Determines if container is alive                             |
|  - Failure -> Container RESTARTED (restartPolicy)               |
|  - Use for: Deadlock detection, stuck threads                   |
|  - Avoid for: External dependency checks (use readiness)        |
|                                                                  |
|  INTERACTION:                                                    |
|  1. Container starts                                            |
|  2. Startup probe runs (if defined)                             |
|  3. Startup succeeds -> Readiness/Liveness begin                |
|  4. Readiness fails -> No traffic, but container lives          |
|  5. Liveness fails -> Container restart                         |
|                                                                  |
|  COMMON MISTAKES:                                                |
|  - Same endpoint for all probes                                 |
|  - Liveness on /healthz that checks DB (cascading failure)      |
|  - Too aggressive failureThreshold (flapping)                   |
|  - No startup probe for slow apps                               |
