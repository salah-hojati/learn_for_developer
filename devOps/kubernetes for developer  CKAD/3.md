### 🛠️ Part 1: Your First Project — The Personal Blog Platform

This project deploys a complete three-tier application (NGINX frontend, Node.js API, MySQL database) and is specifically designed to teach the core Kubernetes objects you need to master. The most efficient way to start is by using the provided "all-in-one" YAML file from the `kubernetes-for-students` course.

#### 📋 Prerequisites
Before you start, ensure you have a running local cluster (like **Minikube** or **kind**) and that `kubectl` is configured to talk to it. The project is designed to work on any cluster but is optimized for Minikube.

#### 🚀 Step-by-Step Deployment Walkthrough

**Step 1: Get the Manifest**
Clone the course repository or simply download the single YAML file that defines every resource for the project.
```bash
git clone https://github.com/0xReLogic/kubernetes-for-students.git
cd kubernetes-for-students
```
The key file is located at: `examples/chapter-10/project-1-blog-platform.yaml`. This single file contains over 600 lines of production-ready manifests for the entire stack.

**Step 2: Deploy the Entire Stack**
Apply the single file to your cluster. This will create a dedicated namespace (`blog-platform`) and all the necessary resources inside it.
```bash
kubectl apply -f examples/chapter-10/project-1-blog-platform.yaml
```

**Step 3: Watch the Pods Start**
Kubernetes will now pull images and start the containers. Watch the pods transition to the `Running` state. The MySQL database may take a moment to initialize.
```bash
kubectl get pods -n blog-platform -w
```
Press `Ctrl+C` once all pods show `Running`.

**Step 4: Access the Application**
The project exposes the frontend via a **NodePort** service on port `30080`. How you access it depends on your cluster:

*   **On Minikube**: Run this command to get the URL:
    ```bash
    minikube service blog-frontend -n blog-platform
    ```
*   **On another cluster (kind, Docker Desktop)**: Access it via `http://localhost:30080`.
*   **Using an Ingress (Advanced)**: The manifest also defines an Ingress resource. If your cluster has an Ingress controller enabled (e.g., `minikube addons enable ingress`), you can add `<cluster-ip> blog.local` to your `/etc/hosts` file and visit `http://blog.local`.

**Step 5: Verify the Stack is Working**
Once the frontend is open in your browser, you can test the full stack by creating a new blog post through the UI. The request will flow from **NGINX → Node.js API → MySQL**, and the new post should appear, proving all three tiers are communicating correctly.

#### 🔍 What You Are Actually Learning
This single project packs in several crucial Kubernetes concepts. Here is how to map the resources in the YAML file to what you're learning:

| Kubernetes Resource | What It Does in the Project | Key Learning Objective |
| :--- | :--- | :--- |
| **Namespace** (`blog-platform`) | Isolates all resources for this project. | Organizing and isolating workloads. |
| **Secret** (`blog-mysql-secret`) | Stores the database root password, user, and name securely. | Managing sensitive configuration separately from code. |
| **ConfigMap** (`blog-api-config`) | Stores non-sensitive config like database host and port for the API. | Decoupling configuration from container images. |
| **PersistentVolumeClaim** (`blog-mysql-pvc`) | Requests 1Gi of storage that survives pod restarts. | Stateful data persistence for databases. |
| **Deployment** (MySQL, API, Frontend) | Manages the desired state and rolling updates for each tier. | Self-healing and declarative application management. |
| **Service** (MySQL, API, Frontend) | Provides stable network endpoints (DNS) for each tier. | Service discovery and internal load balancing. |
| **Ingress** (`blog-ingress`) | Routes external HTTP traffic to the frontend service. | Exposing applications to the outside world with routing. |
| **Health Probes** | Checks the health of MySQL and the API. | Kubernetes automatically restarting unhealthy containers. |

### 🧪 Part 2: Your First Guided Lab on Killercoda

Killercoda provides a zero-setup, browser-based terminal connected to a real Kubernetes cluster. It's the perfect way to practice without installing anything locally.

#### 🎯 Where to Start
1.  Go to **[killercoda.com](https://killercoda.com)** (no signup required for the playgrounds).
2.  In the search bar, type **"Kubernetes"** or **"Kubernetes Basics"**.
3.  Click on a beginner scenario. A great starting point is the **"Kubernetes Basics"** scenario, which walks you through creating your first Pod, Deployment, and Service.

#### ⚡ A "Quick Start" You Can Try Right Now
If you want to get your hands dirty immediately, the `k8s-beginner-project` repository is designed specifically for Killercoda. Once you have a Killercoda Kubernetes terminal open, paste this **one-liner** to deploy a demo application:
```bash
git clone https://github.com/shazforiot/k8s-beginner-project.git && cd k8s-beginner-project && kubectl apply -k k8s/ && sleep 15 && kubectl get pods -n k8s-demo && kubectl port-forward svc/k8s-demo-service 8080:80 -n k8s-demo --address 0.0.0.0
```
**What this does:**
*   Clones a small project.
*   Uses `kubectl apply -k` to deploy all resources at once.
*   Waits 15 seconds for pods to start.
*   Shows you the running pods.
*   Sets up **port-forwarding** so you can access the app.

**To view the app:** In Killercoda's interface, click the **"Traffic / Ports"** tab and add port `8080`. You can then click the generated link to see the running demo application in your browser.
