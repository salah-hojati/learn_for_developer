# جلسه ۵: اسکریپت‌نویسی Bash

**هدف:** در پایان این جلسه بتوانی اسکریپت‌هایی بنویسی که **امن**، **قابل اعتماد** و **حرفه‌ای** باشند—نه اسکریپت‌هایی که با یک فاصله اضافه یا فایل نبود، وسط کار رها می‌شوند.

---

## بخش ۱: ساختار یک اسکریپت حرفه‌ای

هر اسکریپت Bash از سه بخش تشکیل می‌شود:

```bash
#!/usr/bin/env bash
#
# script-name.sh — توضیح کوتاه اسکریپت
# Usage: ./script-name.sh [args]
#

set -Eeuo pipefail   # خط دفاعی اول (در بخش ۷ کامل توضیح می‌دهم)

# ... بدنه اسکریپت ...
```

### Shebang — خط اول

`#!/usr/bin/env bash` به سیستم می‌گوید: «این فایل را با Bash اجرا کن». استفاده از `env` (به جای `#!/bin/bash`) قابل‌حمل‌تر است و روی سیستم‌هایی که Bash در مسیر دیگری است هم کار می‌کند.

### مجوز اجرا

بعد از نوشتن، باید فایل را executable کنی (همان `chmod` جلسه ۲):

```bash
chmod +x script.sh
./script.sh
```

## بخش ۲: متغیرها و `$(...)`

### تعریف متغیر (بدون فاصله دور `=`)

```bash
name="DevOps"
count=5
```

**قانون طلایی:** `name = "DevOps"` (با فاصله) اشتباه است و Bash آن را به عنوان دستور اجرا می‌کند.

### استفاده از متغیر (با `$`)

```bash
echo "Hello, $name"
```

### **همیشه متغیرها را در `"` بگذار**

این مهم‌ترین عادت یک اسکریپت‌نویس حرفه‌ای است:

```bash
# ❌ خطرناک: اگر name فاصله داشته باشد یا خالی باشد، به هم می‌ریزد
echo $name

# ✅ امن
echo "$name"
```

اگر متغیر تعریف‌نشده باشد و `set -u` فعال باشد، `"$name"` خطا می‌دهد و جلوی ادامه کار را می‌گیرد—این **خوب** است، چون خطا را زودتر می‌بینی.

### Command Substitution — خروجی دستور را در متغیر بریز

```bash
today=$(date +%F)
host=$(hostname)
user=$(whoami)
echo "Today is $today, host is $host, user is $user"
```

`$(...)` جای بک‌تیک (`` `...` ``) را گرفته و خواناتر است. هرگز داخل `$(...)` از `"` استفاده نکن مگر لازم باشد.

### `read` — گرفتن ورودی از کاربر

```bash
read -rp "Enter your name: " username
echo "Hello, $username"
```

`-r` از تفسیر backslash جلوگیری می‌کند (همیشه بزن). `-p` prompt می‌سازد.

## بخش ۳: پارامترهای خط فرمان

وقتی اسکریپت را با آرگومان اجرا می‌کنی: `./backup.sh /etc /backup`

| متغیر | معنا |
|---|---|
| `$0` | نام اسکریپت (`./backup.sh`) |
| `$1`, `$2`, ... | آرگومان اول، دوم، ... |
| `$#` | تعداد آرگومان‌ها |
| `$@` | همه آرگومان‌ها (هر کدام جدا) — **همیشه با `"$@"`** |
| `$*` | همه آرگومان‌ها (به هم چسبیده) — کمتر استفاده کن |
| `$?` | exit code آخرین دستور (۰ = موفق) |

### چک کردن تعداد آرگومان

```bash
if [[ $# -ne 2 ]]; then
    echo "Usage: $0 <source> <destination>" >&2
    exit 1
fi
```

`>&2` خطا را به stderr می‌فرستد (استاندارد) و `exit 1` یعنی «شکست خورده».

### پیمایش روی همه آرگومان‌ها

```bash
for arg in "$@"; do
    echo "Processing: $arg"
done
```

**نکته:** `"$@"` با quote، هر آرگومان را جدا نگه می‌دارد حتی اگر فاصله داشته باشد. `$@` بدون quote، آرگومان‌های دارای فاصله را می‌شکند.

## بخش ۴: شرط‌ها

### `if` با `[[ ]]` (توصیه‌شده در Bash)

```bash
if [[ "$user" == "root" ]]; then
    echo "You are root"
elif [[ "$user" == "devops" ]]; then
    echo "You are devops"
else
    echo "Unknown user"
fi
```

**همیشه `[[ ]]` بزن، نه `[ ]`.** `[[ ]]` امن‌تر است، از glob و regex پشتیبانی می‌کند و مشکل word splitting ندارد.

### تست فایل

| شرط | معنا |
|---|---|
| `[[ -f "$file" ]]` | فایل وجود دارد و معمولی است |
| `[[ -d "$dir" ]]` | دایرکتوری وجود دارد |
| `[[ -e "$path" ]]` | هر چیزی وجود دارد |
| `[[ -r "$file" ]]` | قابل خواندن است |
| `[[ -w "$file" ]]` | قابل نوشتن است |
| `[[ -x "$file" ]]` | قابل اجرا است |
| `[[ -s "$file" ]]` | خالی نیست (size > 0) |

### تست عددی

| شرط | معنا |
|---|---|
| `[[ $a -eq $b ]]` | مساوی |
| `[[ $a -ne $b ]]` | نامساوی |
| `[[ $a -gt $b ]]` | بزرگتر |
| `[[ $a -lt $b ]]` | کوچکتر |
| `[[ $a -ge $b ]]` | بزرگتر یا مساوی |
| `[[ $a -le $b ]]` | کوچکتر یا مساوی |

### عملگرهای منطقی

```bash
if [[ -f "$file" && -r "$file" ]]; then
    echo "File exists and is readable"
fi

if [[ "$user" == "root" || "$user" == "devops" ]]; then
    echo "Privileged user"
fi
```

### `case` — برای چند حالت

```bash
case "$1" in
    start)
        echo "Starting service..."
        ;;
    stop)
        echo "Stopping service..."
        ;;
    restart)
        echo "Restarting..."
        ;;
    *)
        echo "Usage: $0 {start|stop|restart}" >&2
        exit 1
        ;;
esac
```

## بخش ۵: حلقه‌ها

### `for` روی لیست

```bash
for server in web01 web02 db01; do
    echo "Checking $server..."
done
```

### `for` روی فایل‌ها (روش امن)

```bash
# ❌ ناامن: اسم فایل‌های دارای فاصله را می‌شکند
for file in $(ls); do
    echo "$file"
done

# ✅ امن: با glob مستقیم
for file in ./*; do
    [[ -f "$file" ]] || continue
    echo "$file"
done
```

برای فایل‌هایی که ممکن است فاصله یا کاراکتر خاص داشته باشند، از `find -print0` و `read -d ''` استفاده کن:

```bash
find /var/log -name "*.log" -print0 | while IFS= read -r -d '' file; do
    echo "Processing: $file"
done
```

### `while` — تا وقتی شرط برقرار است

```bash
count=1
while [[ $count -le 5 ]]; do
    echo "Count: $count"
    ((count++))
done
```

### `until` — تا وقتی شرط برقرار **نیست**

```bash
until ping -c1 -W1 server &>/dev/null; do
    echo "Waiting for server..."
    sleep 2
done
echo "Server is up"
```

### `break` و `continue`

```bash
for i in {1..10}; do
    [[ $i -eq 5 ]] && break     # از حلقه خارج شو
    [[ $i -eq 3 ]] && continue  # این یکی را رد کن
    echo "$i"
done
```

## بخش ۶: توابع

توابع، بلوک‌های قابل استفاده مجدد هستند:

```bash
log_info() {
    echo "[INFO] $(date '+%Y-%m-%d %H:%M:%S') - $*" >&2
}

log_error() {
    echo "[ERROR] $(date '+%Y-%m-%d %H:%M:%S') - $*" >&2
}

check_service() {
    local service="$1"   # local = فقط داخل تابع
    if systemctl is-active --quiet "$service"; then
        log_info "$service is running"
        return 0
    else
        log_error "$service is NOT running"
        return 1
    fi
}

# استفاده
check_service ssh
check_service nginx || log_error "Please start nginx"
```

**نکات مهم:**

- `local` متغیر را محلی می‌کند (از تداخل جلوگیری می‌کند).
- آرگومان‌های تابع هم با `$1`, `$2` گرفته می‌شوند (نه در پرانتز).
- `return` فقط عدد برمی‌گرداند (exit code). برای برگرداندن رشته، از `echo` و `$(...)` استفاده کن.

## بخش ۷: **خط دفاعی: `set -Eeuo pipefail`** (مهم‌ترین بخش این جلسه)

به طور پیش‌فرض، Bash **خطاها را نادیده می‌گیرد** و به کار ادامه می‌دهد. اگر یک دستور شکست بخورد، اسکریپت ادامه می‌دهد و ممکن است فاجعه بار شود.

این خط را در ابتدای هر اسکریپت Production بگذار:

```bash
set -Eeuo pipefail
```

| فلگ | معنا | چرا؟ |
|---|---|---|
| `-e` (`errexit`) | اگر هر دستوری غیرصفر برگرداند، اسکریپت فوراً خارج شود | جلوی ادامه کار با state خراب را می‌گیرد |
| `-u` (`nounset`) | استفاده از متغیر تعریف‌نشده = خطا | جلوی تایپو در نام متغیر را می‌گیرد |
| `-o pipefail` | اگر **هر بخش** از یک pipeline شکست بخورد، pipeline شکست خورده حساب شود | بدون این، `sort missing.txt \| uniq` موفق حساب می‌شود چون `uniq` موفق است |
| `-E` (`errtrace`) | trap ERR به توابع و subshellها هم ارث می‌رسد | دیباگ بهتر |

### چرا `pipefail` حیاتی است؟

بدون `pipefail`:

```bash
$ sort missing.txt | uniq
sort: cannot read missing.txt: No such file or directory
$ echo $?
0    # ← موفق! دروغ می‌گوید
```

با `pipefail`:

```bash
set -o pipefail
$ sort missing.txt | uniq
$ echo $?
2    # ← خطا را نشان می‌دهد
```

این تفاوت در CI/CD حیاتی است: اگر `grep` در pipeline شکست بخورد ولی `wc` موفق باشد، بدون `pipefail` خطا را نمی‌بینی و ممکن است تصمیم غلط بگیری.

### `set -e` و “gotcha” ها

`set -e` در برخی موقعیت‌ها (مثلاً داخل `if`، `&&`، `||`) غیرفعال می‌شود. این عمدی است تا بتوانی خطا را خودت handle کنی. اگر جایی می‌خواهی **عمداً** خطا را نادیده بگیری:

```bash
command_that_might_fail || true
```

### `trap` — پاکسازی و پیام خطا

```bash
cleanup() {
    rm -f "$tmpfile"
    echo "Cleaned up." >&2
}
trap cleanup EXIT

trap 'echo "Error on line $LINENO: $BASH_COMMAND" >&2' ERR
```

`trap ... EXIT` حتی وقتی اسکریپت با خطا خارج می‌شود هم اجرا می‌شود. برای پاک کردن فایل موقت، بستن اتصال، یا فرستادن notification عالی است.

## بخش ۸: توابع مفید و الگوهای امن

### `mktemp` — فایل موقت امن

```bash
tmpfile=$(mktemp)
trap 'rm -f "$tmpfile"' EXIT
# حالا tmpfile یک فایل با نام تصادفی امن است
```

هرگز `>/tmp/myfile` نزن — ممکن است با فایل کاربر دیگری تداخل کند یا symlink attack شود.

### `printf` به جای `echo` برای خروجی قابل پیش‌بینی

```bash
printf "Name: %s, Age: %d\n" "$name" "$age"
```

`echo` در برخی سیستم‌ها رفتار متفاوتی با `-n` و backslash دارد. `printf` استانداردتر است.

### `IFS=$'\n\t'` — جلوگیری از word splitting ناخواسته

```bash
IFS=$'\n\t'
```

این خط را بعد از `set` بگذار. باعث می‌شود فاصله، جداکننده کلمه نباشد (فقط newline و tab).

### `readonly` — متغیرهای ثابت

```bash
readonly LOG_DIR="/var/log/myapp"
readonly CONFIG_FILE="/etc/myapp/config.yml"
```

اگر اشتباهاً بخواهی مقدار را عوض کنی، Bash خطا می‌دهد.

### `shopt -s inherit_errexit`

برای اینکه `set -e` داخل `$(...)` هم کار کند (Bash 4.4+):

```bash
shopt -s inherit_errexit
```

بدون این، `$(false; echo hi)` خروجی `hi` می‌دهد و خطا را نمی‌بینی.

## بخش ۹: الگوی Argument Parsing با `getopts`

برای اسکریپت‌های جدی که فلگ دارند (`-v`, `-o file`, `-h`):

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

verbose=false
output=""

usage() {
    cat <<EOF
Usage: $0 [-v] [-o output] [-h]
  -v    Verbose mode
  -o    Output file
  -h    Show this help
EOF
}

while getopts ":vo:h" opt; do
    case "$opt" in
        v) verbose=true ;;
        o) output="$OPTARG" ;;
        h) usage; exit 0 ;;
        :) echo "Option -$OPTARG requires an argument" >&2; exit 1 ;;
        \?) echo "Invalid option: -$OPTARG" >&2; usage; exit 1 ;;
    esac
done
shift $((OPTIND - 1))

[[ "$verbose" == true ]] && echo "Verbose mode enabled" >&2
[[ -n "$output" ]] && echo "Output to: $output"
```

این الگو را در هر اسکریپت Production خواهی دید.

## بخش ۱۰: سه اسکریپت واقعی (پروژه این جلسه)

### اسکریپت ۱: گزارش سلامت سیستم

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
IFS=$'\n\t'

readonly THRESHOLD=80

check_disk() {
    local usage
    usage=$(df / | awk 'NR==2 {gsub(/%/,""); print $5}')
    if (( usage > THRESHOLD )); then
        echo "⚠️ Disk usage is ${usage}% (threshold: ${THRESHOLD}%)" >&2
        return 1
    fi
    echo "✅ Disk usage: ${usage}%"
}

check_mem() {
    local available
    available=$(free -m | awk '/^Mem:/ {print $7}')
    if (( available < 100 )); then
        echo "⚠️ Low memory: ${available}MB available" >&2
        return 1
    fi
    echo "✅ Memory: ${available}MB available"
}

check_service() {
    local svc="$1"
    if systemctl is-active --quiet "$svc"; then
        echo "✅ $svc is running"
    else
        echo "❌ $svc is NOT running" >&2
        return 1
    fi
}

main() {
    echo "=== System Health Report: $(date) ==="
    local rc=0
    check_disk || rc=1
    check_mem || rc=1
    check_service ssh || rc=1
    return "$rc"
}

main "$@"
```

**چرا این اسکریپت حرفه‌ای است:**

- `set -Eeuo pipefail` + `IFS`
- توابع با `local`
- استفاده از `awk` برای پردازش خروجی (جلسه ۱)
- `return` می‌کند تا در Cron یا CI/CD قابل استفاده باشد
- پیام‌های خطا به stderr

### اسکریپت ۲: بکاپ با `trap` و `mktemp`

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

readonly SOURCE="${1:-/etc}"
readonly BACKUP_DIR="${2:-/backup}"
readonly DATE=$(date +%Y%m%d-%H%M%S)
readonly ARCHIVE="$BACKUP_DIR/backup-$DATE.tar.gz"

cleanup() {
    [[ -f "$ARCHIVE" ]] && rm -f "$ARCHIVE"
    echo "Cleanup done." >&2
}
trap cleanup ERR

if [[ ! -d "$SOURCE" ]]; then
    echo "Error: source '$SOURCE' is not a directory" >&2
    exit 1
fi

mkdir -p "$BACKUP_DIR"

echo "Creating archive: $ARCHIVE" >&2
tar -czf "$ARCHIVE" -C "$(dirname "$SOURCE")" "$(basename "$SOURCE")"

echo "Backup completed: $ARCHIVE ($(du -h "$ARCHIVE" | cut -f1))" >&2
```

**نکات:**

- `trap cleanup ERR`: اگر `tar` شکست بخورد، فایل ناقص پاک می‌شود.
- `"${1:-/etc}"`: مقدار پیش‌فرض اگر آرگومان نداد.
- `mkdir -p`: اگر پوشه بکاپ نبود، می‌سازد.

### اسکریپت ۳: `wait_for` — انتظار برای آماده شدن سرویس

```bash
#!/usr/bin/env bash
set -Eeuo pipefail

wait_for() {
    local host="$1"
    local port="$2"
    local timeout="${3:-30}"
    local elapsed=0

    echo "Waiting for $host:$port (timeout: ${timeout}s)..." >&2
    until timeout 1 bash -c "echo > /dev/tcp/$host/$port" 2>/dev/null; do
        if (( elapsed >= timeout )); then
            echo "Timeout waiting for $host:$port" >&2
            return 1
        fi
        sleep 1
        ((elapsed++))
    done
    echo "$host:$port is ready" >&2
}

wait_for localhost 22 10 || exit 1
```

این الگو را در CI/CD و Docker Compose زیاد می‌بینی: قبل از اجرای تست، صبر کن تا دیتابیس بالا بیاید.

## بخش ۱۱: دیباگ اسکریپت

### `bash -x` — دیدن هر دستور قبل از اجرا

```bash
bash -x ./script.sh
```

یا داخل اسکریپت، موقتاً:

```bash
set -x    # روشن کردن trace
# ... کد موردنظر ...
set +x    # خاموش کردن
```

### `ShellCheck` — بهترین دوستت

```bash
sudo apt install shellcheck
shellcheck ./script.sh
```

ShellCheck تمام باگ‌ها، bad practiceها و مشکلات امنیتی را پیدا می‌کند و لینک به توضیح می‌دهد. **قبل از هر commit، ShellCheck بزن.**

### `bash -n` — فقط syntax check

```bash
bash -n ./script.sh
```

بدون اجرا، فقط syntax را چک می‌کند.

## پروژه جلسه ۵

**سناریو:** یک اسکریپت `server-health.sh` بنویس که:

1. با `set -Eeuo pipefail` شروع شود.
2. آرگومان اول: مسیر لاگ (پیش‌فرض `/var/log`).
3. آرگومان دوم: آستانه دیسک (پیش‌فرض `80`).
4. چک کند دیسک، حافظه و سرویس `ssh`.
5. اگر هر چک شکست خورد، exit code غیرصفر برگرداند.
6. با `trap` در صورت خطا پیام مناسب بدهد.
7. قبل از اجرا با `shellcheck` چک شود.

**تست:**

```bash
chmod +x server-health.sh
./server-health.sh
./server-health.sh /var/log 90
shellcheck server-health.sh
```

## اشتباهات رایج (این‌ها را نکن!)

| ❌ اشتباه | ✅ درست |
|---|---|
| `name = "value"` (فاصله) | `name="value"` |
| `echo $var` بدون quote | `echo "$var"` |
| `for f in $(ls)` | `for f in ./*` یا `find -print0 \| while read` |
| `[ $a == $b ]` | `[[ "$a" == "$b" ]]` |
| فراموش کردن `set -e` | `set -Eeuo pipefail` |
| `tmpfile=/tmp/myfile` | `tmpfile=$(mktemp)` |
| `echo` برای داده‌های دودی | `printf` |
| ادامه دادن بعد از خطا | `return 1` یا `exit 1` |
| نبودن `pipefail` | `set -o pipefail` |

## ارتباط با جلسات قبل و بعد

- **جلسه ۲ (مجوزها):** `chmod +x` روی اسکریپت همان چیزی است که اینجا لازم داری.
- **جلسه ۳ (کاربران):** اسکریپت‌های `sudo` یا `systemctl` را می‌شود با `sudo` اجرا کرد.
- **جلسه ۴ (SSH):** می‌توانی اسکریپت را روی سرور دور اجرا کنی: `ssh myserver 'bash -s' < script.sh`
- **جلسه ۶ (Git و بعد):** اسکریپت‌هایت را در Git نگه می‌داری و در CI/CD اجرا می‌کنی. Ansible هم از همین مفاهیم استفاده می‌کند.
