# جلسه ۴: SSH — از نصب تا سخت‌سازی

**هدف:** در پایان این جلسه بتوانی یک سرور SSH امن راه‌اندازی کنی، با کلید وارد شوی، ورود با رمز و root را غیرفعال کنی، و تانل بزنی.

---

## بخش ۱: SSH چیست و چرا مهم است؟

SSH (Secure Shell) یک پروتکل رمزنگاری‌شده برای اتصال به سرورهای دور است. سه کار اصلی انجام می‌دهد:

1. **ورود امن به سرور** (به جای Telnet که متن ساده می‌فرستاد)
2. **اجرای دستور از راه دور** (اسکریپت، Ansible، CI/CD)
3. **تانل کردن ترافیک** (Port Forwarding)

SSH از **رمزنگاری نامتقارن** استفاده می‌کند: کلید عمومی روی سرور، کلید خصوصی روی کلاینت. سرور با کلید عمومی چالش می‌فرستد، کلاینت با کلید خصوصی پاسخ می‌دهد. اگر تطابق داشت، وارد می‌شوی.

**در DevOps، SSH فقط “ورود” نیست:** Ansible از SSH استفاده می‌کند، Git از SSH استفاده می‌کند، CI/CD از SSH دیپلوی می‌کند. پس **امنیت SSH = امنیت کل زیرساخت**.

## بخش ۲: نصب و راه‌اندازی OpenSSH Server

### نصب
</div>


```bash
sudo apt update
sudo apt install openssh-server -y
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### فعال‌سازی و بررسی
</div>


```bash
sudo systemctl enable ssh
sudo systemctl status ssh
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


باید ببینی `active (running)`.

### ⚠️ نکته مهم Ubuntu 26.04: Socket Activation

در Ubuntu 26.04، SSH به صورت **Socket Activation** اجرا می‌شود. یعنی `ssh.socket` کنترل می‌کند SSH روی چه پورتی گوش می‌دهد، نه `sshd_config`.
</div>


```bash
systemctl status ssh.socket
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


اگر `active (listening)` دیدی، یعنی Socket Activation فعال است. این یعنی **اگر بعداً پورت SSH را عوض کردی، باید Socket را هم override کنی**، وگرنه تغییر اعمال نمی‌شود. برای تغییر پورت:
</div>


```bash
sudo systemctl edit ssh.socket
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


و داخلش:
</div>


```ini
[Socket]
ListenStream=
ListenStream=2222
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

بعد:
</div>


```bash
sudo systemctl daemon-reload
sudo systemctl restart ssh.socket
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### تست اتصال از ویندوز

از PowerShell یا CMD ویندوز:
</div>


```powershell
ssh devops@<IP-سرور-اوبونتو>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


IP سرور اوبونتو را با `ip addr` یا `hostname -I` پیدا کن.

## بخش ۳: احراز هویت با کلید (Key-Based Authentication)

این **مهم‌ترین بخش** است. بعد از این، ورود با رمز را غیرفعال می‌کنیم.

### مرحله ۱: تولید کلید روی کلاینت (ویندوز یا اوبونتو)

روی **کلاینتی** که می‌خواهی از آن وصل شوی:
</div>


```bash
ssh-keygen -t ed25519 -C "your_email@example.com"
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


- `-t ed25519`: الگوریتم توصیه‌شده ۲۰۲۶. امن، سریع و کلید کوتاه.
- `-C`: یک برچسب (ایمیل یا نام).

از رمز عبور (passphrase) استفاده کن. این رمز، کلید خصوصی را در صورت دزدیده شدن محافظت می‌کند.

خروجی:
</div>


```
~/.ssh/id_ed25519      ← کلید خصوصی (هرگز به کسی نده!)
~/.ssh/id_ed25519.pub  ← کلید عمومی (این را روی سرور می‌گذاری)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### مرحله ۲: کپی کلید عمومی به سرور
</div>


```bash
ssh-copy-id devops@<IP-سرور>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


رمز سرور را می‌پرسد. بعد از این، کلید در `~/.ssh/authorized_keys` سرور قرار می‌گیرد.

اگر `ssh-copy-id` روی ویندوز نبود، دستی انجام بده:
</div>


```bash
# روی کلاینت
cat ~/.ssh/id_ed25519.pub
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


سپس روی سرور:
</div>


```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "محتوای-کلید-عمومی-را-اینجا-بچسبان" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### مرحله ۳: تست ورود بدون رمز
</div>


```bash
ssh devops@<IP-سرور>
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


اگر رمز سرور را نپرسید، موفق شدی. (ممکن است رمز کلید خصوصی را بپرسد که طبیعی است.)

### ⚠️ مجوزهای دقیق (SSH خیلی سختگیر است)

SSH اگر مجوزها درست نباشند، کلید را رد می‌کند:
</div>


```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
chmod 600 ~/.ssh/id_ed25519       # کلید خصوصی
chmod 644 ~/.ssh/id_ed25519.pub   # کلید عمومی
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


اگر `Permission denied (publickey)` گرفتی، اول این مجوزها را چک کن.

## بخش ۴: سخت‌سازی `sshd_config`

حالا که کلید کار می‌کند، ورود با رمز را می‌بندیم. **قبل از این مرحله مطمئن شو که با کلید وارد می‌شوی**، وگرنه قفل می‌شوی.

### بهترین روش: فایل Drop-in جداگانه

به جای ویرایش `/etc/ssh/sshd_config`، یک فایل جداگانه در `/etc/ssh/sshd_config.d/` بساز. این روش تمیزتر است و با آپدیت‌ها بازنویسی نمی‌شود:
</div>


```bash
sudo nano /etc/ssh/sshd_config.d/00-hardening.conf
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


محتوای پیشنهادی برای Production:
</div>


```ini
# غیرفعال کردن ورود مستقیم root
PermitRootLogin no

# فقط احراز هویت با کلید
PubkeyAuthentication yes
PasswordAuthentication no
PermitEmptyPasswords no
ChallengeResponseAuthentication no
KbdInteractiveAuthentication no

# محدود کردن کاربران مجاز
AllowUsers devops ali sara

# محدود کردن تلاش‌های احراز هویت
MaxAuthTries 3
MaxSessions 10

# timeout برای جلوگیری از sessionهای فراموش‌شده
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2

# غیرفعال کردن forwarding های غیرضروری (اگر لازم نداری)
X11Forwarding no
AllowAgentForwarding no
AllowTcpForwarding no
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**توضیح هر خط:**
</div>
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">



| تنظیم | چرا؟ |
|---|---|
| `PermitRootLogin no` | هیچ‌کس مستقیم با root وارد نشود؛ از `sudo` استفاده کن |
| `PasswordAuthentication no` | حملات brute-force روی رمز کاملاً بسته می‌شود |
| `AllowUsers` | حتی اگر کسی کلید داشته باشد، فقط این کاربران وارد شوند |
| `MaxAuthTries 3` | بعد از ۳ تلاش اشتباه، اتصال قطع می‌شود |
| `ClientAliveInterval` | session بی‌استفاده خودکار بسته می‌شود |

</div>


<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### اعمال تغییرات
</div>


```bash
sudo sshd -t    # چک کردن syntax (بسیار مهم!)
sudo systemctl restart ssh
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


`sshd -t` اگر خطا داشت، هرگز restart نکن. وگرنه SSH را از دست می‌دهی.

### ⚠️ قانون طلایی

**هرگز جلسه SSH فعلی را نبند** تا وقتی که در یک **جلسه جدید** مطمئن شوی ورود با کلید کار می‌کند. اگر قفل شدی، باید از کنسول فیزیکی سرور وارد شوی.

### بررسی تنظیمات اعمال‌شده

</div>


```bash
sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication|maxauthtries|allowusers'
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


این خروجی **تنظیمات واقعی** را نشان می‌دهد، نه فقط فایل را.

## بخش ۵: فایل `~/.ssh/config` — میان‌بر برای اتصال

اگر سرورهای زیادی داری، هر بار تایپ `ssh -p 2222 -i ~/.ssh/key devops@192.168.1.100` خسته‌کننده است. فایل `~/.ssh/config` این را حل می‌کند:

</div>


```bash
nano ~/.ssh/config
```

```ini
Host myserver
    HostName 192.168.1.100
    User devops
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60

Host prod-web
    HostName web01.prod.example.com
    User deploy
    Port 2222
    IdentityFile ~/.ssh/prod_key
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


بعد از این فقط می‌زنی:
</div>


```bash
ssh myserver
ssh prod-web
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**مزیت:** Alias، پورت، کلید و کاربر همه در یک جا. مجوز فایل باید `600` باشد:
</div>


```bash
chmod 600 ~/.ssh/config
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## بخش ۶: SSH Agent و Agent Forwarding

### ssh-agent چیست؟



`ssh-agent` کلید خصوصی را در حافظه نگه می‌دارد. یک بار passphrase را می‌زنی، بعد از آن agent به جای تو پاسخ می‌دهد:
</div>

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


بعد از این، تا وقتی agent زنده است، passphrase نمی‌پرسد.

### Agent Forwarding — برای پرش از سرور میانی

سناریو: از لپ‌تاپ به Bastion (سرور میانی) وصل می‌شوی، و از Bastion می‌خواهی به سرور داخلی وصل شوی. اگر کلید خصوصی را روی Bastion کپی نکنی، Agent Forwarding کمک می‌کند:
</div>


```bash
ssh -A devops@bastion
# حالا از داخل bastion:
ssh internal-server
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">



`-A` یعنی agent را forward کن.

**⚠️ هشدار امنیتی:** هر پروسه‌ای که روی سرور میانی اجرا می‌شود، می‌تواند از agent تو برای امضای احراز هویت استفاده کند. فقط روی سرورهایی که کاملاً به آن‌ها اعتماد داری `ForwardAgent yes` بگذار. برای Git یا پرش به سرور بعدی خوب است، برای همه‌چیز نه.

در `~/.ssh/config`:
</div>


```ini
Host bastion
    HostName bastion.example.com
    User devops
    ForwardAgent yes
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## بخش ۷: Port Forwarding — تانل SSH

سه نوع تانل داریم که در DevOps حیاتی‌اند:

### ۱. Local Forwarding (`-L`)

**سناریو:** دیتابیس روی سرور دور روی پورت 5432 است و از بیرون قابل دسترسی نیست. می‌خواهی از لپ‌تاپ به آن وصل شوی.
</div>


```bash
ssh -L 5433:localhost:5432 devops@db-server
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


حالا روی لپ‌تاپ به `localhost:5433` وصل شو، به دیتابیس سرور دور وصل می‌شوی.

**فرمول:** `ssh -L [پورت-محلی]:[میزبان-مقصد]:[پورت-مقصد] user@ssh-server`

**کاربرد:** دسترسی به دیتابیس، وب‌اپ داخلی، Redis، هر سرویسی که پشت فایروال است.

### ۲. Remote Forwarding (`-R`)

**سناریو:** یک سرویس روی لپ‌تاپ داری (مثلاً webhook در حال توسعه) و می‌خواهی سرور دور به آن دسترسی داشته باشد.
</div>


```bash
ssh -R 8080:localhost:3000 devops@public-server
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


حالا هر کسی به `public-server:8080` وصل شود، به `localhost:3000` لپ‌تاپ تو می‌رسد.

**کاربرد:** تست webhook، دسترسی به سرویس محلی از بیرون، معکوس Local.

### ۳. Dynamic Forwarding (`-D`)

یک **SOCKS proxy** روی پورت محلی می‌سازد. همه ترافیک TCP از آن رد می‌شود:
</div>


```bash
ssh -D 1080 devops@ssh-server
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


حالا در مرورگر یا برنامه، SOCKS proxy را روی `localhost:1080` تنظیم کن. ترافیک از سرور SSH رد می‌شود.

**کاربرد:** مرور امن از شبکه ناامن، دسترسی به سرویس‌های محدود به IP، تست geo.

### خلاصه سه نوع تانل

| نوع | فلگ | جهت | کاربرد |
|---|---|---|---|
| Local | `-L` | از لپ‌تاپ به سرور دور | دسترسی به دیتابیس/سرویس داخلی |
| Remote | `-R` | از سرور دور به لپ‌تاپ | وب‌هوک، سرویس محلی |
| Dynamic | `-D` | SOCKS proxy | مرور امن، دور زدن محدودیت |

## بخش ۸: عیب‌یابی SSH

### خطاهای رایج

| خطا | علت | راه‌حل |
|---|---|---|
| `Connection refused` | SSH نصب/فعال نیست یا پورت اشتباه | `systemctl status ssh`، `ss -tulnp \| grep :22` |
| `Permission denied (publickey)` | کلید عمومی روی سرور نیست یا مجوز غلط | `~/.ssh/authorized_keys` و مجوزها را چک کن |
| `Permission denied (password)` | رمز اشتباه یا `PasswordAuthentication no` | رمز یا تنظیمات `sshd_config` را چک کن |
| `Host key verification failed` | اثر انگشت سرور عوض شده | `ssh-keygen -R <host>` و دوباره وصل شو |
| `Too many authentication failures` | agent کلیدهای زیادی دارد | `ssh -o IdentitiesOnly=yes -i ~/.ssh/key user@host` |

### ابزارهای دیباگ
</div>


```bash
# لاگ SSH روی سرور
sudo journalctl -u ssh -f
sudo tail -f /var/log/auth.log

# دیباگ سمت کلاینت
ssh -vvv devops@server

# چه چیزی روی پورت 22 گوش می‌دهد؟
sudo ss -tulnp | grep :22

# فایروال
sudo ufw status verbose
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### فعال کردن لاگ بیشتر روی سرور (موقت)

در `sshd_config`:
</div>


```ini
LogLevel VERBOSE
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


بعد `sudo systemctl restart ssh`. در `auth.log` می‌بینی کدام کلید و کدام کاربر تلاش کرده.

## بخش ۹: فایروال (UFW) برای SSH

اگر UFW فعال است، باید پورت SSH را باز کنی:
</div>


```bash
sudo ufw allow 22/tcp
# یا اگر پورت عوض کردی:
sudo ufw allow 2222/tcp

sudo ufw enable
sudo ufw status verbose
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**⚠️ قبل از `ufw enable`** مطمئن شو پورت SSH باز است، وگرنه قفل می‌شوی.

## پروژه جلسه ۴

**سناریو:** یک سرور Production-ready SSH بساز.

1. OpenSSH را نصب و enable کن.
2. روی کلاینت کلید `ed25519` بساز.
3. کلید را به سرور کپی کن و ورود بدون رمز را تست کن.
4. فایل `/etc/ssh/sshd_config.d/00-hardening.conf` را با این تنظیمات بساز:
    - `PermitRootLogin no`
    - `PasswordAuthentication no`
    - `MaxAuthTries 3`
    - `AllowUsers` شامل کاربر خودت
5. `sshd -t` و restart.
6. در **جلسه جدید** تست کن:
    - ورود با کلید: ✅
    - ورود با رمز: ❌
    - ورود root: ❌
7. فایل `~/.ssh/config` با alias `myserver` بساز.
8. یک تانل Local بزن و از لپ‌تاپ به سرویس سرور وصل شو.
9. خروجی `sudo sshd -T | grep -E 'permitrootlogin|passwordauthentication|maxauthtries|allowusers'` را ذخیره کن.

## اشتباهات رایج (این‌ها را نکن!)

| ❌ اشتباه | ✅ درست |
|---|---|
| `PasswordAuthentication no` قبل از تست کلید | اول کلید را تست کن، بعد رمز را ببند |
| ویرایش `/etc/ssh/sshd_config` مستقیم | فایل drop-in در `sshd_config.d/` |
| restart بدون `sshd -t` | همیشه اول syntax را چک کن |
| `chmod 644` روی کلید خصوصی | `600` روی کلید خصوصی، `644` روی `.pub` |
| `ForwardAgent yes` برای همه سرورها | فقط برای Bastion یا Git |
| کپی کلید خصوصی روی سرور | هرگز! کلید خصوصی فقط روی کلاینت |
| باز کردن پورت 22 برای همه در Production | `AllowUsers` + Fail2Ban + تغییر پورت |

## ارتباط با جلسات قبلی

- **جلسه ۳ (کاربران):** `AllowUsers` از همان `/etc/passwd` می‌خواند. کاربرانی که در جلسه ۳ ساختی، همان‌ها می‌توانند SSH بزنند (اگر در `AllowUsers` باشند).
- **جلسه ۲ (مجوزها):** مجوز `600` روی کلید خصوصی و `700` روی `~/.ssh` دقیقاً همان چیزی است که در جلسه ۲ یاد گرفتی.
- **جلسه ۵ (Bash Scripting):** اسکریپت‌هایی که می‌نویسی، از SSH برای اجرا روی سرورهای دور استفاده می‌کنند.
