## بخش ۱: چهار فایل مهم که باید بشناسی

قبل از هر دستوری، این چهار فایل را بشناس. همه چیز در لینوکس درباره کاربران از این‌ها می‌آید:

| فایل | محتوا | دسترسی |
|---|---|---|
| `/etc/passwd` | اطلاعات پایه همه کاربران | همه می‌خوانند |
| `/etc/shadow` | هش رمز عبور | فقط root |
| `/etc/group` | گروه‌ها و اعضا | همه می‌خوانند |
| `/etc/gshadow` | رمز گروه‌ها | فقط root |

| `1000+` | کاربران عادی (اولین کاربر انسانی `1000` است) |

## بخش ۳: ساخت کاربر با `useradd` و `adduser`

### تفاوت `useradd` و `adduser`

| دستور | نوع | کاربرد |
|---|---|---|
| `adduser` | اسکریپت پایتون (فقط Debian/Ubuntu) | تعاملی، راحت |
| `useradd` | باینری سیستمی | اسکریپتی، در همه توزیع‌ها |

**برای DevOps:** `useradd` مهم‌تر است چون در همه توزیع‌ها هست و در اسکریپت‌ها استفاده می‌شود.

### ساخت کاربر ساده با `adduser`

```bash
sudo adduser ali
```

سوال می‌پرسد: رمز، نام کامل، شماره اتاق و... می‌توانی `Enter` بزنی.

این دستور خودش:
- کاربر می‌سازد
- پوشه home می‌سازد
- فایل‌های `/etc/skel` را کپی می‌کند (شامل `.bashrc`)
- رمز تنظیم می‌کند
- گروه همنام می‌سازد

### ساخت کاربر با `useradd` (کنترل کامل)

```bash
sudo useradd -m -s /bin/bash -c "Sara Ahmadi" sara
sudo passwd sara
```

گزینه‌ها:

| گزینه | معنا |
|---|---|
| `-m` | ساخت پوشه home |
| `-M` | **نساختن** پوشه home (پیش‌فرض در بعضی توزیع‌ها) |
| `-s /bin/bash` | shell پیش‌فرض |
| `-s /usr/sbin/nologin` | کاربر نمی‌تواند لاگین کند (برای سرویس‌ها) |
| `-c "توضیح"` | توضیح/نام کامل |
| `-d /path` | مسیر home سفارشی |
| `-u 1500` | UID دستی |
| `-g group` | GID اصلی |
| `-G group1,group2` | گروه‌های اضافه |
| `-e 2026-12-31` | تاریخ انقضا |
| `-r` | کاربر سیستمی (UID < 1000) |

### ⚠️ نکته مهم درباره `useradd` بدون `-m`

اگر `-m` را نزنی، پوشه home ساخته **نمی‌شود** و کاربر بعداً مشکل دارد. همیشه `-m` بزن.

### مثال‌های واقعی DevOps

**کاربر سرویس (بدون shell، بدون home):**

```bash
sudo useradd -r -s /usr/sbin/nologin -M appuser
```

این برای اجرای یک سرویس (مثل Nginx یا یک اپلیکیشن) عالی است.

**کاربر با تاریخ انقضا (برای کارمند موقت):**

```bash
sudo useradd -m -s /bin/bash -e 2026-12-31 tempuser
sudo passwd tempuser
```

بعد از تاریخ، حساب خودکار قفل می‌شود.

**کاربر با UID مشخص (برای هماهنگی بین سرورها):**

```bash
sudo useradd -m -u 1500 -s /bin/bash deploy
```

## بخش ۴: تغییر کاربر با `usermod`

`usermod` برای ویرایش کاربر موجود است.

### تغییر shell

```bash
sudo usermod -s /bin/zsh devops
```

### اضافه کردن به گروه

```bash
sudo usermod -aG docker devops
```

**⚠️ نکته حیاتی:** همیشه `-aG` با `a`. اگر `-G` تنها بزنی، **همه گروه‌های قبلی حذف می‌شوند** و فقط گروه جدید می‌ماند. اشتباه رایج و خطرناک!

```bash
# ❌ اشتباه: همه گروه‌های قبلی پاک می‌شوند
sudo usermod -G docker devops

# ✅ درست: گروه جدید اضافه می‌شود
sudo usermod -aG docker devops
```

### تغییر نام کاربری

```bash
sudo usermod -l newname oldname
```

### قفل کردن حساب

```bash
sudo usermod -L devops    # Lock
sudo usermod -U devops    # Unlock
```

### قفل با `passwd`

```bash
sudo passwd -l devops
sudo passwd -u devops
```

### تغییر پوشه home

```bash
sudo usermod -d /new/home -m devops
```

`-m` محتویات را هم منتقل می‌کند.

## بخش ۵: حذف کاربر با `userdel`

```bash
sudo userdel ali
```

این کاربر را حذف می‌کند ولی **پوشه home را نگه می‌دارد**.

حذف کامل (با home و mail):

```bash
sudo userdel -r ali
```

**⚠️ هشدار:** `-r` پوشه home را پاک می‌کند. قبل از این کار مطمئن شو که فایل مهمی داخلش نیست.

### قبل از حذف، همیشه چک کن

```bash
# آیا کاربر الان لاگین است؟
who | grep ali

# آیا پروسه‌ای با این کاربر در حال اجراست؟
ps -u ali

# فایل‌های مالکیت‌شده توسط کاربر
find / -user ali 2>/dev/null | head
```

اگر کاربر لاگین است:

```bash
sudo pkill -KILL -u ali
sudo userdel -r ali
```

## بخش ۶: مدیریت رمز عبور با `passwd` و `chage`

### `passwd`

```bash
# کاربر خودش رمزش را عوض کند
passwd

# root رمز کاربر دیگر را تنظیم کند
sudo passwd ali

# قفل کردن
sudo passwd -l ali

# باز کردن
sudo passwd -u ali

# منقضی کردن رمز (کاربر باید بار بعد عوض کند)
sudo passwd -e ali
```

### `chage` — سیاست انقضای رمز

```bash
sudo chage -l ali
```

خروجی:

```
Last password change      : Oct 20, 2026
Password expires          : never
Password inactive         : never
Account expires           : never
Minimum number of days between password change  : 0
Maximum number of days between password change  : 99999
```

تنظیم انقضای رمز هر ۹۰ روز:

```bash
sudo chage -M 90 ali
```

اجبار به تغییر رمز در لاگین بعدی:

```bash
sudo chage -d 0 ali
```

تنظیم تاریخ انقضای حساب:

```bash
sudo chage -E 2026-12-31 ali
```

**در محیط‌های Production** این تنظیمات در `/etc/login.defs` تنظیم می‌شوند (سیاست‌های پیش‌فرض همه کاربران).

## بخش ۷: مدیریت گروه‌ها

### `groupadd`

```bash
sudo groupadd devs
sudo groupadd -g 1500 devops-team   # با GID مشخص
sudo groupadd -r sysgroup            # گروه سیستمی
```

### `groupmod`

```bash
sudo groupmod -n newname oldname     # تغییر نام
sudo groupmod -g 1600 devs           # تغییر GID
```

### `groupdel`

```bash
sudo groupdel devs
```

**⚠️ نکته:** اگر گروه، گروه اصلی یک کاربر باشد، نمی‌توانی حذفش کنی.

### `gpasswd` — مدیریت اعضای گروه

`gpasswd` جایگزین مدرن `adduser` برای گروه‌هاست:

```bash
# اضافه کردن کاربر به گروه
sudo gpasswd -a ali devs

# حذف کاربر از گروه
sudo gpasswd -d ali devs

# تعیین لیست کامل اعضا (⚠️ جایگزین می‌شود)
sudo gpasswd -M ali,sara,reza devs
```

### `newgrp` — فعال کردن گروه جدید بدون logout

وقتی به گروه جدیدی اضافه می‌شوی، تغییرات در جلسه فعلی اعمال نمی‌شود. دو راه:

```bash
# راه ۱: logout و دوباره login کن
exit
# (دوباره login کن)

# راه ۲: newgrp
newgrp devs
```

`newgrp` یک shell جدید با گروه جدید باز می‌کند.

## بخش ۸: `sudo` — دسترسی مدیریتی

### sudo چطور کار می‌کند؟

- فایل تنظیمات: `/etc/sudoers`
- دایرکتوری اضافه: `/etc/sudoers.d/`
- **هرگز مستقیم `/etc/sudoers` را با `nano` ویرایش نکن!** همیشه با `visudo`.

### `visudo` چرا؟

`visudo` قبل از ذخیره، syntax را چک می‌کند. اگر خطایی باشد، جلوی ذخیره را می‌گیرد. بدون `visudo`، اگر syntax غلط بنویسی، **کاملاً دسترسی sudo را از دست می‌دهی** و باید با recovery mode درست کنی.

```bash
sudo visudo
```

### ساختار خط در `/etc/sudoers`

```
who      where=(as_who)   what
ali      ALL=(ALL:ALL)    ALL
```

- `who`: کاربر یا `%group`
- `where`: از کدام host (معمولاً `ALL`)
- `(as_who)`: با اختیارات چه کسی (معمولاً `ALL`)
- `what`: چه دستوراتی

### مثال‌های پرکاربرد

```bash
# کاربر ali همه‌چیز با sudo (مثل root)
ali ALL=(ALL:ALL) ALL

# گروه devops همه‌چیز با sudo
%devops ALL=(ALL:ALL) ALL

# بدون پرسیدن رمز (⚠️ خطرناک، فقط برای automation)
devops ALL=(ALL) NOPASSWD: ALL

# فقط دستورات خاص
ali ALL=(ALL) /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# با NOPASSWD برای دستورات خاص (خوب برای CI/CD)
jenkins ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart myapp, /usr/bin/docker
```

### بهترین روش: فایل جدا در `/etc/sudoers.d/`

همیشه به جای ویرایش `/etc/sudoers`، یک فایل جدا بساز:

```bash
sudo visudo -f /etc/sudoers.d/devops-team
```

داخلش:

```
%devops ALL=(ALL:ALL) ALL
```

**مزیت:** مدیریت راحت‌تر، جداسازی، راحت پاک کردن.

**نکته:** نام فایل نباید `.` یا `~` داشته باشد، وگرنه نادیده گرفته می‌شود.

### `sudo -l` — چه دسترسی‌هایی دارم؟

```bash
sudo -l
```

خروجی نشان می‌دهد چه دستوراتی می‌توانی اجرا کنی.

```bash
sudo -l -U ali    # بررسی sudo کاربر دیگر
```

### `sudo -i` vs `sudo su` vs `sudo -s`

| دستور | چه می‌کند |
|---|---|
| `sudo su -` | shell کامل root (محیط root، پوشه home root) |
| `sudo -i` | معادل `sudo su -` |
| `sudo -s` | shell root ولی محیط کاربر فعلی |
| `su -` | نیاز به رمز root دارد |
| `su` | shell root ولی نه pwd عوض می‌شود نه محیط |

**برای کار معمولی `sudo` کافی است.** `sudo -i` فقط وقتی لازم است که کارهای زیادی پشت سرهم با root داری.

### `sudo -u` — اجرای دستور با کاربر دیگر

```bash
sudo -u www-data whoami
sudo -u postgres psql
```

این در DevOps خیلی مهم است — مثلاً برای اجرای یک backup با کاربر دیتابیس.

## بخش ۹: امنیت کاربران — چک‌لیست

چند چیز که هر DevOps باید بداند:

### ۱. کاربر root را غیرفعال نکن، ولی ازش استفاده نکن

به جای root، همیشه با `sudo` کار کن. root فقط برای کارهای ضروری.

### ۲. رمز root را قفل کن (اگر از sudo استفاده می‌کنی)

```bash
sudo passwd -l root
```

بعد از این، نمی‌توانی با `su -` وارد شوی، ولی `sudo` کار می‌کند.

### ۳. کاربران سیستمی shell نداشته باشند

کاربران سیستمی (مثل `www-data`, `postgres`) نباید بتوانند login کنند:

```bash
getent passwd www-data
# باید /usr/sbin/nologin یا /bin/false داشته باشد
```

### ۴. کاربرانی که نباید shell داشته باشند

```bash
sudo usermod -s /usr/sbin/nologin baduser
```

### ۵. لیست کاربران با UID 0 (فقط root باید باشد)

```bash
awk -F: '$3==0 {print $1}' /etc/passwd
```

اگر بیش از یک نفر بود، **مشکل امنیتی جدی**.

### ۶. کاربران بدون رمز

```bash
sudo awk -F: '($2=="") {print $1}' /etc/shadow
```

اگر خروجی داشت، خطرناک.

### ۷. کاربران بدون مالک (orphan)

```bash
find / -nouser -o -nogroup 2>/dev/null | head
```

اگر کاربری حذف شده و فایل‌هایش مانده، اینجا پیدا می‌شوند.

### ۸. لاگ sudo

```bash
sudo journalctl -u sudo -n 20
# یا
sudo grep sudo /var/log/auth.log | tail
```

## بخش ۱۰: آزمایشگاه عملی — سناریوی واقعی

**سناریو:** یک سرور web داری. تیم توسعه نیاز دارد که:

- کاربران `ali`, `sara`, `reza` بسازی

```bash

sudo useradd -m -s /bin/bash -c "Sara Ahmadi" sara
sudo useradd -m -s /bin/bash -c "Reza Karimi" reza
sudo useradd -r -s /usr/sbin/nologin -M deploy

# رمزها
sudo passwd ali
sudo passwd sara
sudo passwd reza
# deploy رمز ندارد (کاربر سرویس است)
```

### مرحله ۲: ساخت گروه و اضافه کردن اعضا

```bash
sudo groupadd devs
sudo usermod -aG devs ali
sudo usermod -aG devs sara
sudo usermod -aG devs reza

# بررسی
getent group devs
```

### مرحله ۳: تنظیم sudo برای هر کدام

```bash
sudo visudo -f /etc/sudoers.d/devops-team
```

داخلش:

```
# Ali: فقط restart و status nginx
ali ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx, /usr/bin/systemctl status nginx

# Sara: فقط خواندن لاگ‌ها
sara ALL=(ALL) /usr/bin/journalctl, /usr/bin/tail, /usr/bin/cat /var/log/*

# Reza: sudo کامل با رمز
reza ALL=(ALL:ALL) ALL

# Deploy: فقط اسکریپت deploy
deploy ALL=(ALL) NOPASSWD: /usr/local/bin/deploy.sh
```

### مرحله ۴: تست

```bash
# به عنوان ali (در یک terminal دیگر یا با su)
sudo -u ali sudo -l
# باید فقط systemctl restart nginx ببینی

# تست دستور مجاز
sudo -u ali sudo systemctl status nginx

# تست دستور غیرمجاز (باید رد شود)
sudo -u ali sudo ls /root
```

## بخش ۱۱: نکات پیشرفته

### اجرای دستور با محیط کاربر دیگر

```bash
sudo -u ali -i
# یا
sudo -u ali bash -c "echo $HOME"
```

### دیدن تمام کاربران انسانی (UID >= 1000)

```bash
awk -F: '$3 >= 1000 && $3 < 65000 {print $1, $3, $7}' /etc/passwd
```

### پیدا کردن کاربرانی که shell دارند

```bash
getent passwd | grep -vE "nologin|false" | cut -d: -f1,7
```

### چک کردن عضویت در گروه

```bash
id -nG ali | grep -qw devs && echo "عضو است" || echo "عضو نیست"
```

این idiom در اسکریپت‌ها زیاد استفاده می‌شود.

### تغییر گروه اصلی کاربر

```bash
sudo usermod -g newgroup ali
```

این `-g` (کوچک) است و GID اصلی را عوض می‌کند. با `-G` (بزرگ) اشتباه نگیر.

## پروژه جلسه ۳

**سناریو:** سرور تیم را آماده کن.

مراحل:

```bash
# ۱. سه کاربر بساز: alice, bob, charlie (با -m -s)
sudo useradd -m -s /bin/bash alice
sudo useradd -m -s /bin/bash bob
sudo useradd -m -s /bin/bash charlie

# ۲. رمز تعیین کن
sudo passwd alice
sudo passwd bob
sudo passwd charlie

# ۳. گروه ops بساز
sudo groupadd ops

# ۴. alice و bob را به ops اضافه کن
sudo usermod -aG ops alice
sudo usermod -aG ops bob

# ۵. charlie را به گروه sudo اضافه کن (sudo کامل)
sudo usermod -aG sudo charlie

# ۶. alice را به گروه docker اضافه کن (اگر docker نصب است)
# sudo usermod -aG docker alice

# ۷. بررسی کن
id alice
id bob
id charlie
getent group ops

# ۸. یک کاربر سرویس بساز
sudo useradd -r -s /usr/sbin/nologin -M appuser

# ۹. بررسی کن کاربر سرویس نمی‌تواند login کند
sudo -u appuser bash    # باید خطا بدهد
```

**سوالات پاسخ بده:**

1. `id alice` چه می‌گوید؟ کدام گروه‌ها را دارد؟
2. بعد از اضافه کردن `alice` به `ops`، اگر در همان terminal `groups alice` بزنی، `ops` را می‌بینی؟
3. `sudo -l -U charlie` چه می‌گوید؟
4. خروجی `awk -F: '$3==0 {print $1}' /etc/passwd` چیست؟
5. چرا `appuser` نمی‌تواند login کند؟

## چک‌لیست پایان جلسه ۳

- [ ] `/etc/passwd` را می‌خوانم و ۷ فیلدش را می‌شناسم
- [ ] `/etc/shadow` و `/etc/group` را می‌فهمم
- [ ] با `useradd` (و `-m -s -c -e -r`) کاربر می‌سازم
- [ ] با `usermod -aG` کاربر به گروه اضافه می‌کنم (و می‌دانم چرا `a` حیاتی است)
- [ ] با `userdel -r` کاربر را کامل حذف می‌کنم
- [ ] با `passwd` و `chage` رمز و انقضا را مدیریت می‌کنم
- [ ] با `groupadd`, `groupmod`, `gpasswd` گروه‌ها را مدیریت می‌کنم
- [ ] فایل `/etc/sudoers.d/` می‌سازم و `visudo` بلدم
- [ ] تفاوت `sudo`, `sudo -i`, `sudo -u` را می‌دانم
- [ ] کاربر سرویس با `nologin` می‌سازم
- [ ] چک‌لیست امنیتی (UID 0، رمز خالی، nologin) را بلدم

## اشتباهات رایج (این‌ها را نکن!)

| ❌ اشتباه | ✅ درست |
|---|---|
| `usermod -G group user` | `usermod -aG group user` |
| `useradd user` بدون `-m` | `useradd -m user` |
| ویرایش `/etc/sudoers` با nano | `visudo` |
| `chmod 777` برای حل مشکل | مجوز/مالکیت را درست کن |
| حذف کاربر با `userdel` بدون `-r` | `userdel -r` (اگر واقعاً پاک می‌خواهی) |
| رمز دادن به کاربر سرویس | `nologin` + بدون رمز |
| اضافه کردن به sudo بدون محدودیت | `NOPASSWD` فقط برای دستور خاص |

## ارتباط با جلسات قبلی و بعدی

- **جلسه ۲ (مجوزها):** حالا می‌دانی چرا `chown root:devs /srv/devshare` کار می‌کند — چون گروه `devs` را ساختی.
- **جلسه ۴ (SSH):** کاربران روی سرور SSH همان کاربران لینوکس هستند. SSH با همین `/etc/passwd` احراز هویت می‌کند. در جلسه بعد، SSH را طوری می‌بندیم که فقط برخی کاربران (با `AllowUsers`) دسترسی داشته باشند.
