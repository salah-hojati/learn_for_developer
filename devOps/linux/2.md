# جلسه ۲: مجوزها و مالکیت در لینوکس

**هدف:** در پایان این جلسه بتوانی بخوانی چه کسی به چه فایلی چه دسترسی‌ای دارد و آن را دقیقاً همان‌طور که می‌خواهی تغییر بدهی.

## بخش ۱: خواندن خروجی `ls -l`

اول برو به پوشه lab:
</div>

```bash
cd ~/linux-course/session1
ls -l
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

خروجی چیزی شبیه این است:
</div>

```
-rw-r--r-- 1 devops devops  12 Oct 20 10:00 a.txt
drwxr-xr-x 2 devops devops 4096 Oct 20 10:00 backup
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

بیایید اولین فایل را تجزیه کنیم:

</div>

```
-rw-r--r--   1   devops   devops   12   Oct 20 10:00   a.txt
│└┬┘└┬┘└┬┘   │   └──┬──┘  └──┬──┘   │         │          │
│ │  │  │    │      │        │      │         │          └─ نام فایل
│ │  │  │    │      │        │      │         └─ تاریخ آخرین تغییر
│ │  │  │    │      │        │      └─ اندازه به بایت
│ │  │  │    │      │        └─ گروه مالک
│ │  │  │    │      └─ کاربر مالک
│ │  │  │    └─ تعداد Hard Link ها
│ │  │  └─ مجوز سایر کاربران (Others)
│ │  └─ مجوز گروه (Group)
│ └─ مجوز مالک (User/Owner)
└─ نوع فایل
```

<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

### نوع فایل (کاراکتر اول)

| کاراکتر | معنا |
|---|---|
| `-` | فایل معمولی |
| `d` | دایرکتوری (پوشه) |
| `l` | لینک نمادین (Soft Link) |
| `c` | دستگاه کاراکتری (مثل `/dev/tty`) |
| `b` | دستگاه بلوکی (مثل `/dev/sda`) |
| `s` | Socket |
| `p` | Named Pipe |

### سه گروه مجوز

هر فایل سه گروه دسترسی دارد:

| گروه | نماد | یعنی چه کسی |
|---|---|---|
| **User (مالک)** | `u` | کاربری که مالک فایل است |
| **Group** | `g` | اعضای گروه مالک فایل |
| **Others** | `o` | بقیه کاربران سیستم |

و هر گروه سه مجوز دارد:

| مجوز | نماد | عدد | روی فایل | روی پوشه |
|---|---|---|---|---|
| **Read** | `r` | 4 | خواندن محتوا | لیست کردن محتویات (`ls`) |
| **Write** | `w` | 2 | تغییر محتوا | ساخت/حذف فایل داخلش |
| **Execute** | `x` | 1 | اجرا کردن | ورود به پوشه (`cd`) |

## بخش ۲: سه روش نمایش مجوز

### روش ۱: نمادی (Symbolic)
</div>

```
-rwxr-xr-- 
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

یعنی:
- مالک: `rwx` (خواندن، نوشتن، اجرا)
- گروه: `r-x` (خواندن، اجرا)
- بقیه: `r--` (فقط خواندن)

### روش ۲: عددی (Octal)

هر سه‌تایی را جمع می‌زنیم:

| نماد | عدد |
|---|---|
| `rwx` | 4+2+1 = **7** |
| `rw-` | 4+2+0 = **6** |
| `r-x` | 4+0+1 = **5** |
| `r--` | 4+0+0 = **4** |
| `-wx` | 0+2+1 = **3** |
| `-w-` | 0+2+0 = **2** |
| `--x` | 0+0+1 = **1** |
| `---` | 0+0+0 = **0** |

پس `rwxr-xr--` می‌شود **754**.

### روش ۳: `stat`

</div>

```bash
stat a.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

خروجی شامل `Access: (0644/-rw-r--r--)` است.

## بخش ۳: جدول مرجع مجوزهای پرکاربرد
</div>

| عدد | نمادی | کاربرد رایج |
|---|---|---|
| `644` | `rw-r--r--` | فایل معمولی (فقط مالک می‌نویسد) |
| `600` | `rw-------` | فایل خصوصی (مثلاً کلید SSH) |
| `755` | `rwxr-xr-x` | اسکریپت یا پوشه عمومی |
| `700` | `rwx------` | پوشه خصوصی |
| `640` | `rw-r-----` | فایل مشترک گروه |
| `775` | `rwxrwxr-x` | پوشه مشترک گروه |
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**قانون سرانگشتی:**
- فایل: `644` یا `600`
- پوشه: `755` یا `700`
- اسکریپت: `755`

## بخش ۴: تغییر مجوز با `chmod`

### روش عددی
</div>

```bash
cd ~/linux-course/session1
touch perm-test.txt
ls -l perm-test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


خروجی معمولاً `-rw-r--r--` است (یعنی 644).

تغییر به `600`:
</div>

```bash
chmod 600 perm-test.txt
ls -l perm-test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

حالا `-rw-------`.

تغییر به `755`:
</div>

```bash
chmod 755 perm-test.txt
ls -l perm-test.txt
```

<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


حالا `-rwxr-xr-x`.

### روش نمادی

| دستور | معنا |
|---|---|
| `chmod u+x file` | به مالک مجوز اجرا بده |
| `chmod g+w file` | به گروه مجوز نوشتن بده |
| `chmod o-r file` | از بقیه مجوز خواندن بگیر |
| `chmod a+r file` | به همه مجوز خواندن بده |
| `chmod u=rwx,g=rx,o= file` | مساوی قرار بده |
| `chmod -R 755 dir/` | بازگشتی روی کل پوشه |

حروف:
- `u` = user
- `g` = group
- `o` = others
- `a` = all (همه)

عملگرها:
- `+` = اضافه کن
- `-` = بگیر
- `=` = دقیقاً برابر قرار بده

**تمرین ۱:**

</div>

```bash
cd ~/linux-course/session1
touch test1.txt test2.txt
chmod 600 test1.txt
chmod u+x test2.txt
ls -l test1.txt test2.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## بخش ۵: مالکیت با `chown` و `chgrp`

### دیدن مالک فعلی
</div>

```bash
ls -l perm-test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


ستون‌های ۳ و ۴: کاربر مالک و گروه مالک.

### `chown` — تغییر مالک
</div>

```bash
sudo chown root perm-test.txt
ls -l perm-test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

حالا مالک `root` شده.

### تغییر همزمان مالک و گروه
</div>

```bash
sudo chown root:root perm-test.txt
```

<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

### `chgrp` — فقط تغییر گروه
</div>

```bash
sudo chgrp sudo perm-test.txt
ls -l perm-test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### بازگشتی
</div>

```bash
sudo chown -R devops:devops ~/linux-course
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**نکته مهم:** برای تغییر مالک باید `sudo` داشته باشی (چون مالک فعلی خودت هستی، برای تغییر به کاربر دیگر نیاز به root داری).

## بخش ۶: `umask` — مجوز پیش‌فرض فایل‌های جدید

وقتی فایل جدید می‌سازی، مجوزش چطور تعیین می‌شود؟ با `umask`.

</div>

```bash
umask
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

معمولاً `0022` است.

**فرمول:**
- فایل جدید: `666 - umask` → `666 - 022 = 644`
- پوشه جدید: `777 - umask` → `777 - 022 = 755`

تغییر موقت:

</div>

```bash
umask 077
touch test-umask.txt
ls -l test-umask.txt    # باید 600 شود
umask 022
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**نکته:** برای دائمی کردن، در `~/.bashrc` اضافه کن.

## بخش ۷: مجوزهای ویژه — SetUID، SetGID، Sticky Bit

این‌ها خیلی مهم‌اند و در DevOps زیاد می‌بینی.

### SetUID (روی فایل)

وقتی روی فایل اجرایی تنظیم شود، آن فایل با اختیارات **مالک فایل** اجرا می‌شود، نه کاربری که اجرا می‌کند.

نشانه: `s` در جای `x` مالک.

</div>

```
-rwsr-xr-x
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


مثال کلاسیک: `/usr/bin/passwd`

</div>

```bash
ls -l /usr/bin/passwd
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

خروجی: `-rwsr-xr-x` — چون `passwd` باید فایل `/etc/shadow` را تغییر بدهد، ولی کاربر معمولی هم باید بتواند رمزش را عوض کند.

تنظیم:
</div>

```bash
chmod u+s file
chmod 4755 file
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**⚠️ هشدار امنیتی:** SetUID روی فایل‌های اشتباه، خطر امنیتی جدی است. همیشه با احتیاط.

### SetGID (روی فایل و پوشه)

- روی **فایل**: اجرا با اختیارات گروه مالک.
- روی **پوشه**: فایل‌های جدید داخل پوشه، گروه پوشه را به ارث می‌برند (نه گروه کاربر سازنده).

نشانه: `s` در جای `x` گروه.
</div>

```
-rwxr-sr-x   (فایل)
drwxrwsr-x   (پوشه)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

تنظیم:
</div>

```bash
chmod g+s folder
chmod 2775 folder
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**کاربرد DevOps:** پوشه مشترک تیم که همه اعضای گروه بتوانند فایل بسازند و همه به آن دسترسی داشته باشند.

### Sticky Bit (روی پوشه)

فقط مالک فایل (یا root) می‌تواند فایل را حذف کند، حتی اگر بقیه در پوشه مجوز نوشتن داشته باشند.

نشانه: `t` در جای `x` بقیه.
</div>

```
drwxrwxrwt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

مثال کلاسیک: `/tmp`
</div>

```bash
ls -ld /tmp
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

خروجی: `drwxrwxrwt` — همه می‌توانند فایل بسازند، ولی فقط مالک می‌تواند فایل خودش را حذف کند.

تنظیم:
</div>

```bash
chmod +t folder
chmod 1777 folder
```

### خلاصه مجوزهای ویژه

| مجوز | عدد | روی فایل | روی پوشه |
|---|---|---|---|
| SetUID | `4xxx` | اجرا با اختیار مالک | (بی‌معنا) |
| SetGID | `2xxx` | اجرا با اختیار گروه | ارث‌بری گروه |
| Sticky | `1xxx` | (بی‌معنا) | فقط مالک حذف کند |

## بخش ۹: تشخیص مشکلات مجوز

### خطای معروف `Permission denied`

سناریو: اسکریپت را `chmod 644` گذاشتی و می‌خواهی اجرا کنی:
</div>

```bash
echo 'echo Hello' > script.sh
chmod 644 script.sh
./script.sh
```

خروجی:

```
bash: ./script.sh: Permission denied
```

راه‌حل:

```bash
chmod 755 script.sh
./script.sh
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

### خطای دسترسی به پوشه

اگر پوشه‌ای `x` نداشته باشد، نمی‌توانی واردش شوی. اگر `r` نداشته باشد، می‌توانی وارد شوی ولی `ls` نمی‌توانی.
</div>

```bash
mkdir testdir
touch testdir/file
chmod 000 testdir
cd testdir      # Permission denied
ls testdir      # Permission denied
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

برگردان:
</div>

```bash
chmod 755 testdir
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## بخش ۱۰: ابزارهای مفید برای مجوزها
</div>

```bash
# دیدن مجوز همه فایل‌های یک پوشه به شکل عددی
stat -c "%a %n" ~/linux-course/session1/*

# پیدا کردن فایل‌های با SetUID (برای امنیت)
sudo find / -perm -4000 -type f 2>/dev/null

# پیدا کردن فایل‌های قابل نوشتن برای همه (خطرناک!)
find / -perm -o+w -type f 2>/dev/null | head

# پیدا کردن فایل‌های بدون مالک (مالک حذف شده)
find / -nouser -o -nogroup 2>/dev/null | head

# پیدا کردن فایل‌های با مجوز خاص
find ~/linux-course -perm 600 -type f
```

## پروژه جلسه ۲

**سناریو:** می‌خواهی یک پوشه مشترک تیم بسازی که:

- اعضای گروه `devs` بتوانند فایل بسازند
- همه فایل‌های ساخته‌شده گروه `devs` بگیرند
- فقط مالک فایل بتواند فایل خودش را پاک کند
- بقیه کاربران سیستم نتوانند داخلش چیزی بسازند

مراحل:
</div>

```bash
# ۱. گروه بساز (اگر قبلاً نساختی)
sudo groupadd devs

# ۲. خودت را به گروه اضافه کن
sudo usermod -aG devs $USER
# نکته: بعد از این باید logout/login کنی یا از newgrp استفاده کنی
newgrp devs

# ۳. پوشه بساز
sudo mkdir /srv/devshare

# ۴. مالکیت
sudo chown root:devs /srv/devshare

# ۵. مجوز: SetGID + Sticky
sudo chmod 3775 /srv/devshare
# 3 = SetGID + Sticky
# 775 = rwxrwxr-x

# ۶. بررسی
ls -ld /srv/devshare
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

باید ببینی: `drwxrwsr-t root devs`

توضیح `3775`:
- `3` = SetGID (2) + Sticky (1)
- `775` = مالک rwx، گروه rwx، بقیه r-x

**تست:**
</div>

```bash
# خودت فایل بساز
touch /srv/devshare/myfile
ls -l /srv/devshare/myfile
# باید گروه devs باشد (SetGID کار می‌کند)

# بررسی Sticky
# با کاربر دیگر (مثلاً ali) سعی کن فایل من را پاک کنی → نمی‌شود
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## چرا `chmod 777` بد است؟

خیلی‌ها فکر می‌کنند `777` همه مشکلات را حل می‌کند. ولی:

1. **امنیت:** هر کاربر سیستم می‌تواند فایل را تغییر دهد → خطرناک
2. **مشکل واقعی حل نمی‌شود:** معمولاً مشکل از گروه یا مالکیت است، نه مجوز
3. **در تولید (Production) ممنوع:** استانداردهای امنیتی مثل CIS آن را رد می‌کنند
4. **Docker/Kubernetes:** اگر داخل کانتینر `777` بگذاری، حجم و امنیت را به‌هم می‌زنی

**جایگزین:** مالکیت را درست کن، گروه را درست کن، مجوز حداقلی لازم را بده.

## تکلیف برای من



1. خروجی `ls -ld /srv/devshare`
2. خروجی `stat -c "%a %n" /srv/devshare/*` بعد از ساختن فایل
3. خروجی `sudo find / -perm -4000 -type f 2>/dev/null` (چند فایل SetUID روی سیستم Ubuntu پیدا می‌شود؟)
