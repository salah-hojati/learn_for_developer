## 🐝 مرحله ۶: Docker Swarm — Orchestration بومی و ساده

### ۱. Swarm در سال ۲۰۲۶ چه وضعیتی داره؟ (مهم برای تصمیم‌گیری)

اول از همه، بذار یه شایعه رو رد کنم: **Docker Swarm منسوخ نشده (deprecated نیست).** این باور غلط از اشتباه گرفتن با «Docker Classic Swarm» (محصولی جداگانه از سال ۲۰۱۵) میاد که دیگه توسعه نمی‌شه.

وضعیت واقعی در سال ۲۰۲۶ اینه:
- **Swarm mode هنوز بخشی از Docker Engine هست** و در هر نسخه جدید Docker عرضه می‌شه. برای مثال، نسخه Engine 29.8.0 در سپتامبر ۲۰۲۶ هفت اصلاحیه مخصوص Swarm داشت.
- توسط **Mirantis** (که Docker Enterprise رو در ۲۰۱۹ خرید) به صورت تجاری پشتیبانی می‌شه و تیم توسعه اختصاصی داره.
- **کتابخانه SwarmKit** فعاله و pull request هاش merge می‌شن.

**اما**، مجموعه ویژگی‌هاش سال‌هاست که تقریباً ثابت مونده (feature-frozen). این برای یادگیری **عالیه** چون یه محصول بالغ و پایدار رو می‌بینی، نه یه چیزی که هر ماه عوض می‌شه.

**خلاصه:** Swarm برای تیم‌های کوچک و متوسط، اپلیکیشن‌های ساده و بارهای کاری قابل پیش‌بینی عالیه. برای مقیاس‌های بزرگ و پیچیده، Kubernetes استاندارد صنعته.

---

### ۲. Swarm در یک نگاه: چطور کار می‌کنه؟

Swarm یه گروه از Docker Engine ها رو به یه **cluster واحد** تبدیل می‌کنه که مثل یه Docker Engine مجازی بزرگ رفتار می‌کنه. دو نوع node داره:

| نوع Node | نقش |
|-----------|------|
| **Manager** | تصمیم‌گیری، مدیریت cluster، هماهنگی (Raft consensus) |
| **Worker** | اجرای واقعی container ها (توسط manager دستور می‌گیره) |

مفاهیم کلیدی که باید بفهمی:
- **Service**: تعریف **وضعیت مطلوب** (مثلاً "۳ نسخه از Nginx همیشه در حال اجرا باشه").
- **Task**: هر container منفرد که بخشی از یه service رو اجرا می‌کنه.
- **Routing Mesh**: load balancing داخلی. هر node می‌تونه ترافیک رو به هر task (حتی روی node دیگه) route کنه.

### ۳. راه‌اندازی Swarm — گام به گام

#### گام ۰: پیش‌نیازها
برای تست، می‌تونی روی **یه ماشین** (single-node swarm) شروع کنی. برای حالت واقعی multi-node، به ۳ هاست لینوکسی با Docker نصب‌شده نیاز داری که بتونن با هم شبکه بشن.

**پورت‌های لازم** بین node ها باید باز باشن:
- `2377/tcp` → ارتباط manager ها
- `7946/tcp/udp` → discovery
- `4789/udp` → ترافیک overlay network (VXLAN)

> **نکته امنیتی (مهم):** پورت `4789` رو **هرگز** به اینترنت باز نکن. VXLAN احراز هویت نداره. اگه شبکه‌ت کاملاً قابل اعتماد نیست، حتماً از **encrypted overlay network** استفاده کن.

#### گام ۱: مقداردهی اولیه (روی node مدیر)

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
# روی ماشینی که می‌خوای manager بشه
docker swarm init --advertise-addr <IP-مدیر>
```

</div>

این دستور:
- cluster رو با نام `default` می‌سازه.
- یه **CA ریشه self-signed** تولید می‌کنه.
- توکن‌های join برای worker و manager تولید می‌کنه.
- یه network به نام `ingress` برای load balancing می‌سازه.

خروجی، دستور `docker swarm join` رو چاپ می‌کنه که باید روی worker ها اجرا کنی.

#### گام ۲: اضافه کردن Worker ها

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
# روی هر ماشین worker
docker swarm join --token <توکن> <IP-مدیر>:2377
```

</div>


#### گام ۳: بررسی Cluster

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
docker node ls
# باید manager (با علامت *) و worker ها رو ببینی
```

</div>


#### گام ۴: استقرار اولین Service

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
# ۳ نسخه از Nginx، با پورت ۸۰۸۰
docker service create --name learn-web --replicas 3 -p 8080:80 nginx:alpine

# وضعیت
docker service ls
docker service ps learn-web
```

</div>

Swarm تضمین می‌کنه که **همیشه** ۳ نسخه در حال اجرا باشه. اگه یکی بمیره، خودکار جایگزین می‌شه.

### ۴. مدیریت Service و Node — دستورات کلیدی

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
# ─── Service ───
docker service ls                    # لیست service ها
docker service ps <service>          # task های یه service
docker service logs -f <service>     # لاگ زنده
docker service scale <service>=5     # تغییر تعداد replica
docker service update --image nginx:1.25 <service>  # rolling update
docker service rollback <service>    # برگشت به نسخه قبل
docker service rm <service>          # حذف

# ─── Node ───
docker node ls                       # لیست node ها
docker node inspect <node>           # جزئیات
docker node update --availability drain <node>  # خالی کردن node برای تعمیرات
docker node promote <node>           # worker → manager
docker node demote <node>            # manager → worker
```

</div>



**نکته حرفه‌ای: Rolling Update**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
docker service create --name web \
  --replicas 3 \
  --update-parallelism 1 \    # یکی‌یکی آپدیت کن
  --update-delay 10s \         # ۱۰ ثانیه بین هر آپدیت
  --update-order start-first \ # اول جدید رو بالا بیار، بعد قدیمی رو بکش
  nginx:1.25
```

</div>

این پیکربندی تضمین می‌کنه در حین آپدیت، downtime نداشته باشی.

### ۵. استقرار Stack (همون Compose، ولی روی Swarm)

اینجا جاییه که تجربه‌ت از Compose به کارت میاد. با `docker stack deploy` می‌تونی یه فایل Compose کامل رو روی Swarm مستقر کنی.

> **⚠️ نکته بسیار مهم:** `docker stack deploy` از **فرمت قدیمی Compose (نسخه ۳)** استفاده می‌کنه، نه فرمت جدید و استاندارد Compose Specification. پس اگه فایل Compose جدید داری، ممکنه بعضی دستوراتش کار نکنن.

**نمونه فایل `stack.yml`:**

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```yaml
version: "3.8"

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"
    deploy:
      replicas: 3
      update_config:
        parallelism: 1
        delay: 10s
        order: start-first
      restart_policy:
        condition: on-failure
      resources:
        limits:
          memory: 256M
          cpus: "0.5"

  redis:
    image: redis:alpine
    deploy:
      replicas: 1
    # redis پورت publish نمی‌کنه، فقط داخل شبکه در دسترسه
```

</div>


<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

```bash
# استقرار
docker stack deploy -c stack.yml learn-stack

# مشاهده
docker stack ls
docker stack services learn-stack
docker stack ps learn-stack

# حذف
docker stack rm learn-stack
```

</div>



**نکته:** بخش `deploy` در فایل Compose، معادل تنظیمات `docker service create` هستش (مثل replica، rolling update، محدودیت منابع).

### ۶. امنیت و نکات کلیدی در Swarm

- **Secrets**: از `docker secret` برای رمزها استفاده کن، نه `environment` متنی.

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

  ```bash
  echo "mysecret" | docker secret create db_password -
  docker service create --secret db_password ...
  ```

</div>

  secret به صورت فایل در `/run/secrets/` داخل container ظاهر می‌شه.

- **Overlay Network رمزنگاری‌شده**: برای ارتباط امن بین node ها:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

  ```bash
  docker network create --opt encrypted --driver overlay learn-net
  ```

</div>


- **Placement Constraints**: کنترل کن کدوم service روی کدوم node اجرا بشه:

<div dir="ltr" style="text-align: left; font-family: 'B Nazanin', Tahoma, sans-serif;">

  ```bash
  docker service create --constraint 'node.role == worker' ...
  ```

</div>


- **Drain کردن Node**: قبل از تعمیرات، node رو `drain` کن تا task هاش به node های دیگه منتقل بشن.

### ۷. مقایسه سریع Swarm با Kubernetes (برای آماده‌سازی ذهنی)

| ویژگی | Docker Swarm | Kubernetes |
|-------|--------------|------------|
| **راه‌اندازی** | یک دستور (`docker swarm init`) | چند مرحله پیچیده |
| **منحنی یادگیری** | بسیار کم | زیاد |
| **Auto-scaling** | ❌ نداره | ✅ دارد |
| **اکوسیستم** | کوچک | بسیار بزرگ (CNCF) |
| **مقیاس** | تیم‌های کوچک/متوسط | سازمان‌های بزرگ |
| **استاندارد صنعت در ۲۰۲۶** | برای موارد ساده | ✅ استاندارد غالب |

**نکته آماری:** حدود **۹۶٪** سازمان‌ها از Kubernetes استفاده می‌کنن یا در حال ارزیابی اون هستن، در حالی که این عدد برای Swarm حدود **۲۴٪** است.

### ۸. تمرین عملی پیشنهادی

۱. روی سیستم Ubuntu خودت (یا یه VM) یه **single-node swarm** راه بنداز.
۲. همون stack ای که تو مرحله ۴ Compose ساختی (FastAPI/Node + Postgres + Redis) رو به یه فایل `stack.yml` تبدیل کن و با `docker stack deploy` مستقرش کن.
۳. یه replica از سرویس web رو عمداً بکش (`docker kill <container>`) و ببین Swarm چطور خودکار جبران می‌کنه.
۴. یه `docker service update` با image جدید انجام بده و rolling update رو تماشا کن.
۵. (اختیاری) اگه ماشین مجازی بیشتری داری، یه worker به swarm اضافه کن و رفتار cluster رو ببین.

---

**قدم بعدی:** وقتی با Swarm راحت شدی و مفاهیم service، task، rolling update و overlay network رو هضم کردی، آماده‌ای برای **Kubernetes**. اونجا این مفاهیم رو با اسم‌های جدید (Pod, Deployment, Service, Ingress) و قدرت خیلی بیشتر می‌بینی، ولی پایه‌ی ذهنی‌ت از الان ساخته شده.

آماده‌ای بریم Kubernetes، یا می‌خوای اول یه تمرین Swarm رو با هم قدم‌به‌قدم انجام بدیم؟
