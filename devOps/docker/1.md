# مرحله ۱: مبانی Docker — صفر تا صد 🐳

هدف این مرحله: **مفاهیم پایه رو واقعاً بفهمی**، نه فقط دستور حفظ کنی. آخر این مرحله باید بتونی توضیح بدی "container چیه" به یه بچه ۱۰ ساله.

## ۱. ذهنیت درست: Container دقیقاً چیه؟

قبل از دستور زدن، این سه تا رو بفهم:

### 🔹 Image = کلاس (Class) در برنامه‌نویسی
یه فایل read-only که همه‌چیز رو داره: سیستم‌عامل پایه، کتابخانه‌ها، کد، تنظیمات. **تغییر نمی‌کنه.** مثل یه DVD که فقط می‌تونی ازش کپی بگیری.

### 🔹 Container = نمونه (Instance) از اون کلاس
یه process در حال اجرا که از image ساخته شده. می‌تونی ۱۰ تا container از یه image بسازی، هر کدوم مستقل.

### 🔹 چرا container سبک‌تر از VM هست؟
| VM | Container |
|----|-----------|
| Virtualize سخت‌افزار | Virtualize سیستم‌عامل |
| هر VM = یه OS کامل | همه container ها از kernel میزبان استفاده می‌کنن |
| گیگابایت حجم | مگابایت حجم |
| چند ثانیه تا بالا بیاد | چند صدم ثانیه |

**آزمایش ذهنی:** یه VM Ubuntu حدود ۲-۳ گیگابایت حجم داره. یه image Ubuntu داکر حدود ۷۰ مگابایت. چرا؟

## ۲. اولین container ها — آزمایش عملی

### تمرین ۲.۱: Hello World
</div>

```bash
docker run hello-world
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">
خروجی رو **کامل بخون**. یه پیام داره که کل چرخه رو توضیح می‌ده:
1. Docker client به daemon گفت
2. daemon دید image نیست، از Docker Hub کشید
3. از image یه container ساخت
4. اجرا کرد، پیام چاپ شد، تموم شد

**سوال:** الان `docker ps -a` رو بزن. این container رو می‌بینی؟ چرا با `docker ps` نمی‌بینیش؟

---

### تمرین ۲.۲: Ubuntu تعاملی
</div>

```bash
docker run -it --name learn-ubuntu ubuntu:22.04 bash
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**هر فلگ رو بفهم:**
- `-i` = interactive (STDIN باز بمونه)
- `-t` = pseudo-TTY (ترمینال مجازی)
- `--name` = اسم دلخواه (اگه ندی، داکر اسم تصادفی می‌ده)
- `ubuntu:22.04` = image + tag

داخلش که هستی:
</div>

```bash
# ببین کدوم kernel داری
uname -a

# ببین OS چیه
cat /etc/os-release

# یه فایل بساز
echo "hello from container" > /tmp/test.txt
cat /tmp/test.txt

# ببین چه process هایی در حال اجران
ps aux

# exit کن
exit
```

**حالا اینو امتحان کن:**
```bash
# container رو دوباره start کن
docker start -ai learn-ubuntu

# فایل /tmp/test.txt هنوز هست؟
cat /tmp/test.txt
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**نتیجه مهم:** ❌ فایل نیست! چون هر بار که container متوقف و دوباره start می‌شه، فایل‌های داخلش **باقی می‌مونن** (چون همون container هست)، ولی اگه `docker rm` کنی و از نو `run` کنی، همه‌چیز از دست می‌ره. اینجا جاییه که **Volume** وارد می‌شه (مرحله ۳).

خروج:
</div>

```bash
exit
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

### تمرین ۲.۳: Container دیتچ شده (detached)
</div>

```bash
# یه nginx اجرا کن در پس‌زمینه
docker run -d --name learn-nginx -p 8888:80 nginx:alpine

# چک کن
docker ps

# ببین لاگ‌هاش
docker logs learn-nginx

# لاگ زنده (مثل tail -f)
docker logs -f learn-nginx
# Ctrl+C برای خروج از log

# تست از مرورگر یا curl
curl http://localhost:8888
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**فلگ‌های جدید:**
- `-d` = detached (پس‌زمینه)
- `-p 8888:80` = پورت ۸۸۸۸ میزبان → ۸۰ داخل container
- `nginx:alpine` = نسخه Alpine (خیلی کوچیک، ~۲۰ مگ)

**چرا از پورت ۸۸۸۸ استفاده کردم؟** چون ممکنه پورت ۸۰ روی سیستم تو اشغال باشه (همون compose هات).

**سوال برای فکر:** الان اگه `docker ps` رو بزنی، ستون `PORTS` چی نشون می‌ده؟ `0.0.0.0:8888->80/tcp` یعنی چی؟

---

### تمرین ۲.۴: ورود به container در حال اجرا
</div>

```bash
# nginx یه container سبکه، shell نداره ولی sh داره
docker exec -it learn-nginx sh

# داخلش
ls /usr/share/nginx/html/
cat /usr/share/nginx/html/index.html

# ببین process اصلی چیه
ps aux

exit
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**تفاوت `docker run` و `docker exec`:**
- `run` = container **جدید** بساز و اجرا کن
- `exec` = تو container **در حال اجرا** یه دستور بزن

اینو با experiment ثابت کن:
</div>

```bash
# با exec
docker exec learn-nginx ls /

# با run (container جدید می‌سازه!)
docker run nginx:alpine ls /
# بعدش docker ps -a بزن، یه container جدید اضافه شده
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## ۳. چرخه حیات container (Lifecycle)

این چرخه رو کامل بفهم — سوال کلاسیک مصاحبه‌ایه:
</div>

```
   created → running → paused
                ↓
              stopped (exited)
                ↓
              removed
```

### تمرین ۳.۱: کل چرخه رو دستی طی کن
```bash
# ساخت و اجرا
docker run -d --name learn-lifecycle nginx:alpine
docker ps                           # running ✓

# توقف
docker stop learn-lifecycle
docker ps                           # خالیه
docker ps -a                        # هست، ولی Exited

# شروع مجدد
docker start learn-lifecycle
docker ps                           # دوباره running

# ری‌استارت
docker restart learn-lifecycle

# pause (process متوقف، ولی container زنده)
docker pause learn-lifecycle
docker ps                           # STATUS: Up (Paused)
docker unpause learn-lifecycle

# kill (مثل SIGKILL)
docker kill learn-lifecycle

# حذف
docker rm learn-lifecycle           # اگه running باشه خطا می‌ده
docker rm -f learn-lifecycle        # اجباری

# نکته: -f یعنی force
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

**سوال مهم:** تفاوت `stop` و `kill` چیه؟
- `stop` = SIGTERM می‌فرسته، صبر می‌کنه (پیش‌فرض ۱۰ ثانیه)، بعد SIGKILL
- `kill` = مستقیم SIGKILL، فرصت تمیزکاری نمی‌ده

## ۴. دستورات ضروری — چیت‌شیت
</div>

```bash
# ─── مشاهده ───
docker ps                    # در حال اجرا
docker ps -a                 # همه
docker ps -a --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
docker logs <name>           # لاگ
docker logs -f --tail 50 <name>
docker inspect <name>        # جزئیات کامل JSON
docker stats                 # منابع زنده (Ctrl+C)
docker top <name>            # process های داخل
docker port <name>           # پورت مپینگ

# ─── تعامل ───
docker exec -it <name> bash  # یا sh
docker cp <name>:/path/file ./local
docker cp ./local <name>:/path/file

# ─── مدیریت ───
docker stop <name>           # یا چند تا: docker stop a b c
docker start <name>
docker restart <name>
docker rm <name>             # یا -f
docker rename <old> <new>

# ─── image ───
docker images
docker image inspect <img>
docker image history <img>   # لایه‌ها
docker pull <img>
docker rmi <img>

# ─── پاک‌سازی (محتاط!) ───
# فقط container های متوقف رو پاک کن:
docker container prune

# ⚠️ هیچوقت اینا رو نزن بدون فکر:
# docker system prune -a
# docker volume prune
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">
**نکته امنیتی برای تو:** دستور `docker container prune` امنه چون فقط container های **متوقف** رو پاک می‌کنه. ولی حواست باشه، اگه از setup اصلیت یه container متوقف شده و می‌خوایش، قبلش چک کن.

## ۵. تمرین بزرگ: همه‌چیز با هم

یه بازی کن — بدون نگاه به بالا، این‌ها رو انجام بده:
</div>

```bash
# 1. یه redis بساز که تو پس‌زمینه اجرا بشه، اسمش learn-redis، پورت ۶۳۷۹
# 2. لاگ هاش رو ببین
# 3. داخلش یه redis-cli بزن و یه کلید ست کن
# 4. از بیرون (host) با یه redis-cli یا nc تستش کن
# 5. container رو stop کن
# 6. دوباره start کن
# 7. داخلش ببین اون کلیدی که ست کردی هنوز هست؟
# 8. همه چی رو پاک کن
```

<details>
<summary>راه‌حل (بعد از تلاش خودت باز کن)</summary>



```bash
# 1
docker run -d --name learn-redis -p 6379:6379 redis:alpine

# 2
docker logs learn-redis

# 3
docker exec -it learn-redis redis-cli
# داخل redis-cli:
# SET mykey "hello docker"
# GET mykey
# exit

# 4 (از host، اگه redis-cli داری)
redis-cli -h localhost -p 6379 ping
# یا تست ساده:
nc -zv localhost 6379

# 5
docker stop learn-redis

# 6
docker start learn-redis

# 7
docker exec -it learn-redis redis-cli GET mykey
# → "hello docker" چون همون container هست!

# 8
docker rm -f learn-redis
```

</details>

<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">
**درس این تمرین:** با `stop` و `start` دیتا می‌مونه، ولی با `rm` و `run` جدید همه‌چیز از دست می‌ره. **اینجاست که Volume ضروری می‌شه.**

## ۶. سوالات خودآزمایی (بعد از تموم کردن، جواب بده)

1. تفاوت `docker run` و `docker start` چیه؟
2. چرا `docker ps` بعد از `docker run hello-world` هیچی نشون نمی‌ده؟
3. `-it` یعنی چی؟ کِی لازمه؟
4. تفاوت `stop` و `kill` چیه؟
5. اگه container یه دیتابیس داشته باشه و `rm` کنی، دیتا می‌مونه؟ چرا؟
6. `docker exec` و `docker run` هر دو shell می‌دن، فرقشون چیه؟
7. چرا image های `alpine` خیلی کوچیک‌ترن؟

<details>
<summary>جواب‌های کوتاه</summary>

1. `run` = image → container جدید + اجرا. `start` = container موجود رو دوباره اجرا.
2. چون hello-world یه کار انجام داد و تموم شد (Exited). با `ps -a` می‌بینیش.
3. `-i` STDIN باز، `-t` ترمینال مجازی. برای shell تعاملی لازمه.
4. `stop` = SIGTERM + grace period، `kill` = مستقیم SIGKILL.
5. اگه Volume نداشته باشه، نه. دیتا داخل لایه نوشتنی container بود، با rm می‌ره.
6. `exec` تو container **در حال اجرا**، `run` یه container **جدید**.
7. Alpine Linux پایه‌اش فقط ~۵ مگه، با busybox به‌جای coreutils.
</details>
