# مرحله ۲: Dockerfile — از صفر تا حرفه‌ای 📝

هدف این مرحله: بتونی برای **هر پروژه‌ای** یه Dockerfile بهینه بنویسی، اندازه image رو کم کنی، و بفهمی هر لایه چطور کار می‌کنه.

---

## ۱. Dockerfile دقیقاً چیه؟

یه فایل متنی ساده که به Docker می‌گه: "چطور image من رو بساز". هر **دستور** یه **لایه (layer)** می‌سازه که کش می‌شه.

### ذهنیت درست: Dockerfile = دستور پخت
</div>


```dockerfile
FROM ubuntu:22.04          # مواد اولیه
RUN apt install nginx -y   # مرحله پخت
COPY nginx.conf /etc/...   # چاشنی
CMD ["nginx", "-g", "daemon off;"]  # سرو کردن
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### قانون طلایی لایه‌ها
> **هر دستور = یه لایه immutable. لایه‌ها روی هم سوار می‌شن. اگه یه لایه تغییر کنه، همه لایه‌های بعدیش دوباره ساخته می‌شن.**

این یعنی **ترتیب دستورات حیاتیه**.

---

## ۲. اولین Dockerfile — دستی

یه پوشه تمرین بساز (بیرون از پوشه‌های compose فعلیت!):
</div>



## ۳. همه دستورات Dockerfile با مثال

### `FROM` — نقطه شروع
</div>


```dockerfile
FROM ubuntu:22.04                  # با tag مشخص
FROM node:20-alpine                # پایه برنامه‌نویسی
FROM scratch                       # خالی! (برای باینری استاتیک)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**قانون:** همیشه tag دقیق بده. `FROM ubuntu` = `ubuntu:latest` = غافلگیری در آینده.

**multi-arch (اختیاری):**
</div>


```dockerfile
FROM --platform=linux/amd64 node:20-alpine
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


---

### `WORKDIR` — پوشه کاری
</div>


```dockerfile
WORKDIR /app
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


- پوشه رو می‌سازه اگه نباشه
- همه دستورات بعدی نسبت به این اجرا می‌شن
- **بهتر از** `RUN cd /app && ...`

---

### `COPY` و `ADD` — کپی فایل
</div>


```dockerfile
# فرمت: COPY <منبع> <مقصد>
COPY package.json .              # از context به WORKDIR
COPY ./src /app/src              # پوشه
COPY --chown=node:node . /app    # با owner مشخص
COPY --from=builder /app/dist /app/dist  # از stage قبلی (multi-stage)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**تفاوت COPY و ADD:**
- `COPY` = فقط کپی. **همیشه این رو ترجیح بده.**
- `ADD` = کپی + باز کردن tar + دانلود از URL (این‌ها باعث شگفتی می‌شن، استفاده نکن)

---

### `RUN` — اجرای دستور در زمان build
</div>


```dockerfile
# فرمت shell (پرکاربردتر)
RUN apt-get update && apt-get install -y curl

# فرمت exec
RUN ["apt-get", "install", "-y", "curl"]

# چند خطی برای خوانایی
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        curl \
        git \
    && rm -rf /var/lib/apt/lists/*
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**قوانین طلایی `RUN`:**
1. `apt-get update` و `apt-get install` رو **توی یه RUN** بذار (چرا؟ بعداً می‌فهمی)
2. آخرش `rm -rf /var/lib/apt/lists/*` بزن تا cache پاک بشه
3. `--no-install-recommends` تا پکیج‌های غیرضروری نصب نشن

---

### `ENV` و `ARG` — متغیرها
</div>


```dockerfile
# ENV = در زمان runtime هم موجوده
ENV NODE_ENV=production
ENV APP_PORT=3000

# ARG = فقط در زمان build
ARG VERSION=1.0.0
RUN echo "Building version $VERSION"

# ARG رو با --build-arg پاس می‌دن
# docker build --build-arg VERSION=2.0.0 .
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**تفاوت مهم:**
| ENV | ARG |
|-----|-----|
| هم build هم runtime | فقط build |
| در image ذخیره می‌شه | ذخیره نمی‌شه |
| `docker run -e VAR=x` | `docker build --build-arg VAR=x` |

---

### `EXPOSE` — مستندسازی پورت
</div>


```dockerfile
EXPOSE 3000
EXPOSE 3000/tcp
EXPOSE 53/udp
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**نکته:** `EXPOSE` فقط **مستندسازیه**. پورت رو باز نمی‌کنه! برای باز کردن باید `-p` بدی.

---

### `CMD` vs `ENTRYPOINT` — مهم‌ترین تفاوت
</div>


```dockerfile
# CMD = پیش‌فرض (قابل بازنویسی)
CMD ["node", "server.js"]

# ENTRYPOINT = ثابت (سخت‌تر بازنویسی می‌شه)
ENTRYPOINT ["node", "server.js"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**تفاوت رو با مثال بفهم:**
</div>


```dockerfile
# Dockerfile A:
CMD ["echo", "hello"]

# Dockerfile B:
ENTRYPOINT ["echo"]
```

```bash
# با CMD
docker run imageA                    # → hello
docker run imageA "world"            # → world (CMD کلاً نادیده گرفته شد!)

# با ENTRYPOINT
docker run imageB                    # → (خالی)
docker run imageB "world"            # → world (آرگومان اضافه شد)
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**بهترین ترکیب:**
</div>


```dockerfile
ENTRYPOINT ["node"]
CMD ["server.js"]
```
```bash
docker run myapp                    # → node server.js
docker run myapp other.js           # → node other.js
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**قانون:**
- `CMD` = آرگومان‌های پیش‌فرض
- `ENTRYPOINT` = دستور ثابت
- برای اسکریپت‌ها از `ENTRYPOINT` + `CMD` استفاده کن

---

### `USER` — امنیت
</div>


```dockerfile
# کاربر غیر root بساز
RUN useradd -m -u 1000 appuser
USER appuser
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**همیشه non-root باشه.** این مهم‌ترین توصیه امنیتی Docker.

---

### `HEALTHCHECK` — بررسی سلامت
</div>


```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:3000/health || exit 1
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


بعدش `docker ps` ستون `STATUS` می‌شه: `Up 2 minutes (healthy)`.

---

### `VOLUME` — نقطه اتصال دیتا
</div>


```dockerfile
VOLUME /data
VOLUME ["/var/log", "/var/db"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


این فقط **اعلام** می‌کنه که این پوشه‌ها دیتا دارن. اگه کاربر `-v` نده، Docker یه anonymous volume می‌سازه.

---

### `LABEL` — متادیتا
</div>


```dockerfile
LABEL maintainer="you@example.com"
LABEL version="1.0"
LABEL description="My awesome app"
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## ۴. `.dockerignore` — خیلی مهم!

وقتی `docker build .` می‌زنی، **کل پوشه** به daemon فرستاده می‌شه. برای پروژه‌های واقعی، این **خیلی کند** می‌شه.

**فایل `.dockerignore` تو ریشه پروژه:**
</div>


```
.git
.gitignore
node_modules
__pycache__
*.pyc
.env
.env.*
dist
build
*.log
.DS_Store
docker-compose*.yml
Dockerfile*
README.md
.vscode
.idea
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**آزمایش کن:** یه فایل ۵۰۰ مگابایتی بساز، build رو با و بدون `.dockerignore` زمان بگیر.
</div>


```bash
cd ~/docker-learn/step2
dd if=/dev/zero of=bigfile.bin bs=1M count=500

# بدون .dockerignore
time docker build -t test-noignore .

# با .dockerignore
echo "bigfile.bin" > .dockerignore
time docker build -t test-withignore .

# پاک کن
rm bigfile.bin
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


تفاوت زمان رو ببین. این یعنی زندگی.

## ۵. Layer Caching — قلبی‌ترین مفهوم

**قانون:** هر لایه بر اساس **دستور + محتوای فایل‌هایی که COPY/RUN می‌بینه** کش می‌شه. اگه دستور یا محتوا تغییر کنه، اون لایه و **همه لایه‌های بعدی** دوباره ساخته می‌شن.

### اشتباه رایج:
</div>


```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY . .                    # ❌ همه فایل‌ها یه جا
RUN npm install             # هر تغییر کد → install از نو!
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### درست:
</div>


```dockerfile
FROM node:20-alpine
WORKDIR /app

COPY package*.json ./       # ✅ فقط package ها اول
RUN npm install             # اگه package.json تغییر نکرد، cache!

COPY . .                    # کد بعد از install
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**آزمایش عملی:**

پروژه Node بساز:
</div>


```bash
cd ~/docker-learn/step2
mkdir -p node-app && cd node-app

cat > package.json <<'EOF'
{
  "name": "learn-app",
  "version": "1.0.0",
  "scripts": { "start": "node index.js" },
  "dependencies": { "express": "^4.19.0" }
}
EOF

cat > index.js <<'EOF'
const express = require('express');
const app = express();
app.get('/', (req, res) => res.send('Hello Docker!'));
app.listen(3000, () => console.log('Running on 3000'));
EOF
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**Dockerfile بد (اشتباه):**
</div>


```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**Dockerfile خوب:**
</div>


```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
CMD ["npm", "start"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**تست کش:**
</div>


```bash
# build اول (هر دو)
docker build -f Dockerfile.bad -t learn-app:bad .
docker build -f Dockerfile.good -t learn-app:good .

# حالا یه تغییر کوچیک تو index.js بده
echo "// تغییر کوچیک" >> index.js

# دوباره build کن و زمان رو ببین:
time docker build -f Dockerfile.bad -t learn-app:bad .
time docker build -f Dockerfile.good -t learn-app:good .
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


با Dockerfile خوب، `npm install` از کش میاد → **چند ثانیه**.
با Dockerfile بد، `npm install` از نو → **چند دقیقه**.

## ۶. Multi-stage Build — تکنیک حرفه‌ای‌ها 🎯

### مشکل: image های حجیم
پروژه Node: node_modules خودش ~۲۰۰ مگ، ولی برای runtime فقط به بخشی نیاز داریم.
پروژه Go: کامپایلر گو ~۸۰۰ مگ، باینری نهایی ۱۰ مگ.

### راه‌حل: چند مرحله
</div>


```dockerfile
# ─── مرحله ۱: build ───
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# ─── مرحله ۲: runtime ───
FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package*.json ./
RUN npm ci --only=production
CMD ["node", "dist/index.js"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**نکته کلیدی:** فقط مرحله آخر تو image نهایی می‌مونه. مرحله build کاملاً دور ریخته می‌شه.

### مثال Go — شگفت‌انگیزترین حالت:
</div>


```dockerfile
FROM golang:1.22-alpine AS builder
WORKDIR /build
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o myapp

# image نهایی از scratch (خالی!)
FROM scratch
COPY --from=builder /build/myapp /myapp
ENTRYPOINT ["/myapp"]
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


نتیجه: image از ~۹۰۰ مگ → **~۵ مگ**!

### مرحله میانی مشترک
</div>


```dockerfile
# مرحله پایه
FROM node:20-alpine AS base
WORKDIR /app
COPY package*.json ./

# dev (برای توسعه)
FROM base AS dev
RUN npm install
COPY . .
CMD ["npm", "run", "dev"]

# prod (نهایی)
FROM base AS prod
RUN npm ci --only=production
COPY . .
CMD ["npm", "start"]
```

```bash
docker build --target dev -t myapp:dev .
docker build --target prod -t myapp:prod .
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

## ۷. BuildKit و buildx — ابزار مدرن

Docker از نسخه ۲۳ به بعد BuildKit به صورت پیش‌فرض فعاله. دستور `docker buildx` نسخه پیشرفته‌ست:
</div>


```bash
# نسخه رو ببین
docker buildx version

# build با خروجی های مختلف
docker buildx build --platform linux/amd64,linux/arm64 -t myapp:multi .
docker buildx build --load -t myapp:v1 .           # به docker محلی load کن
docker buildx build --push -t user/myapp:v1 .      # مستقیم push
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


### ترفندهای BuildKit:
</div>


```dockerfile
# cache mount برای install
# syntax=docker/dockerfile:1
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN --mount=type=cache,target=/root/.npm npm ci
COPY . .
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


`--mount=type=cache` یعنی npm cache بین build ها **می‌مونه** بدون اینکه تو image نهایی بره. عالی!
</div>


```dockerfile
# secret mount
RUN --mount=type=secret,id=mysecret cat /run/secrets/mysecret
```
```bash
docker build --secret id=mysecret,src=./secret.txt .
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


Secret تو image ذخیره نمی‌شه!

## ۸. سوال کلاسیک: چرا `apt-get update` و `install` توی یه RUN؟

**اشتباه:**
</div>


```dockerfile
RUN apt-get update
RUN apt-get install -y curl
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**درست:**
</div>


```dockerfile
RUN apt-get update && apt-get install -y curl
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">


**چرا؟**
- لایه ۱ (update) کش می‌شه.
- یک ماه بعد، package list قدیمی شده ولی Docker می‌گه "دستور update عوض نشده → از cache استفاده می‌کنم".
- لایه ۲ (install) با لیست قدیمی اجرا می‌شه → ممکنه پکیج پیدا نشه یا نسخه قدیمی نصب بشه.
- پس **همیشه با هم**.

## ۹. امنیت Dockerfile — چک‌لیست
</div>


```dockerfile
# ✅ از tag دقیق استفاده کن
FROM node:20.10.0-alpine3.19
# ❌ FROM node:latest

# ✅ کاربر non-root
RUN addgroup -S app && adduser -S app -G app
USER app

# ✅ read-only filesystem
# در runtime: docker run --read-only --tmpfs /tmp

# ✅ secrets رو نذار تو image
# ❌ ENV DB_PASSWORD=secret123
# ❌ COPY .env /app/.env
# ✅ RUN --mount=type=secret,...

# ✅ image پایه کوچیک
# alpine یا distroless

# ✅ پاک کردن cache ها
RUN apt-get update && apt-get install -y ... && rm -rf /var/lib/apt/lists/*

# ✅ HEALTHCHECK
HEALTHCHECK CMD curl -f http://localhost:3000/health || exit 1

# ✅ پین کردن با SHA (برای پارانویای امنیتی)
FROM node@sha256:abc123...
```
<div dir="rtl" style="text-align: right; font-family: 'B Nazanin', Tahoma, sans-serif;">

```dockerfile
# syntax=docker/dockerfile:1

# ─── مرحله build ───
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN --mount=type=cache,target=/root/.npm npm ci
COPY . .
RUN npm ci --only=production

# ─── مرحله runtime ───
FROM node:20-alpine
WORKDIR /app

# غیر root
RUN addgroup -S app && adduser -S app -G app

# فقط چیزهای لازم
COPY --from=builder --chown=app:app /app/node_modules ./node_modules
COPY --chown=app:app index.js package.json ./

USER app

ENV NODE_ENV=production
EXPOSE 3000

HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD wget -qO- http://localhost:3000/health || exit 1

CMD ["node", "index.js"]
```

## ۱۱. سوالات خودآزمایی

1. تفاوت `CMD` و `ENTRYPOINT` چیه؟ کِی از هر کدوم استفاده می‌کنی؟
2. `COPY` و `ADD` چه تفاوتی دارن؟ کدوم رو ترجیح می‌دی؟
3. چرا `apt-get update` و `install` باید تو یه `RUN` باشن؟
4. توی Dockerfile Node، چرا `package.json` رو قبل از کد کپی می‌کنیم؟
5. Multi-stage build چه سودی داره؟
6. `ARG` و `ENV` چه فرقی دارن؟
7. `.dockerignore` چرا مهمه؟
8. چرا `USER` غیر root مهمه؟
9. `EXPOSE` پورت رو باز می‌کنه؟ (بله/خیر + توضیح)
10. `--mount=type=cache` به چه دردی می‌خوره؟

<details>
<summary>جواب‌ها</summary>

1. CMD پیش‌فرض قابل بازنویسیه؛ ENTRYPOINT ثابت. برای اسکریپت‌ها ترکیب هر دو.
2. COPY فقط کپی؛ ADD کپی + tar + URL. همیشه COPY.
3. چون لایه update ممکنه cache بشه ولی لیست package ها قدیمی بشه.
4. برای layer caching — اگه کد عوض شه ولی package.json نه، install از cache میاد.
5. کاهش حجم image نهایی + جداسازی ابزار build از runtime.
6. ARG فقط build time؛ ENV هم build هم runtime و تو image ذخیره می‌شه.
7. کاهش build context + امنیت (مثلاً .env نره) + سرعت.
8. اگه container رخنه کنه، مهاجم دسترسی root به host نداره.
9. خیر، فقط مستندسازیه. برای باز کردن باید `-p` بدی.
10. cache بین build ها حفظ می‌شه بدون اینکه تو image نهایی بره.
</details>
