# انتخاب پروژه برای تمرین عملی 🎯

عالی! قبل از انتخاب، یه سوال مهم:

**compose های فعلیت چی هستن؟** (مثلاً: WordPress + MySQL؟ Nextcloud؟ یه API؟) اگه بگی، پروژه‌ای انتخاب می‌کنیم که **تداخل نداشته باشه** و حتی بتونه **مکمل** باشه.

---

## ۴ گزینه پیشنهادی — با مزایا و معایب

### 🥇 گزینه ۱: **FastAPI + Postgres + Redis** (پیشنهاد من)
**چرا بهترینه:**
- ✅ پایتون ساده و خوانا — تمرکزت روی Docker می‌مونه نه زبان
- ✅ همه مفاهیم مهم رو پوشش می‌ده: web + db + cache
- ✅ `HEALTHCHECK`, `depends_on`, volume, network — همه یه جا
- ✅ multi-stage build معنی‌داره (build deps vs runtime)
- ✅ آماده برای مرحله ۴ (Compose) هستش
- ✅ کاربردی در دنیای واقعی

**چی یاد می‌گیری:**
- Dockerfile بهینه پایتون (با `uv` یا `pip`)
- مدیریت secret و env
- اتصال به Postgres با volume
- کش با Redis
- اجرا با `uvicorn` غیر root
- Healthcheck برای DB

---

### 🥈 گزینه ۲: **Node.js + Postgres** (اگه Node بلدی)
**چرا خوبه:**
- ✅ layer caching آموزش فوق‌العاده‌ای داره (`package.json` vs کد)
- ✅ `node_modules` دردسر جالبی برای حل کردن داره
- ✅ پرکاربردترین سناریو در دنیای واقعی

**چی یاد می‌گیری:**
- Multi-stage با `npm ci` vs `npm install`
- `--mount=type=cache` برای npm
- Alpine vs slim vs distroless
- Build argument برای env

---

### 🥉 گزینه ۳: **Go API + Postgres** (اگه Go دوست داری)
**چرا خاصه:**
- ✅ بهترین نمایش multi-stage: از ~۹۰۰MB به ~۱۵MB
- ✅ `FROM scratch` رو عملاً می‌بینی
- ✅ باینری استاتیک — یادگیری عمیق
- ⚠️ اگه Go بلد نیستی، یه کم کندتر پیش می‌ره

---

### گزینه ۴: **پروژه خودت** (اگه داری)
اگه یه پروژه واقعی (هر زبونی) داری که می‌خوای داکرایز کنی، بگو چی هست و با هم قدم به قدم داکرایزش می‌کنیم. **بهترین حالت یادگیریه** چون انگیزه واقعی داری.

---

## پیشنهاد من: **گزینه ۱ (FastAPI + Postgres + Redis)**

دلایل:
1. **کاملاً ایزوله از setup فعلیت** — پورت و اسم جدا
2. **پوشش همه مفاهیم مرحله ۲ و ۳ و ۴**
3. **کاربردیه** — این پترن تو خیلی از پروژه‌های واقعی تکرار می‌شه
4. **ساده‌ست ولی سطحی نیست**
5. اگه پایتون بلد نباشی، کدش آنقدر کم و خواناست که مشکلی نمی‌شه

---

## اگه موافقی، این مسیر رو با هم می‌ریم:

### فاز A: ساخت پروژه پایه (بدون Docker)
1. یه FastAPI ساده که به Postgres وصل می‌شه
2. یه endpoint که از Redis کش می‌کنه
3. تست محلی بدون Docker (تا مطمئن شیم کد درسته)

### فاز B: Dockerfile برای اپ (مرحله ۲)
1. نسخه naive → ببینیم چقدر بزرگه
2. نسخه بهینه با multi-stage
3. اضافه کردن healthcheck، non-root، .dockerignore
4. مقایسه حجم و سرعت

### فاز C: اضافه کردن Postgres و Redis (مرحله ۳ و ۴)
1. اول دستی با `docker network` و `docker run`
2. بعد با Compose
3. Volume برای Postgres
4. env و secrets درست

### فاز D: بهینه‌سازی و امنیت
1. اسکن با trivy
2. user غیر root
3. read-only filesystem
4. resource limits
