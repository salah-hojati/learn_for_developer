# **Partitioning و Sequence در Oracle**

این دو قابلیت در Oracle برای **مدیریت بهتر حجم داده، بهبود عملکرد، و تولید شناسه‌های یکتا** استفاده می‌شوند؛ اما هدفشان کاملاً متفاوت است.

- **Partitioning**: تقسیم یک جدول بزرگ به بخش‌های کوچک‌تر از نظر فیزیکی/مدیریتی، در حالی که از دید SQL همچنان یک جدول است.
- **Sequence**: تولید عددهای متوالی برای استفاده در شناسه‌ها، کلیدهای Primary Key و موارد مشابه.

اگر تمام اطلاعات در یک جدول بزرگ باشد، نگهداری، Query، Backup و حذف داده‌های قدیمی می‌تواند دشوار شود.

## **2. انواع Partitioning**

### **A. Range Partitioning**

تقسیم بر اساس بازه یک ستون، معمولاً تاریخ یا عدد.

مثلاً Orders را بر اساس سال تقسیم کنیم:

```
CREATE TABLE ORDERS (
    ORDER_ID   NUMBER PRIMARY KEY,
    ORDER_DATE DATE NOT NULL,
    AMOUNT     NUMBER(12,2)
)
PARTITION BY RANGE (ORDER_DATE)
(
    PARTITION P2024 VALUES LESS THAN (DATE '2025-01-01'),
    PARTITION P2025 VALUES LESS THAN (DATE '2026-01-01'),
    PARTITION P2026 VALUES LESS THAN (DATE '2027-01-01'),
    PARTITION P_MAX  VALUES LESS THAN (MAXVALUE)
);
```

مثال:

اگر Query زیر اجرا شود:

```
SELECT *
FROM ORDERS
WHERE ORDER_DATE >= DATE '2026-01-01'
  AND ORDER_DATE < DATE '2027-01-01';
```

Oracle می‌تواند فقط Partition مربوط به 2026 را بررسی کند، به جای اینکه همه Partitionها را Scan کند.

مزایا:

- کاهش I/O
- بهبود Queryهای روی بازه‌های زمانی
- مدیریت ساده‌تر داده‌های قدیمی
- امکان حذف یا Archive داده‌های قدیمی بدون DELETE میلیون‌ها رکورد

### **B. List Partitioning**

تقسیم بر اساس مقادیر مشخص، مثلاً Region یا Country.

```
CREATE TABLE CUSTOMERS (
    CUSTOMER_ID NUMBER,
    REGION      VARCHAR2(20),
    NAME        VARCHAR2(100)
)
PARTITION BY LIST (REGION)
(
    PARTITION P_EUROPE VALUES ('EUROPE'),
    PARTITION P_ASIA    VALUES ('ASIA'),
    PARTITION P_AMERICA VALUES ('AMERICA'),
    PARTITION P_OTHER   VALUES (DEFAULT)
);
```

اگر Query داشته باشیم:

```
SELECT *
FROM CUSTOMERS
WHERE REGION = 'ASIA';
```

Oracle می‌تواند Partition مربوط به Asia را انتخاب کند.

### **C. Hash Partitioning**

تقسیم رکوردها بر اساس الگوریتم Hash روی یک ستون.

```
CREATE TABLE TRANSACTIONS (
    TX_ID      NUMBER,
    CUSTOMER_ID NUMBER,
    AMOUNT     NUMBER
)
PARTITION BY HASH (CUSTOMER_ID)
PARTITIONS 8;
```

Oracle با Hash کردن `CUSTOMER_ID` رکوردها را بین ۸ Partition توزیع می‌کند.

مناسب برای:

- توزیع یکنواخت داده‌ها
- جلوگیری از تمرکز داده در یک Partition
- Parallel Processing
- جداول بزرگ با دسترسی بر اساس Key

### **D. Composite Partitioning**

ترکیب دو روش Partitioning.

مثلاً ابتدا بر اساس سال، سپس Hash بر اساس Customer ID:

```
CREATE TABLE ORDERS (
    ORDER_ID    NUMBER,
    ORDER_DATE  DATE,
    CUSTOMER_ID NUMBER,
    AMOUNT      NUMBER
)
PARTITION BY RANGE (ORDER_DATE)
SUBPARTITION BY HASH (CUSTOMER_ID)
SUBPARTITIONS 4
(
    PARTITION P2025 VALUES LESS THAN (DATE '2026-01-01'),
    PARTITION P2026 VALUES LESS THAN (DATE '2027-01-01'),
    PARTITION P_MAX  VALUES LESS THAN (MAXVALUE)
);
```

این ساختار می‌تواند برای سیستم‌های پرتراکنش و جداول بسیار بزرگ مفید باشد.

## **3. Partitioning چه زمانی مفید است؟**

| شرایط                                          | Partitioning مفید است؟          |
| ---------------------------------------------- | ------------------------------- |
| جدول چند میلیون یا میلیارد رکورد دارد          | بله، ممکن است                   |
| Queryها معمولاً روی تاریخ فیلتر می‌شوند        | بسیار مناسب                     |
| داده‌های قدیمی باید حذف یا Archive شوند        | بسیار مناسب                     |
| جدول کوچک است                                  | معمولاً خیر                     |
| Queryها تقریباً همیشه کل جدول را می‌خوانند     | لزوماً خیر                      |
| فیلترهای Query با Partition Key ارتباطی ندارند | سود Partition Pruning محدود است |

نکته مهم مصاحبه:

Partitioning به‌تنهایی تضمین نمی‌کند Query سریع‌تر شود. اگر Query به Partition Key فیلتر نداشته باشد، ممکن است Oracle مجبور شود چندین Partition یا همه آنها را بررسی کند.

همچنین Partitioning جای Index را نمی‌گیرد؛ در بسیاری از سیستم‌ها از هر دو استفاده می‌شود.

# **4. Sequence در Oracle**

## **Sequence چیست؟**

Sequence یک Object در Oracle است که اعداد را طبق تنظیمات تولید می‌کند.

معمولاً برای تولید شناسه‌های یکتا در جدول استفاده می‌شود.

مثلاً:

```
1001
1002
1003
1004
1005
```

در Oracle، Sequence از جدول مستقل است و تولید عدد آن به رکوردهای جدول وابسته نیست.

## **5. ایجاد Sequence**

```
CREATE SEQUENCE ORDER_SEQ
START WITH 1
INCREMENT BY 1
NOCACHE
NOCYCLE;
```

معنی تنظیمات:

| گزینه          | توضیح                                         |
| -------------- | --------------------------------------------- |
| `START WITH`   | عدد شروع                                      |
| `INCREMENT BY` | مقدار افزایش                                  |
| `CACHE`        | ذخیره تعدادی از Sequence valueها در حافظه     |
| `NOCACHE`      | بدون Cache                                    |
| `CYCLE`        | بعد از رسیدن به حد، دوباره از ابتدا ادامه دهد |
| `NOCYCLE`      | بعد از حد مجاز متوقف شود                      |
| `MAXVALUE`     | بیشترین مقدار                                 |
| `MINVALUE`     | کمترین مقدار                                  |

در محیط Production معمولاً `CACHE` انتخاب مناسبی برای performance است، مگر اینکه نیاز خاصی وجود داشته باشد.

## **6. استفاده از Sequence**

### **گرفتن مقدار بعدی**

```
SELECT ORDER_SEQ.NEXTVAL
FROM DUAL;
```

خروجی:

```
NEXTVAL
-------
1
```

### **گرفتن مقدار فعلی**

```
SELECT ORDER_SEQ.CURRVAL
FROM DUAL;
```

نکته: `CURRVAL` در همان Session فقط بعد از اینکه `NEXTVAL` برای آن Sequence فراخوانی شده باشد قابل استفاده است.

## **7. استفاده Sequence در INSERT**

```
INSERT INTO ORDERS (
    ORDER_ID,
    ORDER_DATE,
    AMOUNT
)
VALUES (
    ORDER_SEQ.NEXTVAL,
    SYSDATE,
    2500
);
```

در این حالت Oracle شناسه جدید تولید می‌کند.

## **8. Sequence با Trigger**

در سیستم‌های قدیمی Oracle معمولاً از Trigger برای تولید ID استفاده می‌شد.

```
CREATE OR REPLACE TRIGGER TRG_ORDERS_BI
BEFORE INSERT ON ORDERS
FOR EACH ROW
BEGIN
    IF :NEW.ORDER_ID IS NULL THEN
        :NEW.ORDER_ID := ORDER_SEQ.NEXTVAL;
    END IF;
END;
/
```

در این صورت حتی اگر هنگام INSERT مقدار `ORDER_ID` ارسال نشود، Trigger آن را ایجاد می‌کند.

مزیت: کلاینت یا برنامه مجبور نیست خودش ID تولید کند.

در نسخه‌های جدید Oracle، Identity Column نیز می‌تواند جایگزین ساده‌تری باشد.

## **9. Sequence و Identity Column چه تفاوتی دارند؟**

در نسخه‌های جدید Oracle، به‌جای ایجاد Sequence و Trigger به‌صورت جداگانه، می‌توان از `IDENTITY` استفاده کرد.

### **روش قدیمی**

```
CREATE TABLE EMPLOYEES (
    ID NUMBER PRIMARY KEY,
    NAME VARCHAR2(100)
);

CREATE SEQUENCE EMP_SEQ START WITH 1 INCREMENT BY 1;
```

و سپس:

```
INSERT INTO EMPLOYEES (ID, NAME)
VALUES (EMP_SEQ.NEXTVAL, 'Ali');
```

### **روش جدید: Identity**

```
CREATE TABLE EMPLOYEES (
    ID NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    NAME VARCHAR2(100)
);
```

حالا:

```
INSERT INTO EMPLOYEES (NAME)
VALUES ('Ali');
```

Oracle خودش مقدار `ID` را تولید می‌کند.

| ویژگی                     | Sequence                | Identity                       |
| ------------------------- | ----------------------- | ------------------------------ |
| Object مستقل              | بله                     | معمولاً Sequence داخلی         |
| استفاده در چند جدول       | بله                     | مخصوص همان ستون                |
| استفاده دستی از `NEXTVAL` | بله                     | معمولاً مستقیم استفاده نمی‌شود |
| نیاز به Trigger           | در صورت نیاز            | خیر                            |
| کنترل و انعطاف            | بیشتر                   | ساده‌تر                        |
| کاربرد                    | شناسه عمومی و کنترل‌شده | ID خودکار جدول                 |

## **10. نکته بسیار مهم درباره Sequence**

Sequence الزاماً اعداد بدون فاصله تولید نمی‌کند.

مثلاً:

```
100
101
102
105
106
```

ممکن است اعداد 103 و 104 از دست رفته باشند.

چرا؟

- Transaction Rollback
- استفاده از `CACHE`
- Restart یا Crash دیتابیس
- مصرف Sequence در Transactionهایی که Insert آنها انجام نشده
- استفاده هم‌زمان توسط Sessionهای مختلف

مثلاً:

```
INSERT INTO ORDERS (ID)
VALUES (ORDER_SEQ.NEXTVAL);
```

اگر Transaction بعداً Rollback شود، مقدار Sequence لزوماً به عقب برنمی‌گردد.

Sequence برای تولید شناسه یکتا است، نه شماره‌گذاری بدون فاصله.

اگر الزام Business داری که شماره فاکتور بدون فاصله باشد، Sequence به‌تنهایی راهکار مناسبی نیست؛ باید مکانیزم شماره‌گذاری کنترل‌شده و Transactional جداگانه طراحی شود، با در نظر گرفتن concurrency و performance.

# **11. Partitioning و Sequence چه ارتباطی با هم دارند؟**

این دو قابلیت مستقل هستند، اما می‌توانند در یک جدول استفاده شوند.

مثلاً یک جدول بزرگ سفارش:

```
CREATE TABLE ORDERS (
    ORDER_ID   NUMBER,
    ORDER_DATE DATE,
    CUSTOMER_ID NUMBER,
    AMOUNT NUMBER
)
PARTITION BY RANGE (ORDER_DATE)
(
    PARTITION P2025 VALUES LESS THAN (DATE '2026-01-01'),
    PARTITION P2026 VALUES LESS THAN (DATE '2027-01-01'),
    PARTITION P_MAX  VALUES LESS THAN (MAXVALUE)
);
```

برای تولید شناسه:

```
CREATE SEQUENCE ORDER_SEQ
START WITH 1
INCREMENT BY 1
CACHE 1000;
```

در زمان Insert:

```
INSERT INTO ORDERS (
    ORDER_ID,
    ORDER_DATE,
    CUSTOMER_ID,
    AMOUNT
)
VALUES (
    ORDER_SEQ.NEXTVAL,
    SYSDATE,
    1001,
    5000
);
```

- Sequence مقدار `ORDER_ID` را تولید می‌کند.
- Partitioning مشخص می‌کند رکورد در کدام Partition ذخیره شود، بر اساس `ORDER_DATE`.

# **12. نکات مهم مصاحبه Senior Java / Oracle**

اگر در مصاحبه از تو پرسیدند Partitioning چه مشکلاتی را حل می‌کند، این جواب مناسب است:

> Partitioning is used to improve manageability and query performance for large tables. It allows Oracle to divide a table into smaller logical partitions based on a partition key. Features like partition pruning can reduce the amount of data scanned. It is also useful for archiving and purging historical data. However, partitioning is not always beneficial, and it should be designed based on query patterns and data volume.

و درباره Sequence:

> An Oracle sequence is a database object used to generate numeric values, typically for primary keys. It is concurrency-safe and performs well for multiple sessions. However, sequences are not gap-free because values can be lost due to rollbacks, caching, or instance failures. Therefore, I use sequences for unique identifiers, not for generating gapless business numbers.

## **خلاصه نهایی**

| موضوع                  | Partitioning                  | Sequence                        |
| ---------------------- | ----------------------------- | ------------------------------- |
| هدف                    | تقسیم و مدیریت داده‌های حجیم  | تولید عدد                       |
| مشکل اصلی که حل می‌کند | حجم زیاد داده و مدیریت آن     | تولید ID                        |
| اثر بر Performance     | در شرایط مناسب بهبود Query    | کاهش نیاز به ID generation دستی |
| وابسته به Query        | بله، Partition Key اهمیت دارد | خیر                             |
| مثال                   | تقسیم Orders بر اساس تاریخ    | تولید Order ID                  |
| جایگزین Index است؟     | خیر                           | ارتباطی با Index ندارد          |
| تضمین شماره بدون فاصله | ندارد                         | ندارد                           |

اگر بخواهی در مرحله بعد، یکی از مباحث مهم Oracle برای مصاحبه Senior را بررسی کنیم، پیشنهاد من **Deadlock، Blocking و تشخیص آن در Oracle با مثال واقعی دو Transaction** است؛ چون ارتباط مستقیم با Lock، Transaction و Performance دارد.
