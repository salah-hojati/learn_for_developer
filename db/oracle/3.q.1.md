## 🧠 Section A: Foundation & Architecture

**Q1.** What is the difference between an **Oracle Instance** and an **Oracle Database**?

**Q2.** In Multitenant Architecture, what do **CDB** and **PDB** stand for, and how do they relate?

**Q3.** What is the purpose of the `DUAL` table?

**Q4.** Name three differences between a **Primary Key** and a **Foreign Key**.

**Q5.** What does the **Listener** do?

<details>
<summary><b>✅ Answers — Section A</b></summary>

**A1.** The **Instance** is the running software in memory (SGA memory + background processes). The **Database** is the physical files on disk (data files, control files, redo logs). You can have an instance without a mounted database (NOMOUNT), but normally they work together.

**A2.** **CDB** = Container Database (the root container). **PDB** = Pluggable Database (a self-contained database inside the CDB). One CDB can host many PDBs; each PDB looks like a separate database to users.

**A3.** `DUAL` is a special one-row, one-column dummy table used to run `SELECT` statements that don't need real table data — e.g., `SELECT SYSDATE FROM DUAL;` or `SELECT 1+1 FROM DUAL;`.

**A4.** (1) PK uniquely identifies a row in **its own** table; FK references a PK in **another** (or same) table. (2) PK cannot be NULL; FK can be NULL (unless constrained). (3) A table can have only one PK but many FKs. (4) PK enforces uniqueness; FK enforces referential integrity.

**A5.** The Listener is a background process that listens on a port (default 1521) for incoming client connection requests and hands them off to the appropriate database service (e.g., `FREEPDB1`).

</details>

## 📜 Section B: SQL

**Q6.** What is the logical order of execution of a `SELECT` statement's clauses? (Not the written order.)

**Q7.** What is the difference between `WHERE` and `HAVING`?

**Q8.** What is the difference between `INNER JOIN` and `LEFT JOIN`?

**Q9.** Write a query: show `department_id` and the **number of employees** in each department, but only for departments with **more than 5 employees**, sorted by count descending.

**Q10.** What's wrong with this statement, and how do you fix it?
```sql
DELETE FROM employees;
```

**Q11.** Explain the difference between `COMMIT` and `ROLLBACK`.

**Q12.** What does `TRUNCATE TABLE` do, and how is it different from `DELETE FROM`?

**Q13.** Write a query using an analytic function to show each employee's name, salary, and their **rank by salary within their department** (highest salary = rank 1).

<details>
<summary><b>✅ Answers — Section B</b></summary>

**A6.** Written order: `SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY`. **Execution order:** `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`. (This is why you can't use a `SELECT` alias in `WHERE`, but you can in `ORDER BY`.)

**A7.** `WHERE` filters **individual rows before grouping**. `HAVING` filters **groups after `GROUP BY`** (typically used with aggregate functions).

**A8.** `INNER JOIN` returns only rows that match in **both** tables. `LEFT JOIN` returns **all rows from the left table** plus matches from the right; unmatched right-side columns appear as `NULL`.

**A9.**
```sql
SELECT department_id, COUNT(*) AS emp_count
FROM employees
GROUP BY department_id
HAVING COUNT(*) > 5
ORDER BY emp_count DESC;
```

**A10.** It has **no `WHERE` clause**, so it deletes **every row** in `employees`. Fix it by adding a filter, e.g.:
```sql
DELETE FROM employees WHERE department_id = 999;
```
Always test with `SELECT *` using the same `WHERE` first, and remember you can `ROLLBACK` before `COMMIT`.

**A11.** `COMMIT` makes all changes since the last commit **permanent**. `ROLLBACK` **undoes** all uncommitted changes back to the last commit point.

**A12.** `TRUNCATE` removes **all rows** quickly (no row-by-row undo, minimal redo), resets high-water mark, and is **DDL — it auto-commits and cannot be rolled back**. `DELETE FROM` is DML: it can have a `WHERE`, generates undo, can be rolled back, and fires triggers.

**A13.**
```sql
SELECT first_name, last_name, department_id, salary,
       RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS salary_rank
FROM employees;
```

</details>

## ⚙️ Section C: PL/SQL

**Q14.** What are the four sections of a PL/SQL block, and which is mandatory?

**Q15.** What is the difference between `%TYPE` and `%ROWTYPE`?

**Q16.** What does the `EXIT WHEN` statement do inside a loop?

**Q17.** What is the difference between a **procedure** and a **function**?

**Q18.** In cursor processing, what does `c_emps%NOTFOUND` mean?

**Q19.** What is wrong with this exception handler?
```sql
EXCEPTION
   WHEN OTHERS THEN
      NULL;
```

**Q20.** Write a function that takes `p_dept_id` and returns the **average salary** of that department. Return `0` if no employees are found.

**Q21.** What is a **trigger**, and what does `:OLD` vs `:NEW` refer to in a row-level trigger?

<details>
<summary><b>✅ Answers — Section C</b></summary>

**A14.** `DECLARE` (optional), `BEGIN` (mandatory), `EXCEPTION` (optional), `END` (mandatory). Only `BEGIN ... END` is required.

**A15.** `%TYPE` anchors a variable to the data type of a **single column** (e.g., `v_name employees.first_name%TYPE`). `%ROWTYPE` anchors a record to an **entire row** of a table or cursor (e.g., `v_emp employees%ROWTYPE`).

**A16.** `EXIT WHEN <condition>` exits the current loop as soon as the condition is true. Typically `EXIT WHEN c_emps%NOTFOUND;` after a `FETCH`.

**A17.** A **function** must `RETURN` a single value and can be called **inside SQL statements** (e.g., `SELECT get_dept_name(10) FROM DUAL`). A **procedure** performs an action, may return values via `OUT` parameters, and is called from PL/SQL with `BEGIN proc_name; END;`.

**A18.** It means the last `FETCH` did **not** retrieve a row (either the cursor is exhausted or empty). You use it to exit the fetch loop.

**A19.** `WHEN OTHERS THEN NULL;` **silently swallows** all errors. This hides bugs and makes debugging nearly impossible. Better:
```sql
WHEN OTHERS THEN
   DBMS_OUTPUT.PUT_LINE('Error: ' || SQLERRM);
   RAISE;   -- or log to an error table
```

**A20.**
```sql
CREATE OR REPLACE FUNCTION avg_salary(p_dept_id IN NUMBER) RETURN NUMBER IS
   v_avg NUMBER;
BEGIN
   SELECT AVG(salary) INTO v_avg
   FROM employees
   WHERE department_id = p_dept_id;

   RETURN NVL(v_avg, 0);
EXCEPTION
   WHEN NO_DATA_FOUND THEN
      RETURN 0;
END;
/
```
> Note: `AVG()` with no matching rows returns `NULL`, not `NO_DATA_FOUND`, so `NVL(v_avg, 0)` handles the empty case. The `NO_DATA_FOUND` handler is defensive.

**A21.** A **trigger** is a stored PL/SQL block that fires **automatically** in response to a DML event (`INSERT`/`UPDATE`/`DELETE`) on a table. In a `FOR EACH ROW` trigger: `:OLD` = the row's values **before** the change (NULL on INSERT), `:NEW` = values **after** the change (NULL on DELETE).

</details>
