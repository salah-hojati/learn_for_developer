PL/SQL adds variables, loops, conditions, error handling, and reusable modules (procedures, functions, packages, triggers) to SQL.

### 🧱 Step 1: Understand PL/SQL Block Structure

Every PL/SQL program is a **block**. The basic structure is:

```sql
DECLARE
   -- optional: variables, cursors, types
BEGIN
   -- mandatory: executable statements
EXCEPTION
   -- optional: error handling
END;
/
```

- **Anonymous block**: not stored in the database; runs once. Great for learning.
- **Named block**: stored as a procedure, function, package, or trigger.

**Hands-on**: Run this in SQL Developer or Live SQL:

```sql
DECLARE
   v_message VARCHAR2(50) := 'Hello from PL/SQL!';
BEGIN
   DBMS_OUTPUT.PUT_LINE(v_message);
END;
/
```

> **Note**: In SQL Developer, enable `DBMS_OUTPUT` by clicking the "DBMS Output" tab and turning it on. In Live SQL, output appears automatically.

### 📦 Step 2: Variables, Data Types, and Assignment

Learn to declare variables and assign values.

- Use `%TYPE` to match a column’s data type.
- Use `%ROWTYPE` to match an entire row.

```sql
DECLARE
   v_emp_name   employees.first_name%TYPE;
   v_emp_salary employees.salary%TYPE := 5000;
   v_emp_row    employees%ROWTYPE;
BEGIN
   SELECT first_name, salary
   INTO v_emp_name, v_emp_salary
   FROM employees
   WHERE employee_id = 100;

   DBMS_OUTPUT.PUT_LINE('Name: ' || v_emp_name || ', Salary: ' || v_emp_salary);
END;
/
```

**Practice**: Write a block that fetches the department name for department_id 10 and prints it.

### 🔀 Step 3: Control Structures — IF and Loops

PL/SQL gives you procedural control.

**IF-THEN-ELSIF-ELSE**:

```sql
DECLARE
   v_salary employees.salary%TYPE := 12000;
BEGIN
   IF v_salary > 15000 THEN
      DBMS_OUTPUT.PUT_LINE('High salary');
   ELSIF v_salary > 8000 THEN
      DBMS_OUTPUT.PUT_LINE('Medium salary');
   ELSE
      DBMS_OUTPUT.PUT_LINE('Low salary');
   END IF;
END;
/
```

**Loops** — three common types:

```sql
-- Basic LOOP
DECLARE
   i NUMBER := 1;
BEGIN
   LOOP
      DBMS_OUTPUT.PUT_LINE('i = ' || i);
      i := i + 1;
      EXIT WHEN i > 3;
   END LOOP;
END;
/

-- FOR loop (most common)
BEGIN
   FOR i IN 1..3 LOOP
      DBMS_OUTPUT.PUT_LINE('i = ' || i);
   END LOOP;
END;
/

-- WHILE loop
DECLARE
   i NUMBER := 1;
BEGIN
   WHILE i <= 3 LOOP
      DBMS_OUTPUT.PUT_LINE('i = ' || i);
      i := i + 1;
   END LOOP;
END;
/
```

**Practice**: Write a FOR loop that prints the first 10 employee last names from the `employees` table.

### 🎯 Step 4: Cursors — Row-by-Row Processing

A **cursor** lets you process a query result set one row at a time.

- **Implicit cursor**: automatically created for every DML/SELECT.
- **Explicit cursor**: declared and controlled by you.

```sql
DECLARE
   CURSOR c_emps IS
      SELECT first_name, salary FROM employees WHERE department_id = 50;

   v_name   employees.first_name%TYPE;
   v_sal    employees.salary%TYPE;
BEGIN
   OPEN c_emps;
   LOOP
      FETCH c_emps INTO v_name, v_sal;
      EXIT WHEN c_emps%NOTFOUND;
      DBMS_OUTPUT.PUT_LINE(v_name || ' earns ' || v_sal);
   END LOOP;
   CLOSE c_emps;
END;
/
```

**Better approach**: Use a **cursor FOR loop** — Oracle handles open/fetch/close automatically.

```sql
BEGIN
   FOR rec IN (SELECT first_name, salary FROM employees WHERE department_id = 50) LOOP
      DBMS_OUTPUT.PUT_LINE(rec.first_name || ' earns ' || rec.salary);
   END LOOP;
END;
/
```

**Practice**: Use a cursor FOR loop to print department_id and department_name from `departments`.

### 🛡️ Step 5: Exception Handling

Robust code handles errors gracefully.

- **Predefined exceptions**: `NO_DATA_FOUND`, `TOO_MANY_ROWS`, `ZERO_DIVIDE`.
- **User-defined exceptions**: declare your own.
- **`WHEN OTHERS`**: catch-all (use carefully; log the error).

```sql
DECLARE
   v_name employees.first_name%TYPE;
BEGIN
   SELECT first_name INTO v_name
   FROM employees
   WHERE employee_id = -1;   -- no such employee

   DBMS_OUTPUT.PUT_LINE('Name: ' || v_name);
EXCEPTION
   WHEN NO_DATA_FOUND THEN
      DBMS_OUTPUT.PUT_LINE('No employee found with that ID.');
   WHEN TOO_MANY_ROWS THEN
      DBMS_OUTPUT.PUT_LINE('Query returned more than one row.');
   WHEN OTHERS THEN
      DBMS_OUTPUT.PUT_LINE('Unexpected error: ' || SQLERRM);
END;
/
```

**Practice**: Write a block that divides 10 by a variable. Set the variable to 0, handle `ZERO_DIVIDE`, and print a friendly message.

### 🧩 Step 6: Stored Procedures and Functions

These are **named PL/SQL blocks stored in the database** so you can reuse them.

**Procedure** — performs an action; may have `IN`, `OUT`, `IN OUT` parameters.

```sql
CREATE OR REPLACE PROCEDURE raise_salary (
   p_emp_id IN employees.employee_id%TYPE,
   p_percent IN NUMBER
) IS
BEGIN
   UPDATE employees
   SET salary = salary * (1 + p_percent/100)
   WHERE employee_id = p_emp_id;

   IF SQL%ROWCOUNT = 0 THEN
      DBMS_OUTPUT.PUT_LINE('No employee updated.');
   ELSE
      DBMS_OUTPUT.PUT_LINE('Salary updated for employee ' || p_emp_id);
   END IF;

   COMMIT;
END;
/
```

Call it:

```sql
BEGIN
   raise_salary(100, 10);
END;
/
```

**Function** — must return a value.

```sql
CREATE OR REPLACE FUNCTION get_dept_name (
   p_dept_id IN departments.department_id%TYPE
) RETURN VARCHAR2 IS
   v_name departments.department_name%TYPE;
BEGIN
   SELECT department_name INTO v_name
   FROM departments
   WHERE department_id = p_dept_id;

   RETURN v_name;
EXCEPTION
   WHEN NO_DATA_FOUND THEN
      RETURN 'Unknown Department';
END;
/
```

Use it in SQL:

```sql
SELECT employee_id, first_name, get_dept_name(department_id) AS dept
FROM employees
WHERE ROWNUM <= 5;
```

**Practice**: Create a function that returns the average salary for a given department_id.

### 📚 Step 7: Packages — Group Related Code

A **package** bundles related procedures, functions, variables, and cursors. It has two parts:

- **Specification** (public interface)
- **Body** (implementation)

```sql
-- Specification
CREATE OR REPLACE PACKAGE emp_pkg IS
   PROCEDURE raise_salary(p_emp_id IN NUMBER, p_percent IN NUMBER);
   FUNCTION get_dept_name(p_dept_id IN NUMBER) RETURN VARCHAR2;
END emp_pkg;
/

-- Body
CREATE OR REPLACE PACKAGE BODY emp_pkg IS

   PROCEDURE raise_salary(p_emp_id IN NUMBER, p_percent IN NUMBER) IS
   BEGIN
      UPDATE employees
      SET salary = salary * (1 + p_percent/100)
      WHERE employee_id = p_emp_id;
      COMMIT;
   END raise_salary;

   FUNCTION get_dept_name(p_dept_id IN NUMBER) RETURN VARCHAR2 IS
      v_name departments.department_name%TYPE;
   BEGIN
      SELECT department_name INTO v_name
      FROM departments
      WHERE department_id = p_dept_id;
      RETURN v_name;
   EXCEPTION
      WHEN NO_DATA_FOUND THEN
         RETURN 'Unknown';
   END get_dept_name;

END emp_pkg;
/
```

Call package members:

```sql
BEGIN
   emp_pkg.raise_salary(100, 5);
   DBMS_OUTPUT.PUT_LINE(emp_pkg.get_dept_name(10));
END;
/
```

**Practice**: Add a function `get_employee_count` to the package that returns the number of employees in a given department.

### ⚡ Step 8: Triggers — Automatic Actions

A **trigger** fires automatically in response to DML events (`INSERT`, `UPDATE`, `DELETE`) on a table.

Common uses: auditing, enforcing complex rules, auto-populating columns.

```sql
-- Audit table
CREATE TABLE salary_audit (
   audit_id    NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
   emp_id      NUMBER,
   old_salary  NUMBER,
   new_salary  NUMBER,
   changed_on  DATE DEFAULT SYSDATE
);

-- Trigger
CREATE OR REPLACE TRIGGER trg_salary_audit
AFTER UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
   INSERT INTO salary_audit (emp_id, old_salary, new_salary)
   VALUES (:OLD.employee_id, :OLD.salary, :NEW.salary);
END;
/
```

Test it:

```sql
UPDATE employees SET salary = salary + 100 WHERE employee_id = 100;
COMMIT;
SELECT * FROM salary_audit;
```

**Practice**: Create a BEFORE INSERT trigger on a test table that automatically sets a `created_date` column to `SYSDATE` if it is null.
