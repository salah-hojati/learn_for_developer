### 4. `RedisStartupCheck.java` — pings Redis on boot

This is the **most useful file** for your setup: if the network path is wrong, you'll see it in the startup log immediately, before touching any endpoint.

```java
package com.example.redislearn;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.ApplicationRunner;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Component;

@Component
public class RedisStartupCheck implements ApplicationRunner {

    private static final Logger log = LoggerFactory.getLogger(RedisStartupCheck.class);
    private final StringRedisTemplate redis;

    public RedisStartupCheck(StringRedisTemplate redis) {
        this.redis = redis;
    }

    @Override
    public void run(ApplicationArguments args) {
        try {
            String pong = redis.getConnectionFactory().getConnection().ping();
            log.info("✅ Redis connection OK — PING returned: {}", pong);
        } catch (Exception e) {
            log.error("❌ Redis connection FAILED: {}", e.getMessage());
        }
    }
}
```

Expected log line on success:

```
✅ Redis connection OK — PING returned: PONG
```

### 5. `RedisController.java` — SET / GET / TTL / INCR / DELETE

```java
package com.example.redislearn;

import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.time.Duration;
import java.util.LinkedHashMap;
import java.util.Map;

@RestController
@RequestMapping("/redis")
public class RedisController {

    private final StringRedisTemplate redis;

    public RedisController(StringRedisTemplate redis) {
        this.redis = redis;
    }

    /** Health check against Redis */
    @GetMapping("/ping")
    public Map<String, Object> ping() {
        String pong = redis.getConnectionFactory().getConnection().ping();
        return Map.of("ping", pong == null ? "null" : pong);
    }

    /** SET with optional TTL (in seconds) */
    @PostMapping("/set")
    public Map<String, Object> set(@RequestParam String key,
                                   @RequestParam String value,
                                   @RequestParam(required = false) Long ttlSeconds) {
        if (ttlSeconds != null) {
            redis.opsForValue().set(key, value, Duration.ofSeconds(ttlSeconds));
        } else {
            redis.opsForValue().set(key, value);
        }
        Map<String, Object> resp = new LinkedHashMap<>();
        resp.put("key", key);
        resp.put("value", value);
        resp.put("ttlSeconds", ttlSeconds == null ? "none" : ttlSeconds);
        return resp;
    }

    /** GET value + remaining TTL */
    @GetMapping("/get")
    public Map<String, Object> get(@RequestParam String key) {
        String value = redis.opsForValue().get(key);
        Long ttl = redis.getExpire(key);
        Map<String, Object> resp = new LinkedHashMap<>();
        resp.put("key", key);
        resp.put("value", value == null ? "null" : value);
        resp.put("ttlSeconds", ttl);   // -1 = no expiry, -2 = key doesn't exist
        return resp;
    }

    /** INCR — a classic Redis counter (great for learning atomicity) */
    @PostMapping("/incr")
    public Map<String, Object> incr(@RequestParam String key) {
        Long v = redis.opsForValue().increment(key);
        return Map.of("key", key, "value", v);
    }

    /** DELETE */
    @DeleteMapping("/delete")
    public Map<String, Object> delete(@RequestParam String key) {
        Boolean deleted = redis.delete(key);
        return Map.of("key", key, "deleted", Boolean.TRUE.equals(deleted));
    }
}
```

### ▶️ Run and Verify (End-to-End)

**Step 1 — Start the app in IntelliJ** (run `RedisLearnApplication`).

Watch the console. You should see:

```
✅ Redis connection OK — PING returned: PONG
...
Tomcat started on port 8080
```

If you see `❌ Redis connection FAILED`, jump to the troubleshooting table below.

**Step 2 — Hit the endpoints from Windows PowerShell**

Use `curl.exe` (not `curl` — PowerShell aliases `curl` to `Invoke-WebRequest` and the flags differ):

```powershell
# 1) Ping
curl.exe "http://localhost:8080/redis/ping"
# {"ping":"PONG"}

# 2) SET with 60s TTL
curl.exe -X POST "http://localhost:8080/redis/set?key=hello&value=world&ttlSeconds=60"
# {"key":"hello","value":"world","ttlSeconds":60}

# 3) GET (check value + TTL)
curl.exe "http://localhost:8080/redis/get?key=hello"
# {"key":"hello","value":"world","ttlSeconds":58}

# 4) Counter
curl.exe -X POST "http://localhost:8080/redis/incr?key=pageviews"
curl.exe -X POST "http://localhost:8080/redis/incr?key=pageviews"
curl.exe -X POST "http://localhost:8080/redis/incr?key=pageviews"
# {"key":"pageviews","value":3}

# 5) Delete
curl.exe -X DELETE "http://localhost:8080/redis/delete?key=hello"
# {"key":"hello","deleted":true}

# 6) Confirm it's gone
curl.exe "http://localhost:8080/redis/get?key=hello"
# {"key":"hello","value":"null","ttlSeconds":-2}
```

**Step 3 — Verify from a third angle (IntelliJ Redis console)**

Open the **Database** tool window → select your Redis data source → open the console → run:

```
KEYS *
GET pageviews
TTL hello
```

You should see `pageviews = 3` and `hello` gone. This proves the whole chain: **IntelliJ → Windows → Linux → Docker → Redis**.

**Step 4 — (Optional) Verify on the Linux host**

```bash
docker exec -it redis-server redis-cli -a YourStrongPassword123
127.0.0.1:6379> KEYS *
127.0.0.1:6379> GET pageviews
```

### 🩺 Troubleshooting the End-to-End Path

| Symptom (in Spring Boot log) | Cause | Fix |
|---|---|---|
| `Connection refused` | Linux firewall blocking 6379 | `sudo firewall-cmd --add-port=6379/tcp --permanent && sudo firewall-cmd --reload` (or `ufw allow 6379/tcp`) |
| `NOAUTH Authentication required` | Password missing in `application.yml` | Add `spring.data.redis.password` matching `--requirepass` |
| `WRONGPASS invalid username-password` | Password mismatch | Double-check both sides |
| `Connection timed out` | Wrong IP, or Redis not reachable | Re-run `Test-NetConnection 192.168.1.100 -Port 6379` from Windows |
| Boots fine, but `ping` fails inside endpoints | Rare; usually a stale Lettuce connection after container restart | Restart the app (or add a retry/`@EventListener` — advanced topic) |
| Works from Linux, not Windows | Firewall (again) or different subnet | Check `ip addr` on Linux and ping it from Windows |

### 🎯 What to Learn Next From This Base

Once these endpoints work, you can extend the **same project** to practice each Redis concept from your course:

- **Hash** → `opsForHash()` (store a user object)
- **List** → `opsForList()` (simple queue)
- **Set / SortedSet** → `opsForSet()` / `opsForZSet()` (leaderboards, unique visitors)
- **Pub/Sub** → `RedisMessageListenerContainer` (a chat demo)
- **Caching** → `@Cacheable` with `RedisCacheManager` (Spring caching abstraction)
- **Distributed lock** → `SET key value NX PX` via `setIfAbsent`

You can swap `StringRedisTemplate` for a `RedisTemplate<String, Object>` with JSON serialization when you start storing objects — that's a good lesson too.
