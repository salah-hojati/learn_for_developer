تفاوت اصلی بین `$lookup` و `$graphLookup` در ماهیت عملیات آن‌هاست: `$lookup` یک **اتصال (Join) ساده** بین دو مجموعه انجام می‌دهد، در حالی که `$graphLookup` یک **جستجوی بازگشتی (Recursive Search)** برای پیمایش ساختارهای سلسله‌مراتبی یا گرافی است.

### 🆚 مقایسه مستقیم

| ویژگی | `$lookup` | `$graphLookup` |
| :--- | :--- | :--- |
| **نوع عملیات** | اتصال چپ خارجی (Left Outer Join) ساده | جستجوی بازگشتی و پیمایش گراف |
| **هدف اصلی** | ترکیب اسناد از دو مجموعه بر اساس یک شرط برابری | دنبال کردن زنجیره‌ای از ارجاعات در یک مجموعه (مانند روابط والد-فرزند) |
| **نسخه معرفی** | MongoDB 3.2 | MongoDB 3.4 |
| **عمق جستجو** | فقط **یک سطح** ارتباط را بررسی می‌کند | می‌تواند **چندین سطح** را به صورت بازگشتی طی کند |
| **مناسب برای** | داده‌های رابطه‌ای ساده (مثل اتصال سفارش به کاربر) | داده‌های سلسله‌مراتبی یا گرافی (مثل ساختار سازمانی، دسته‌بندی محصولات، شبکه‌های اجتماعی) |

### 📌 `$lookup`: اتصال ساده و تک‌سطحی
عملگر `$lookup` برای انجام یک **اتصال چپ خارجی (Left Outer Join)** طراحی شده است. این عملگر به شما اجازه می‌دهد تا اسنادی از یک مجموعه دیگر را که با یک شرط خاص (معمولاً برابری یک فیلد با فیلد دیگر) مطابقت دارند، به اسناد فعلی اضافه کنید. این اتصال **فقط یک سطح** عمق دارد و روابط بازگشتی را دنبال نمی‌کند.

**مثال کاربردی:** فرض کنید مجموعه‌ای از `orders` (سفارشات) و `users` (کاربران) دارید. می‌خواهید اطلاعات کاربر هر سفارش را به آن اضافه کنید.
```javascript
db.orders.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "user_id",
      foreignField: "_id",
      as: "user_info"
    }
  }
])
```
این عملیات برای هر سفارش، سند کاربر مربوطه را در فیلد `user_info` قرار می‌دهد.

### 📌 `$graphLookup`: جستجوی بازگشتی برای داده‌های گرافی
عملگر `$graphLookup` برای انجام **جستجوهای بازگشتی** روی مجموعه‌ای از اسناد طراحی شده است که ساختار گراف یا درخت را تشکیل می‌دهند. این عملگر با دنبال کردن یک زنجیره از ارجاعات (مثلاً از یک `parentId` به `_id` بعدی)، می‌تواند به صورت خودکار چندین سطح از ارتباطات را طی کند.

**مثال کاربردی:** ساختار یک سازمان را در نظر بگیرید که در آن هر کارمند یک فیلد `reportsTo` دارد که به `name` مدیر خود اشاره می‌کند. برای پیدا کردن **تمام** زیردستان (مستقیم و غیرمستقیم) یک مدیر، از `$graphLookup` استفاده می‌کنید:
```javascript
db.employees.aggregate([
  { $match: { name: "Alice" } }, // شروع از مدیر
  {
    $graphLookup: {
      from: "employees",
      startWith: "$name", // از نام Alice شروع کن
      connectFromField: "name", // فیلد فعلی را به ...
      connectToField: "reportsTo", // ... فیلد reportsTo در سند بعدی وصل کن
      as: "allReports" // نتیجه در این فیلد ذخیره شود
    }
  }
])
```
این کوئری تمام کارمندانی را که به طور مستقیم یا غیرمستقیم به "Alice" گزارش می‌دهند، در فیلد `allReports` برمی‌گرداند.

### 💎 جمع‌بندی
- اگر نیاز به **ترکیب داده‌های دو مجموعه** بر اساس یک رابطه ساده و تک‌سطحی دارید (مثل اتصال یک سند به سند دیگر)، از **`$lookup`** استفاده کنید.
- اگر می‌خواهید **روابط سلسله‌مراتبی یا شبکه‌ای را به صورت بازگشتی پیمایش کنید** (مثل پیدا کردن تمام زیرمجموعه‌های یک دسته‌بندی یا تمام زیردستان یک مدیر)، **`$graphLookup`** ابزار مناسب است.
