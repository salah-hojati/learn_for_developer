Here is a step-by-step tutorial to learn MongoDB with Java and Spring Boot. We will build a simple **Task Manager** application, covering the essential concepts from project setup to advanced queries.

---

### Step 1: Set Up Your Environment

First, you need a MongoDB database and a Spring Boot project.

**1.1 Run MongoDB with Docker**
The easiest way to get started is to run MongoDB in a Docker container. Create a `compose.yml` file in your project directory:

```yaml
services:
  mongodb:
    image: mongo:latest
    container_name: mongodb
    ports:
      - "27017:27017"
    environment:
      - MONGO_INITDB_DATABASE=taskdb
    volumes:
      - mongo_data:/data/db
volumes:
  mongo_data:
```
Then, start the container by running `docker-compose up -d` in your terminal.

**1.2 Generate the Spring Boot Project**
Go to **Spring Initializr** (start.spring.io) and create a new project with the following dependencies:
- **Spring Web**
- **Spring Data MongoDB**

### Step 2: Configure the Application

Open the generated project and configure the connection to your MongoDB instance. In your `src/main/resources/application.properties` file, add:

```properties
spring.data.mongodb.uri=mongodb://localhost:27017/taskdb
# Optional: Enable debug logging to see the generated queries
logging.level.org.springframework.data.mongodb.core.MongoTemplate=DEBUG
```
This tells Spring Boot where to find your database.

### Step 3: Define Your Document Model

Create a Java class that represents a document in your MongoDB collection. Use Spring Data annotations to map the class and its fields.

```java
import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;

@Document(collection = "tasks") // Maps this class to the "tasks" collection
public class Task {

    @Id // Marks this field as the unique document ID
    private String id;
    private String title;
    private String description;
    private boolean completed;

    // Constructors, Getters, and Setters (or use Lombok's @Data)
    public Task() {}

    public Task(String title, String description) {
        this.title = title;
        this.description = description;
        this.completed = false;
    }

    // ... getters and setters ...
}
```
This class is the blueprint for the data stored in MongoDB.

### Step 4: Create a Repository (The Easy Way)

Spring Data MongoDB provides the `MongoRepository` interface, which automatically implements basic CRUD operations. Create an interface that extends it:

```java
import org.springframework.data.mongodb.repository.MongoRepository;
import java.util.List;

public interface TaskRepository extends MongoRepository<Task, String> {

    // Spring Data automatically implements this query based on the method name!
    List<Task> findByCompleted(boolean completed);

    // You can also use @Query for more control
    // @Query("{ 'title' : ?0 }")
    // List<Task> findByTitle(String title);
}
```
This is the fastest way to get basic data access working. You can also define derived query methods simply by naming them correctly (e.g., `findByCompleted`).

### Step 5: Build a Service and Controller

Now, create a service layer for your business logic and a REST controller to expose your API.

**Service Layer**
```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class TaskService {

    @Autowired
    private TaskRepository taskRepository;

    public List<Task> getAllTasks() {
        return taskRepository.findAll();
    }

    public Task createTask(Task task) {
        return taskRepository.save(task);
    }

    public List<Task> getTasksByStatus(boolean completed) {
        return taskRepository.findByCompleted(completed);
    }

    // ... other methods ...
}
```

**REST Controller**
```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/api/tasks")
public class TaskController {

    @Autowired
    private TaskService taskService;

    @GetMapping
    public List<Task> getAllTasks() {
        return taskService.getAllTasks();
    }

    @PostMapping
    public Task createTask(@RequestBody Task task) {
        return taskService.createTask(task);
    }

    // ... other endpoints ...
}
```
Now you have a working CRUD application.

### Step 6: Use MongoTemplate for Complex Queries

While `MongoRepository` is great for simple operations, `MongoTemplate` gives you fine-grained control for complex queries, aggregations, and custom updates.

Inject `MongoTemplate` into your service:

```java
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.query.Criteria;
import org.springframework.data.mongodb.core.query.Query;
import org.springframework.data.mongodb.core.query.Update;

@Autowired
private MongoTemplate mongoTemplate;

// Example: Update a task's title directly
public void updateTaskTitle(String taskId, String newTitle) {
    Query query = new Query(Criteria.where("id").is(taskId));
    Update update = new Update().set("title", newTitle);
    mongoTemplate.updateFirst(query, update, Task.class);
}

// Example: Aggregation - Count tasks by completion status
public List<Object> getTaskCountByStatus() {
    Aggregation agg = Aggregation.newAggregation(
        Aggregation.group("completed").count().as("count"),
        Aggregation.project("count").and("completed").previousOperation()
    );
    AggregationResults<Object> results = mongoTemplate.aggregate(agg, "tasks", Object.class);
    return results.getMappedResults();
}
```
`MongoTemplate` is your tool for advanced operations like aggregations and bulk updates.

### Step 7: Explore Advanced Topics

Once you are comfortable with the basics, you can explore more advanced features.

**7.1 Indexes**
Create indexes on fields you query frequently to improve performance. You can do this via annotations on your model class:

```java
import org.springframework.data.mongodb.core.index.Indexed;

public class Task {
    @Indexed
    private String title;
    // ...
}
```
Or programmatically with `MongoTemplate`.

**7.2 Database Migrations**
For managing schema changes in production, consider using a tool like **Mongock**. It is the MongoDB equivalent of Flyway or Liquibase for SQL databases.

### Step 8: Best Practices

- **Data Modeling**: Model your documents based on how your application *reads* data. Embed related data when it is frequently accessed together to reduce the number of queries.
- **Use Both Repository and Template**: In a real application, use `MongoRepository` for simple CRUD and inject `MongoTemplate` for complex queries or aggregations.
- **Reactive Programming**: For high-concurrency applications, Spring Data MongoDB also supports reactive streams with `ReactiveMongoTemplate` and `ReactiveMongoRepository`.
