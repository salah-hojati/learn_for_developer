در Neo4j، `MERGE` دقیقاً برای همین هدف طراحی شده است: **"اگر وجود دارد، استفاده کن؛ اگر نه، بساز"** (Get or Create). با این حال، برای جلوگیری کامل از داده‌های تکراری (Duplicate)، فقط استفاده از `MERGE` کافی نیست و باید نکات مهمی را رعایت کنید.

### 📌 `MERGE` چگونه کار می‌کند؟

`MERGE` ترکیبی از `MATCH` و `CREATE` است. وقتی اجرا می‌شود:
1.  ابتدا سعی می‌کند الگوی مشخص‌شده را در گراف پیدا کند (مثل `MATCH`).
2.  اگر الگو **دقیقاً** وجود داشته باشد، آن را متصل کرده و کاری انجام نمی‌دهد.
3.  اگر الگو وجود نداشته باشد، آن را ایجاد می‌کند (مثل `CREATE`).

به همین دلیل، `MERGE` برخلاف `CREATE`، **idempotent** (تکرارپذیر) است و اجرای مجدد یک اسکریپت باعث ایجاد داده تکراری نمی‌شود.

### 🛡️ روش اصلی جلوگیری از تکرار: استفاده از Unique Constraint

مهم‌ترین اقدام برای جلوگیری از ایجاد تصادفی نودهای تکراری، تعریف **محدودیت یکتایی (Unique Constraint)** روی ویژگی‌های شناسه‌ای است.

**چرا این کار ضروری است؟**
بدون یک محدودیت یکتایی، `MERGE` در برابر همزمانی (Concurrency) آسیب‌پذیر است. اگر دو تراکنش همزمان سعی کنند نودی با یک شناسه را ایجاد کنند و هیچ‌کدام نود موجودی را پیدا نکنند، هر دو نود جدیدی می‌سازند. یک محدودیت یکتایی به عنوان یک قفل عمل می‌کند و تضمین می‌کند که فقط یکی از تراکنش‌ها موفق به ایجاد نود شود.

**مثال:**
فرض کنید می‌خواهید از ایجاد کاربران تکراری با ایمیل یکسان جلوگیری کنید.
```cypher
// 1. ابتدا یک محدودیت یکتایی روی ویژگی ایمیل ایجاد کنید
CREATE CONSTRAINT unique_user_email FOR (u:User) REQUIRE u.email IS UNIQUE;

// 2. حالا MERGE با خیال راحت اجرا می‌شود
MERGE (u:User {email: "test@example.com"})
RETURN u;
```
علاوه بر جلوگیری از تکرار، این محدودیت یک **ایندکس** نیز ایجاد می‌کند که سرعت جستجوی `MERGE` را به شدت بالا می‌برد (بدون ایندکس، `MERGE` مجبور است تمام نودهای آن برچسب را اسکن کند).

### 🎯 تکنیک کلیدی: استفاده از "متغیرهای مقید" (Bound Variables)

این مهم‌ترین تکنیک برای جلوگیری از تکرار در **روابط** است. یک "متغیر مقید" متغیری است که قبلاً با `MATCH` یا `MERGE` به یک نود موجود در گراف متصل شده است.

**اشتباه رایج (منجر به تکرار می‌شود):**
```cypher
// این کار خطرناک است! اگر رابطه از قبل وجود نداشته باشد،
// MERGE ممکن است نودهای Student و Class جدیدی هم ایجاد کند.
MERGE (s:Student {id: 123})-[:ENROLLED_IN]->(c:Class {name: 'Cypher101'});
```
در اینجا `s` و `c` متغیرهای جدیدی هستند. اگر کل الگو وجود نداشته باشد، `MERGE` همه اجزا (شامل نودهای Student و Class) را از نو می‌سازد که ممکن است منجر به نودهای تکراری شود.

**روش صحیح (با استفاده از متغیرهای مقید):**
ابتدا نودهای موجود را پیدا کنید (یا با `MERGE` ایجاد/پیدا کنید)، سپس رابطه را بین آن‌ها `MERGE` کنید.
```cypher
// 1. ابتدا نودهای شروع و پایان را MATCH کنید (آن‌ها را "مقید" کنید)
MATCH (s:Student {id: 123})
MATCH (c:Class {name: 'Cypher101'})
// 2. سپس رابطه را MERGE کنید
MERGE (s)-[:ENROLLED_IN]->(c);
```
این الگو تضمین می‌کند که `MERGE` فقط رابطه را بررسی و در صورت نیاز ایجاد می‌کند و نودهای موجود را مجدداً استفاده می‌کند، بنابراین از تکرار نودها جلوگیری می‌شود.

### ⚙️ کنترل رفتار با `ON CREATE` و `ON MATCH`

`MERGE` این امکان را می‌دهد که مشخص کنید وقتی الگو ایجاد می‌شود (`ON CREATE`) یا پیدا می‌شود (`ON MATCH`)، چه اتفاقی بیفتد. این برای به‌روزرسانی هوشمند داده‌ها بسیار مفید است.

**مثال:** ثبت زمان ایجاد و آخرین مشاهده یک کاربر.
```cypher
MERGE (u:User {email: "jane@example.com"})
ON CREATE SET u.createdAt = timestamp() // فقط اگر کاربر جدید ساخته شود
ON MATCH SET u.lastSeen = timestamp()    // فقط اگر کاربر از قبل وجود داشته باشد
RETURN u;
```
این ساختار کمک می‌کند تا از به‌روزرسانی‌های ناخواسته جلوگیری کنید و منطق "Get or Create" را کامل‌تر کنید.

### 💎 خلاصه و بهترین شیوه‌ها

1.  **همیشه از `MERGE` به جای `CREATE` برای داده‌هایی که ممکن است از قبل وجود داشته باشند، استفاده کنید.**
2.  **قبل از هر چیز، محدودیت یکتایی روی ویژگی‌های شناسه‌ای نودها تعریف کنید.** این کار هم از تکرار در برابر همزمانی جلوگیری می‌کند و هم سرعت را بالا می‌برد.
3.  **هنگام `MERGE` کردن روابط، ابتدا نودهای شروع و پایان را با `MATCH` (یا `MERGE`) پیدا کرده و آن‌ها را به متغیر مقید کنید.** سپس رابطه را بین آن متغیرها `MERGE` کنید. از `MERGE` کردن یک الگوی کامل که شامل نودهای جدید است، خودداری کنید.
4.  **از `ON CREATE` و `ON MATCH` برای اعمال تغییرات هدفمند (مثل تنظیم timestamp) استفاده کنید** تا رفتار `MERGE` را دقیقاً مطابق نیاز خود کنترل کنید.
