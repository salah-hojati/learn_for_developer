Let's dive into **Step 1: Understand the Graph Model & Cypher**. This foundational step is about learning to "think in graphs" before you write any Java code.

### 🧩 Part 1: The Property Graph Model

Neo4j uses the **property graph model**. Think of it as a way to represent data that focuses on how things are connected, not just the things themselves.

Here are the core building blocks:

*   **Nodes**: These represent the **entities** or "things" in your domain, like a `Person`, a `Movie`, or a `Company`. In a diagram, they are usually circles.
*   **Labels**: Labels are used to **classify** nodes into groups. A node can have zero, one, or multiple labels. For example, a node might be labeled `:Person` and also `:Actor`.
*   **Relationships**: These represent the **connections** between two nodes. Every relationship has a **direction** (e.g., from one node to another) and a **type** (e.g., `:ACTED_IN`) that describes the connection. In diagrams, they are the arrows.
*   **Properties**: Both nodes and relationships can have **properties**, which are simply key-value pairs that store data like `name: 'Tom Hanks'` or `born: 1956`.

**A Concrete Example:**
This Cypher query creates a small graph representing a movie and its actors. It reads like ASCII art: `(node)-[relationship]->(node)`.

```cypher
CREATE (:Person:Actor {name: 'Tom Hanks', born: 1956})-[:ACTED_IN {roles: ['Forrest']}]->(:Movie {title: 'Forrest Gump', released: 1994})
```
*   This creates a `Person` node with the extra label `Actor` and properties `name` and `born`.
*   It creates a `Movie` node with properties `title` and `released`.
*   It creates an `ACTED_IN` relationship from the person to the movie, and the relationship itself has a property `roles`.

### 🔍 Part 2: Introduction to Cypher

**Cypher** is Neo4j's **declarative** query language. This means you tell it **what** you want, not **how** to get it. It's designed to be highly readable and is inspired by SQL and pattern-matching languages.

Here are the most essential clauses you'll use:

| Clause | Purpose |
| :--- | :--- |
| **`MATCH`** | Finds a pattern in the graph. This is how you query for data. |
| **`WHERE`** | Adds constraints or filters to a `MATCH` pattern. |
| **`RETURN`** | Specifies what data to return from your query. |
| **`CREATE`** | Creates new nodes and relationships. |
| **`SET`** | Updates properties on a node or relationship. |
| **`DELETE`** | Deletes nodes and relationships. |

### 🚀 Part 3: Hands-On Practice with the Movie Graph

The best way to learn is by doing. Neo4j provides a built-in **"Movie Graph"** sample dataset that is perfect for practice. It models movies, actors, directors, and the relationships between them.

#### 1. Access the Neo4j Browser
If you have a running Neo4j instance (like a free Aura cloud database or a local installation), open the **Neo4j Browser**. It's a web-based interface where you can type and run Cypher queries.

#### 2. Load the Sample Data
In the Neo4j Browser query bar, type the following command and press Enter (or click the "Play" button):
```
:play movies
```
This will load an interactive guide. Click the **"Create"** button within the guide to populate your database with the movie dataset.

#### 3. Try Your First Queries
Now, let's run some Cypher queries to explore the data.

**Query A: Find a specific node**
This finds the node labeled `Person` where the `name` property is 'Keanu Reeves' and returns their name and birth year.
```cypher
MATCH (keanu:Person {name:'Keanu Reeves'})
RETURN keanu.name, keanu.born
```

**Query B: Find connected nodes**
This finds all `Movie` nodes that have an `ACTED_IN` relationship coming from a `Person` node named 'Tom Hanks'. It then returns the movie's title and release year, ordered by year.
```cypher
MATCH (tom:Person {name: 'Tom Hanks'})-[:ACTED_IN]->(movie:Movie)
RETURN movie.title, movie.released
ORDER BY movie.released
```

**Query C: Find "co-actors" (a 2-hop traversal)**
This is a more powerful graph query. It finds actors who have acted in the same movie as Tom Hanks, counts how many films they've collaborated on, and lists them in descending order of collaboration.
```cypher
MATCH (tom:Person {name: 'Tom Hanks'})-[:ACTED_IN]->(movie)<-[:ACTED_IN]-(coActor:Person)
RETURN coActor.name, count(movie) AS filmsTogether
ORDER BY filmsTogether DESC
LIMIT 10
```

**Query D: Create your own data**
Let's add a new person to the graph and then verify it was created.
```cypher
// Create a new node
CREATE (p:Person {name: 'Your Name', born: 2000})

// Then, find it
MATCH (p:Person {name: 'Your Name'})
RETURN p
```
